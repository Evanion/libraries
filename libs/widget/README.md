# @evanion/widget

**Decide what a view shows in your logic layer, as a list of items any renderer can draw.**

When a view must change based on feature flags, user roles, or record state, the template often fills with branching logic. `@evanion/widget` moves these decisions out of the view and into a plain function in your logic layer. This function returns the view's sections as a list of items—each with a type and props—which the view then renders without further branching. Because this logic lives outside the UI, you can test it without rendering. Whether the list is generated by code or fetched from a CMS, `validateItems` ensures the data matches the types your renderer supports before it reaches the screen.

<!-- #region unknown -->

```ts @import.meta.vitest
import { validateItems } from '@evanion/widget';
import type { AnyWidgetItem } from '@evanion/widget';

interface Order {
  number: string;
  daysLeft: number;
}

// The logic layer decides which sections an order page shows.
function sectionsFor(order: Order, flags: { returns: boolean }) {
  const items: AnyWidgetItem[] = [
    { id: 'summary', type: 'summary', props: { number: order.number } },
  ];
  if (flags.returns) {
    items.push({
      id: 'returns',
      type: 'returns',
      props: { daysLeft: order.daysLeft },
    });
  }
  return items;
}

const page = sectionsFor({ number: '1042', daysLeft: 14 }, { returns: true });

page.map((item) => item.id); // -> ['summary', 'returns']

// The widget types the renderer has a component for. `returns` shipped in the
// logic before the renderer learned it, so the check reports it.
const problems = validateItems(page, ['summary']);

problems; // -> [{ index: 1, id: 'returns', type: 'returns', message: 'unknown widget type' }]
```

## Capabilities of @evanion/widget

The library provides the structural "glue"—the registry and the validator—to manage the following:

- **Logic-Layer Composition**: Decide "who sees what" in a function that returns items, not in the view.
- **Structural Integrity**: Catch unknown types, missing required props, and duplicate IDs at the edge before a renderer silently skips a widget.
- **Recursive Nesting**: Support complex, nested layouts (such as grids within tabs) with full validation at every level.
- **Framework-Agnostic Design**: Handle the structure independently of your UI framework; you provide the renderer.

## Installation

`@evanion/widget` is ESM only, requires Node 20 or newer, and has zero runtime or peer dependencies.

```bash
npm install @evanion/widget
```

To render these widgets, install the renderer for your specific framework:

- For React: `npm install @evanion/react-widget`
- For Astro: `npm install @evanion/astro-widget`
