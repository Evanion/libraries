# Carry the id through a job

To run a queue message's work under the id the message carried, open a
correlation context with `CorrelationService.run(id, callback)`.
`CorrelationIdMiddleware` opens none outside a request, so there
`getCorrelationId()` returns `undefined`.

## Open a correlation context in a queue consumer

`RestockJob` is a queue consumer in Baize's `orders` service that opens its own
correlation context with `CorrelationService.run()` from
`@evanion/nestjs-correlation-id`. For each restock message it asks `stock` for
the game's current level. The code that queued the message, such as a request
handler in `orders`, copied `getCorrelationId()` into the message's
`correlationId` field, so the message carries that request's id when there was
one.

`CorrelationConfig` is the type of the configuration `forRoot()` builds from its
argument and the defaults, with the fields `header`, `generator` and `validate`.
`CORRELATION_CONFIG_TOKEN` is the injection token `forRoot()` provides that
configuration under, and `RestockJob` reads `validate` from it to check the id a
message carried. `RestockJob` injects `CorrelationService`, the configuration,
and `StockClient`, the client [Forward the id](../forwarding) builds:

```ts file=libs/nestjs-correlation-id/examples/restock.job.ts region=restock-job

```

- `run(id, callback)` runs `callback` inside a correlation context and returns
  what `callback` returns, so the promise from `stock.level()` comes straight
  back out of `handle()`.
- Everything the callback calls or awaits reads `id`. `StockModule` registers
  `StockClient`'s `HttpService` with `withCorrelation()`, so its call to `stock`
  carries the id.
- `generate()` returns a new id from the configured generator, `randomUUID`
  unless `forRoot()` was given another. A cron job has no id to carry, so it
  runs its work inside `run(generate(), …)`.

Declare `RestockJob` in a module that imports `StockModule`, and call `handle()`
from your queue library's consumer.

## Why RestockJob validates the carried id

An id read off a queue message reaches the same log lines and outgoing headers
as one read off a request, so `RestockJob` runs it through the same check
`@evanion/nestjs-correlation-id` applies to a request. `validate` on the
injected configuration is the function `CorrelationIdMiddleware` applies to an
incoming header, `DEFAULT_CORRELATION_ID_VALIDATOR` unless `forRoot()` was given
another. A carried id that fails the check is dropped, and the job generates its
own.

## Replace the id inside a correlation context

`CorrelationService.setCorrelationId(id)`, from
`@evanion/nestjs-correlation-id`, replaces the id for the rest of the context it
is called in. It serves a consumer that opens its context before it has read the
message: a wrapper calls `run(generate(), …)` around every handler, so each
handler starts under a generated id. A handler that then reads an id off its
message passes that id to `setCorrelationId`. Outside any context
`setCorrelationId` throws.

returns. Outside, the call threw, and the error message names the two ways to
open a context: `CorrelationIdMiddleware` and `CorrelationService.run()`.

Inside a request, `setCorrelationId` leaves the response header alone. The
header keeps the id the middleware wrote when the request arrived.

## Change the header, the generator and the check

A job now carries the id its message brought, and
`@evanion/nestjs-correlation-id` generates a fresh one when the message brought
none. [Configuration](../configuration) changes the header, the generator and
the check `@evanion/nestjs-correlation-id` applies to an incoming id, through
the fields `forRoot()` takes.
