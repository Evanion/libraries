# Getting started

By the end of this page every request to your NestJS application carries a
correlation id, and a handler reads it from `CorrelationService`.

## Before you install nestjs-correlation-id

`@evanion/nestjs-correlation-id` needs:

- A NestJS 12 application, meaning `@nestjs/common` `^12.0.0`, on the Express or
  the Fastify adapter.
- Node 20 or newer. The package ships only ES modules, so the minimum depends on
  your project's module format:
  - An ES module project imports it on any Node 20.
  - A CommonJS project loads it through `require()`, which needs Node 20.19,
    22.12 or newer. NestJS 12 needs the same versions in a CommonJS project.

## Install nestjs-correlation-id

```bash
npm install @evanion/nestjs-correlation-id
```

```bash
yarn add @evanion/nestjs-correlation-id
```

```bash
pnpm add @evanion/nestjs-correlation-id
```

## Register CorrelationModule and the middleware

`CorrelationModule.forRoot()` from `@evanion/nestjs-correlation-id` provides
`CorrelationService` to every module, and `CorrelationIdMiddleware` opens a
correlation context around each request. Register both in your root module:

```ts twoslash file=libs/nestjs-correlation-id/examples/app.module.ts region=register

```

`forRoot()` with no argument is the whole minimum configuration. The middleware
then reads `X-Correlation-Id` and generates a missing id with `randomUUID` from
`node:crypto`. It reuses an incoming id only when the id passes
`DEFAULT_CORRELATION_ID_VALIDATOR`, which accepts 1 to 128 characters from the
ASCII letters, the digits, `_`, `.`, `:` and `-`. `forRoot()` also takes three
optional fields, `header`, `generator` and `validate`, that replace those
defaults.

- `forRoot()` registers a global module, so call it once, in the root module.
- `forRoutes('*')` covers every route. On a route the middleware skips,
  `getCorrelationId()` returns `undefined`.
- Nest runs middleware in the order `configure()` applies it, and the
  correlation context opens in `CorrelationIdMiddleware`. Apply your own
  middleware that reads the id in a later `consumer.apply()` call, or later in
  the same call's argument list.

## Read the request's id in a handler

Inject `CorrelationService` from `@evanion/nestjs-correlation-id` and call
`getCorrelationId()`. `OrdersController` in Baize's `orders` service returns the
id with the order and writes both to its log line:

```ts file=libs/nestjs-correlation-id/examples/orders.controller.ts region=read-the-id

```

`getCorrelationId()` is synchronous, and nothing passes the id to `find()`: the
controller reads it from the context the middleware opened.

## Check that the caller's id comes back

To see `@evanion/nestjs-correlation-id` reuse a caller's id, add
`controllers: [OrdersController]` to the `@Module()` of `AppModule` and start
the application. The request below assumes it listens on port 3000, the port
`nest new` sets up. Send a request with an id:

```bash
curl -i -H 'X-Correlation-Id: storefront-4f1c9a' http://localhost:3000/orders/order-2026-0042
```

The response carries the header `X-Correlation-Id: storefront-4f1c9a` and the
body `{"order":"order-2026-0042","correlationId":"storefront-4f1c9a"}`. Leave
the header off and both carry a fresh universally unique identifier (UUID).

- once for a request that carries `storefront-4f1c9a` under `x-correlation-id`,

## Send the id on to the stock service

Every request to your application now carries an id from
`@evanion/nestjs-correlation-id`, and a handler reads it.
[Forward the id to the next service](../forwarding) passes `withCorrelation()`
to `HttpModule`, so Baize's `stock` service receives the id the `orders` service
was called with.
