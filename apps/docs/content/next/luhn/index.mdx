# @evanion/luhn

**Prevent database pollution and user frustration with a check character.**

A customer reads an order code back, and one digit comes out wrong. `@evanion/luhn` appends a check character, so your app refuses the mistyped code locally.

## The Problem: The "Silent Typo"

Without `@evanion/luhn`, an ID is just a string. If a user types `order-2026-0043` instead of `order-2026-0042`, the system treats it as a perfectly valid request for a non-existent resource, which leads to:

- **Wasted Resources**: Every mistyped ID triggers an unnecessary database query.
- **Poor User Experience**: The user receives a "Not Found" error and has no way of knowing they mistyped a single character.
- **Support Overhead**: Staff must manually verify the order, as they cannot tell the difference between a typo and a missing record.

## The Solution: The Luhn Algorithm

`@evanion/luhn` implements the Luhn algorithm, the check-digit scheme on credit card numbers, generalised to any alphabet, to detect transcription errors. It computes a single character from the rest of the code; if any character is changed or two neighbours are swapped, the check character no longer matches.

For example, the order number `order-2026-0042` results in a check character of `l`, so the final code becomes `order-2026-0042-l`.

If a user types `order-2026-0043-l` (one digit changed) or `order-2026-0024-l` (two digits swapped), `Luhn.validate` immediately returns `isValid: false`. The request is rejected before it ever reaches your database.

## How it Works: The Luhn Sum

`@evanion/luhn` calculates the check character through a process called the Luhn sum:

1. **Phrase Extraction**: Every character outside the chosen **dictionary**, the alphabet a code is read against, is dropped. The default instance, `Luhn`, also folds uppercase to lowercase. `ORDER 2026 0042` becomes the **phrase** `order20260042`.
2. **Index Mapping**: Each character is replaced by its **index**, its position in the dictionary (e.g., `o` $\rightarrow$ 24).
3. **The Doubling Step**: Starting from the right, every second index is doubled. If the result reaches the dictionary size, its two digits (in the dictionary's base) are added together.
4. **Summation**: All values are added together to create the **Luhn sum**, 123 for `order20260042`.
5. **Final Character**: The **check character** is the one whose index brings the sum up to the next multiple of the dictionary size: 144 − 123 is 21, the index of `l`.

## Core Capabilities

`@evanion/luhn` covers these tasks:

| Goal                            | Tool                                                                                              |
| :------------------------------ | :------------------------------------------------------------------------------------------------ |
| Add a check character to a code | `Luhn.generate(code).checksum`                                                                    |
| Validate a code's integrity     | `Luhn.validate(code).isValid`                                                                     |
| Support flexible input          | On the default instance, both calls ignore case and separators (non-dictionary chars)             |
| Custom alphabets                | `createLuhn({ dictionary })` builds a custom **instance**, and refuses a dictionary it cannot use |
| Credit card validation          | `createLuhn({ dictionary: '0123456789' })`                                                        |

## What a Check Character Catches (and What it Doesn't)

`@evanion/luhn` is a tool for **error detection**, not **security**.

### It catches:

- **Every single-character substitution**: If one character is replaced by another, at any position including the check character itself, the check fails.
- **Almost every adjacent swap**: If two neighboring characters are swapped, it is caught (except for a swap of the dictionary's first and last characters, e.g., `0` and `z`).

### It does NOT:

- **Prove existence**: A random string passes the check one time in `n`, the dictionary's size: 1 in 36 under the default. You still need a database to verify the code was actually issued.
- **Provide authentication**: The algorithm and the dictionary are public. Anyone can compute a valid check character for any string.
- **Choose the ID**: This library only provides the check character. Use [`@evanion/token`](/token) if you need to generate random, human-readable IDs.
