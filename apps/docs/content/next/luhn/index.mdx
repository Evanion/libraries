# @evanion/luhn

A customer of a board game shop reads an order code back over the phone, and
one digit comes out wrong. `@evanion/luhn` puts a check character on the code,
so `Luhn.validate` refuses the mistyped one before your database is asked.

## How a check character catches a mistyped code

`@evanion/luhn` checks a code against one character computed from the code
itself. Baize, the shop these examples are set in, prints the order code
`order-2026-0042-l` on a receipt: the order number `order-2026-0042` with the
check character `l`, a lowercase L, computed from the order number.
`Luhn.validate` computes it again from the code it is given and compares:

The second code has one digit changed. The third has two adjacent digits
swapped. Neither produces `l` again, so both come back `isValid: false`, and
neither reaches your database, where it could have matched a different order.

## The luhn vocabulary

`@evanion/luhn` describes a code in six terms.

- The **dictionary** is the alphabet a code is read against, as one string. The
  default dictionary is `0` to `9` then `a` to `z`, 36 characters.
- A character's **index** is its position in the dictionary, from `0` for `0` to
  `35` for `z` in the default. Because every check character is computed from
  indices, the same letters in a different order are a different dictionary.
- The **phrase** is the input with every character outside the dictionary
  dropped and, on the default instance, uppercase folded to lowercase.
  `order-2026-0042` and `ORDER 2026 0042` have the same phrase, `order20260042`.
- The **check character** is one character of the dictionary, appended to a
  code. `generate` returns it as `checksum`.
- The **Luhn sum** is the number both calls compute from the indices of the
  phrase. The next section adds it up.
- An **instance** is a dictionary with `generate` and `validate` bound to it.
  `Luhn` is the default instance.

## How `Luhn.generate` computes the check character

`Luhn.generate` is the `@evanion/luhn` call that computes a check character.
It computed the `l` of `order-2026-0042-l` in four steps:

1. It reads `order-2026-0042` as the phrase `order20260042`.
2. It replaces each character of the phrase with its index: `o` is 24, `r` is
   27, `2` is 2.
3. It doubles every second index, starting with the phrase's last character and
   moving left. A doubled index of 36 or more, the dictionary's size, counts as
   its two digits in base 36 added together: the second `r` doubles to 54, which
   is 1 × 36 + 18, and counts 19. The `o` doubles to 48 and counts 13.
4. It adds everything up. Over `order20260042` the terms are
   13 + 27 + 26 + 14 + 19 + 2 + 0 + 2 + 12 + 0 + 0 + 4 + 4, and the Luhn sum is 123.

The check character is the one whose index brings the sum up to a multiple
of 36. Here that is 144, and 144 − 123 is 21, the index of `l`.

`Luhn.validate` runs the same steps over the whole code, `order20260042l`. It
starts doubling one place from the end, so the check character's index is added
undoubled and every character of `order20260042` is doubled exactly as
`generate` doubled it. 123 + 21 is 144, a multiple of 36, and `validate`
accepts the code. A changed character moves the sum off the multiple. Over a
dictionary of the ten digits the same steps give the check digit on a credit
card number.

## What luhn can do

| You want to                                 | What luhn gives you                                                                                                                   |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| put a check character on a code             | `Luhn.generate(code).checksum`                                                                                                        |
| refuse a mistyped code                      | `Luhn.validate(code).isValid`                                                                                                         |
| accept `ORDER 2026 0042 L` as the same code | both calls read the phrase, so case and separators do not count                                                                       |
| check codes drawn from your own dictionary  | `createLuhn({ dictionary })` builds an instance over it, and refuses a dictionary it cannot use, such as one that repeats a character |
| compute a credit card's check digit         | `createLuhn({ dictionary: '0123456789' })`, the algorithm card numbers use                                                            |

## What a check character catches, and what it does not

An `@evanion/luhn` check character catches typing mistakes and nothing else.

- It catches every single-character substitution, at every position, including
  the check character itself.
- It catches every swap of two adjacent characters except a swap of the
  dictionary's first and last characters, `0` and `z` in the default.
- It does not prove a code exists. A random string passes one time in 36 under
  the default dictionary, and whether order `2026-0042` was ever placed is a
  question for your database.
- It is not authentication. The algorithm and the dictionary are public, so
  anyone can compute the check character for any string.
- It does not choose the code. Baize's order numbers come from its database,
  and [`@evanion/token`](/token) draws the shop's pickup codes at random and asks this
  package for their check character.
