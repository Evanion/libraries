## Before you install luhn

- Node 20 or newer, or any browser.
- An ES module (ESM) project, or a CommonJS project on Node 20.19, 22.12 or
  newer, whose `require()` loads ES modules. An older `require()` fails with
  `ERR_REQUIRE_ESM`.
- No peer dependencies and no runtime dependencies.

## Install luhn

Pick the line for your package manager.

```bash
npm install @evanion/luhn
```

```bash
yarn add @evanion/luhn
```

```bash
pnpm add @evanion/luhn
```

## `Luhn` needs no configuration

`Luhn` is `@evanion/luhn`'s default [instance](../#the-luhn-vocabulary), over
the 36-character default dictionary. `import { Luhn } from '@evanion/luhn'` is
the whole setup.

## Print an order code with a check character

`@evanion/luhn` returns a check character and leaves the code to you. Baize's
**order number** is `order-2026-0042`, the id its database already holds. The
**order code** is the order number with the check character appended, which is
what the receipt prints and what a customer reads back. `orderCode` builds one:

```ts twoslash file=libs/luhn/README.md region=round-trip

```

`Luhn.generate` returns the check character as `checksum`, and `orderCode`
decides that a hyphen goes before it. `validate` accepts the printed code
without the hyphen counting, because it reads the
[phrase](../#the-luhn-vocabulary), which drops it.

A customer reading `order-2026-0042-l` off the receipt can take the last
character for a `1`. `validate` refuses `order-2026-0042-1`, so the shop's till
asks again before the database is asked about an order that does not match.
