# Generating and validating

`Luhn.generate` computes the check character for an identifier, and `Luhn.validate` checks if a code carrying one is well-formed. Both return the "phrase" (the cleaned input) they read, allowing you to map a customer's input back to a database record.

## Minting a Check Character with `Luhn.generate`

`Luhn.generate` takes an identifier without a check character and returns its `phrase`, its `checksum` and its `filtered` count.


### The Result Object

| Field      | What it holds                                       | Example (`order-2026-0042`) |
| :--------- | :-------------------------------------------------- | :-------------------------- |
| `phrase`   | The cleaned input used for the calculation.         | `'order20260042'`           |
| `checksum` | The computed check character.                       | `'l'`                       |
| `filtered` | The number of characters dropped (separators, etc). | `2`                         |

Because `generate` reads the [phrase](../#how-the-luhn-sum-works), inputs like `order-2026-0042` and `ORDER 2026/0042` produce the same checksum. So a code typed in capitals with spaces finds the same order as the printed one.

## Handling Empty Inputs

`Luhn.generate` throws an `EmptyInputError` when no characters in the input belong to the dictionary.

If every character is dropped, the resulting phrase is empty. Every empty phrase would get the same check character, so a blank form field and a string of hyphens (`'--'`) would be indistinguishable, and the character would check nothing. To prevent this, `generate` requires at least one dictionary character.

```ts twoslash file=libs/luhn/README.md region=empty-input

```

`EmptyInputError` is the only error `generate` throws, and `validate` never throws.

## Validating a Code with `Luhn.validate`

`Luhn.validate` treats the last character of the input that belongs to the dictionary as the check character.

```ts twoslash file=libs/luhn/README.md region=validate

```

### Validation Rules

- **The Phrase**: `validate`'s `phrase` includes the check character.
- **Minimum Length**: `isValid` is `false` if the phrase contains fewer than two characters (an ID plus its check character is the minimum).
- **Case and Separators**: Like `generate`, `validate` ignores case and non-dictionary characters.

The card below appends the check character with no hyphen, so it issues `order-2026-0042l`. Type the code back with any case or hyphens and the card shows `accepted` or `rejected`, following `isValid`. The "Change a character" and "Swap two" buttons each break the code, and `validate` refuses it.

## Mapping a Code Back to an Order

`Luhn.generate` from `@evanion/luhn` returns the **phrase** to store with each order, in its own indexed column. For orders already in the database, run `Luhn.generate` over each order number once to fill that column.

When a code comes back, use `validate` to verify it, then slice off the last character (the check character) to get the original phrase.


This approach ensures that `ORDER 2026 0042 L` and `order-2026-0042-l` both resolve to the same database key: `order20260042`. The phrase has lost the hyphens and the case, so keep `order-2026-0042` in its own column if a screen or a receipt prints it.

## Strict Input with `filtered`

`@evanion/luhn` drops every character outside the dictionary, which lets a person type separators. A barcode scanner sends exactly the characters the barcode holds.

Use the `filtered` count to enforce strict input. If `filtered` is greater than 0, the input held characters outside the dictionary.

```ts twoslash file=libs/luhn/README.md region=strict-input

```

By requiring `filtered === 0` on the scanner's input only, you keep accepting separators in a code a person types while refusing them in a scanned one. `filtered` counts code points, not UTF-16 units, so an astral character such as 🂡 is one dropped character, not two.

## Customizing the Alphabet

By default, every call on `Luhn` from `@evanion/luhn` runs on a 36-character dictionary. If you need a different set of characters, such as the 32-character alphabet `@evanion/token` uses, build a custom instance. [Dictionaries](../dictionaries) shows how to use `createLuhn`.
