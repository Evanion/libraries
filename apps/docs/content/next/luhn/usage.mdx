# Generating and validating

`Luhn.generate` computes the check character for an order number, and
`Luhn.validate` checks an order code that carries one. Both return the phrase
they read, and only `generate` can throw.

## What `Luhn.generate` returns

`Luhn.generate` takes an order number, without a check character, and returns
three fields, `phrase`, `checksum` and `filtered`:

```ts twoslash file=libs/luhn/README.md region=generate

```

<Probe package="luhn" probe="generate" />

| Field      | What it holds                                                                       |
| ---------- | ----------------------------------------------------------------------------------- |
| `phrase`   | the [phrase](../#the-luhn-vocabulary) the check character was computed over         |
| `checksum` | the check character, one character of the dictionary                                |
| `filtered` | how many characters of the input were dropped, the two hyphens in `order-2026-0042` |

`order-2026-0042` and `ORDER 2026/0042` produce the same phrase, so they get the
same `l`. `generate` does not append `checksum`, which is why
[Getting started](../getting-started) writes `orderCode`.

## Why `Luhn.generate` throws `EmptyInputError`

`Luhn.generate` throws `EmptyInputError` when no character of its input is in
the dictionary. Every such input leaves an empty phrase, so a blank form field
and `'--'` would get the same check character, and that character would check
nothing. Catch the error where the input comes from a person:

```ts twoslash file=libs/luhn/README.md region=empty-input

```

`generate` throws `EmptyInputError`, and `validate` never throws. `createLuhn`
throws `InvalidDictionaryError` when it builds an instance, so `generate` and
`validate` never fail on the dictionary.
[What `createLuhn` checks](../dictionaries#what-createluhn-checks-in-a-dictionary)
lists the constraints.

## What `Luhn.validate` returns

`Luhn.validate` treats the last character of its input that is in the
dictionary as the check character:

```ts twoslash file=libs/luhn/README.md region=validate

```

`validate`'s `phrase` includes the check character, because the code carried
one. `generate`'s `phrase` does not, because the check character did not exist
yet. `isValid` is `false` when `phrase` holds fewer than two characters, because
an order number and a check character is the minimum.

The card below issues `order-2026-0042l`, Baize's order code without the hyphen
before the `l`, and `validate` reads the same phrase from both. Type it back in
with any case or hyphens and the verdict follows `isValid`. The "Change a
character" and "Swap two" buttons each break the code, and `validate` refuses
it.

## Find the order a luhn code belongs to

`Luhn.validate('order-2026-0042-l')` returns the phrase `order20260042l`.
Without its last character that is `order20260042`, the phrase `generate`
returned for the order number. Store that phrase with the order when Baize
creates it, and look the order up by it when a code comes back:

```ts twoslash file=libs/luhn/README.md region=look-up

```

`orderPhrase` slices the `phrase` that `validate` returned, so
`ORDER 2026 0042 L` and `order-2026-0042-l` both find `order20260042`. The
phrase has lost the hyphens and the case, so keep `order-2026-0042` in its own
column if a screen or a receipt prints it. `orderPhrase` returns `null` for a
code `validate` refuses, and the till asks the customer again.

## Refuse stray characters with `filtered`

`@evanion/luhn` drops characters outside the dictionary because a person typing
`ORDER 2026 0042 L` means the same order as `order-2026-0042-l`. A barcode
scanner adds no separators. Baize's receipt carries
`order20260042l` in its barcode, so a scanned code with any character dropped
means the scanner read something other than a receipt. `filtered` counts the
characters `validate` dropped, and the till's barcode input refuses any:

```ts twoslash file=libs/luhn/README.md region=strict-input

```

The field a person types into keeps accepting `order-2026-0042-l` through
[`orderPhrase`](#find-the-order-a-luhn-code-belongs-to). `filtered` counts code points, not UTF-16 units, so an emoji is
one dropped character, not two.

## Choose the dictionary luhn reads

`orderCode` and `orderPhrase` both run on `Luhn`'s default dictionary.
[Dictionaries](../dictionaries) builds an instance over the shop's 32-character
pickup dictionary with `createLuhn`, and lists what a dictionary has to satisfy.
