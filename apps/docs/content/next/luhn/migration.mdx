# Migrating from 2.x

`@evanion/luhn` 3.x introduces breaking changes to the default dictionary and the configuration API. Most notably, the default dictionary has shrunk from 62 characters to 36, so a code produced by 2.x validates under 3.x only by coincidence.

## Handling Legacy Codes

If your system has already issued codes using `@evanion/luhn` 2.x, you must decide how to handle them before updating. You have three primary options:

1. **Reissue**: If codes are internal or short-lived, reissue them using 3.x.
2. **Legacy Support**: Maintain a legacy instance to validate 2.x codes.
3. **Transition Period**: Validate against both 2.x and 3.x instances, and reissue the code to the 3.x format when it is first read.

The 2.x default lowercased input but used a 62-character dictionary that included both cases. You can reproduce 2.x check characters using `ALTERNATING_CASE_DICTIONARY` combined with lowercased input:


`issuedBy2x` lowercases everything but the check character. 2.x's own `validate` lowercased that too, so it refused every code whose check character was an uppercase letter, `order-2026-0042-E` among them. During a transition period, `issuedBy2x(code) || Luhn.validate(code).isValid` accepts a code from either version.

## API Mapping: 2.x $\rightarrow$ 3.x

The `@evanion/luhn` 2.x API relied on mutable static properties on a class. 3.x replaces this with frozen instances created via `createLuhn`. `caseInsensitive` below is the `createLuhn` option that folds input to lowercase, covered in [Handling Case Sensitivity](../dictionaries#handling-case-sensitivity).

| 2.x Call / Property                                   | 3.x Equivalent                                            | Notes                                                                                                                                                       |
| :---------------------------------------------------- | :-------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Luhn.generate(input)`                                | `Luhn.generate(input)`                                    | Call is the same; output value is different.                                                                                                                |
| `Luhn.validate(input)`                                | `Luhn.validate(input)`                                    | Call is the same; now accepts every code `generate` produces.                                                                                               |
| `Luhn.generate(input, true)`                          | `createLuhn({ caseInsensitive: false }).generate(input)`  | Disables input folding.                                                                                                                                     |
| `Luhn.validate(input, true)`                          | `createLuhn({ caseInsensitive: false }).validate(input)`  | Disables input folding.                                                                                                                                     |
| `class X extends Luhn { static dictionary = d }`      | `createLuhn({ dictionary: d, caseInsensitive: true })`    | Same values as the legacy subclass. When `d` holds both cases of a letter, use `createLuhn({ dictionary: d })` over lowercased input, as `issuedBy2x` does. |
| `class X extends Luhn { static sensitive = true }`    | `createLuhn({ dictionary: ALTERNATING_CASE_DICTIONARY })` | Reproduces case-sensitive 2.x behavior.                                                                                                                     |
| `Luhn.dictionary = d`                                 | throws `TypeError`                                        | The default instance is now frozen.                                                                                                                         |
| `Luhn.sensitive`                                      | `!Luhn.caseInsensitive`                                   | The flag's meaning is now inverted.                                                                                                                         |
| `Luhn.lowercaseOnly(d)`                               | removed                                                   | Nothing folds a dictionary any more.                                                                                                                        |
| the `protected static` helpers                        | removed                                                   | An override of `char2index` never took effect, because `reduce` called `Luhn`'s own.                                                                        |
| `ValidationError`                                     | `LuhnError`                                               | Base class for `EmptyInputError` and `InvalidDictionaryError`.                                                                                              |
| `validate('')` $\rightarrow$ `isValid: true`          | `isValid: false`                                          | Empty strings are no longer considered valid.                                                                                                               |
| `generate('')` $\rightarrow$ `{ checksum: '0' }`      | throws `EmptyInputError`                                  | Generating a checksum for nothing is now an error.                                                                                                          |
| a dictionary of odd length throwing at the first call | throws `InvalidDictionaryError` at `createLuhn`           | The dictionary is checked once, when the instance is built.                                                                                                 |

## Why the Architecture Changed

### From Mutable Statics to Frozen Instances

`@evanion/luhn` 2.x was configured through mutable statics, which meant dictionaries were never checked before use. This led to runtime crashes (e.g., `TypeError: dictionary.indexOf is not a function`) if a dictionary was misconfigured.

`createLuhn` now validates the dictionary immediately upon instance creation. Once built, the instance is frozen, so the assignment that configured 2.x now throws a `TypeError` in an ES module:

### The Alphabet Shrinkage

The 2.x default alphabet held case pairs (both `A` and `a`). However, the library was documented as case-insensitive. This was a contradiction: if you fold `A` to `a`, the index originally held by `A` becomes unreachable.

The 3.x default consists of 36 lowercase alphanumerics. This is a sound basis for a case-insensitive default. If you need the full 62-character set, use `ALTERNATING_CASE_DICTIONARY`.

## Transitioning from Subclasses to Instances

In `@evanion/luhn` 2.x, you created a subclass for every extra dictionary. In 3.x, you create a new instance. Since `createLuhn` builds a lookup table on every call, you should cache these instances if they recur. [Caching Instances](../dictionaries#caching-instances) shows the recommended caching pattern.
