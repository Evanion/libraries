# Dictionaries

`createLuhn({ dictionary })` builds an instance over a set of characters of your choice. This allows you to adapt the Luhn algorithm to any alphabet—from credit card digits to a custom set of symbols.

## The Foundation: The Default Dictionary

The standard `Luhn` instance is built over the `DEFAULT_DICTIONARY`, which consists of the 36 lowercase alphanumerics (`0-9` and `a-z`).

The default instance automatically folds input to lowercase. This ensures that `O` is treated as `o`, mapping it to a single consistent index in the dictionary.

### Important: The Importance of Order

The dictionary string is not just a set of characters—it is an **ordered list**. The index of each character in the string determines its value in the Luhn sum.

**Never sort or deduplicate your dictionary string at runtime.** If you change the order of characters, you change the check characters the instance produces, which will break validation for any codes already issued.

## Dictionary Constraints

To ensure the Luhn algorithm works correctly, `createLuhn` validates your dictionary against five constraints. If any are broken, it throws an `InvalidDictionaryError`.

| `reason`       | Constraint                                    | Why it matters                                                                                 |
| :------------- | :-------------------------------------------- | :--------------------------------------------------------------------------------------------- |
| `not-a-string` | Must be a string                              | The library requires a sequence of characters.                                                 |
| `too-short`    | At least 2 characters                         | With only one character, every code would technically be valid.                                |
| `odd-length`   | Must have an even size                        | The doubling step in the Luhn sum requires an even-sized alphabet to avoid "blind spots."      |
| `duplicate`    | No repeated characters                        | Each character must map to exactly one unique index.                                           |
| `case-pairs`   | No case variants (if `caseInsensitive: true`) | If `A` and `a` both exist, folding input to lowercase would make the index of `A` unreachable. |

## Handling Case Sensitivity

By default, `createLuhn` sets `caseInsensitive` to `false` when you provide a custom dictionary. This is because the library cannot assume you want your input folded to lowercase.

If you want your custom instance to ignore case, set `caseInsensitive: true`. This is useful for dictionaries that only contain lowercase letters but need to accept uppercase input from users.

## Advanced Considerations

### Unicode and Code Points

`createLuhn` counts **code points**, not UTF-16 units. This means you can safely use emojis or other multi-byte symbols in your dictionary without breaking the index mapping.

```ts twoslash file=libs/luhn/README.md region=code-points

```

### Caching Instances

`createLuhn` builds a lookup table for the dictionary every time it is called. If your application uses a few recurring dictionaries (e.g., one for orders, one for pickup codes), you should cache the resulting instances in a `Map` rather than recreating them on every request.
