## Prerequisites

To follow this react-widget guide, ensure you have the following:

- **Node 20 or newer.**
- **React 18 or 19**: The package's only peer dependency. The example on this page also needs `react-dom` at the same version, for `renderToStaticMarkup`.
- **An ES module project**: Your `package.json` must include `"type": "module"`. The package ships no CommonJS build.
- **TypeScript 5.0 or newer**: Ensure your `tsconfig.json` has `"jsx": "react-jsx"` under `compilerOptions` to allow JSX without importing React.

To set up a fresh project for this example, run:

```bash
npm init -y
npm pkg set type=module
npm install --save-dev typescript tsx @types/react @types/react-dom
npx tsc --init --jsx react-jsx
```

## Install react-widget

Run the command for your preferred package manager (each one also installs React and `react-dom`):

```bash
npm install @evanion/react-widget react react-dom
```

```bash
yarn add @evanion/react-widget react react-dom
```

```bash
pnpm add @evanion/react-widget react react-dom
```

## Render your first widget region

The primary entry point of react-widget is `createWidgets`, which takes a component map (linking widget types to React components) and returns a `Widgets` component and a `defineItems` helper.

### Type an item array with `defineItems`

TypeScript widens the `type` strings in an array held in a variable to `string`, so passing that variable to `<Widgets>` is a compile error. `defineItems` types the array against your component map, so every `type` has to be a key of the map and every `props` object has to match its component.

### How to run the example:

1. Create `render.tsx` with the two imports above at the top.
2. Paste the code above below them and add `console.log(html);` at the end.
3. Run `npx tsx render.tsx`.

The command prints the string in the `// ->` comment. If it does, react-widget is working in your project. The output shows a `<section>` (the default `chrome.wrapper`) containing a `<div>` (the default `chrome.item`, carrying the item's `id` and `type`) which wraps the actual `ListingCard` markup.

### Verifying Type Safety

While `tsx` runs the code without checking its types, you can verify the type safety by running `npx tsc --noEmit`. If you change `price` to `'649'`, TypeScript reports `Type 'string' is not assignable to type 'number'` on that line, preventing a potential runtime error in your component.

**Warning**: Call `createWidgets` once at the module scope. Each call returns a new `Widgets` component, so calling it inside a component will cause the entire region to remount on every render, destroying the internal state of your widgets.
