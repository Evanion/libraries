## Before you install react-widget

- Node 20 or newer.
- React 18 or 19, the only peer dependency, and `react-dom` at the same
  version. The example below imports `renderToStaticMarkup` from
  `react-dom/server`.
- An ES module project, meaning `"type": "module"` in `package.json`. The
  package ships no CommonJS build.
- TypeScript 5.0 or newer, the first version that reads the package's types,
  with `"jsx": "react-jsx"` under `compilerOptions` in `tsconfig.json`. That
  setting compiles JSX in a file that imports no `React`.

In an empty directory, these commands create such a project, with `tsx` to run
a TypeScript file:

```bash
npm init -y
npm pkg set type=module
npm install --save-dev typescript tsx @types/react @types/react-dom
npx tsc --init --jsx react-jsx
```

## Install react-widget

Pick the line for your package manager. Each installs React and `react-dom`
beside the package.

```bash
npm install @evanion/react-widget react react-dom
```

```bash
yarn add @evanion/react-widget react react-dom
```

```bash
pnpm add @evanion/react-widget react react-dom
```

## Render one listing with `renderToStaticMarkup`

react-widget's `createWidgets` takes `components`, the component map, and
returns `Widgets` and `defineItems`. TypeScript widens each `type` in an array
held in a variable to `string`, so passing that array to `Widgets` is a compile
error. `defineItems` returns the array it is handed, typed against the map, so
each `type` stays a key of the map. `renderToStaticMarkup`, from
`react-dom/server`, returns the HTML `Widgets` rendered:

```tsx twoslash file=libs/react-widget/README.md region=region-markup

```

To run it:

1. Create `render.tsx` with two imports at the top:
   `import { createWidgets } from '@evanion/react-widget';` and
   `import { renderToStaticMarkup } from 'react-dom/server';`.
2. Paste the code above below them, and add `console.log(html);` at the end.
3. Run `npx tsx render.tsx`.

The command prints the string in the `// ->` comment. If it does, react-widget
is working in your project.

| In the HTML                  | Where it came from                                    |
| ---------------------------- | ----------------------------------------------------- |
| `<section>`                  | the default `chrome.wrapper`, around the whole region |
| `<div data-widget-id=…>`     | the default `chrome.item`, carrying the item's `id`   |
| `data-widget-type="listing"` | the same `<div>`, carrying the item's `type`          |
| `<h3>Brass: Birmingham, …`   | `ListingCard`, the only markup the widget wrote       |

`tsx` runs a file without checking its types. `npx tsc --noEmit` runs the
check: change `price` to `'649'` and it reports
`Type 'string' is not assignable to type 'number'` on that line.

Call `createWidgets` once, at module scope. Each call returns a new `Widgets`
component, so a call inside a component remounts the region on every render.
