## Before you install react-widget

- React 18 or 19, the only peer dependency.
- `react-dom` at the same version. The example below imports
  `renderToStaticMarkup` from it.
- Node 20 or newer.
- An ESM project, since the package ships no CommonJS build.
- TypeScript 5.0 or newer for the compile-time check, because the published
  types use a `const` type parameter. The components render without TypeScript.

## Install react-widget

Pick the line for your package manager.

```bash
npm install @evanion/react-widget
```

```bash
yarn add @evanion/react-widget
```

```bash
pnpm add @evanion/react-widget
```

`validateItems` comes from `@evanion/widget`, which this package pins exactly
and re-exports, so this one install is enough.

## Render one react-widget region

`createWidgets` takes `components`, the component map from a widget type to the
component that draws it, and returns `Widgets`. `Widgets` takes `items` and
renders each item's component with its `props`. `renderToStaticMarkup`, from
`react-dom/server`, returns the HTML React wrote:

```tsx twoslash file=libs/react-widget/README.md region=region-markup

```

To run it:

1. Save the code above as `render.tsx`.
2. Import `createWidgets` from `@evanion/react-widget` and
   `renderToStaticMarkup` from `react-dom/server` at the top.
3. Add `console.log(html)` at the end.
4. Set `"jsx": "react-jsx"` under `compilerOptions` in `tsconfig.json`. The
   file imports no `React`, and the classic JSX transform needs it in scope.
5. Run `npx tsx render.tsx`.

The file prints the string in the `// ->` comment. If it does, react-widget is
working in your project.

| In the HTML                  | Where it came from                                   |
| ---------------------------- | ---------------------------------------------------- |
| `<section>`                  | the default wrapper `Widgets` puts around the region |
| `<div data-widget-id=…>`     | the default item chrome, carrying the item's `id`    |
| `data-widget-type="listing"` | the same `<div>`, carrying the item's `type`         |
| `<h3>Brass: Birmingham</h3>` | `ListingCard`, the only markup the widget wrote      |

`as const` keeps `type` the literal `'listing'`. Without it TypeScript widens
the type to `string`, and passing the array to `Widgets` is a compile error. An
array written inline in the JSX, as on the Overview, is typed in place and needs
no `as const`. `defineItems`, from the Overview's capability table, types a
whole array held in a variable.

Call `createWidgets` once, at module scope. Each call returns a new `Widgets`
component, so a call inside a component remounts the region on every render.
