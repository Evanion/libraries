# Nesting items

A widget's `children` field allows you to nest items inside other widgets. For example, you can place multiple `ListingCard` widgets inside a single `Showcase` widget. `@evanion/react-widget` automatically renders these nested items as the parent component's `children` prop.

### Type Safety and Nested Items

TypeScript prevents you from nesting items where they don't belong. Since `ListingCard` does not declare a `children` prop, the compiler will reject any attempt to nest items under it.

## Where Nested Items are Rendered

`@evanion/react-widget` handles the recursive rendering of items and hands the result to the parent component as its `children` prop. **The parent component decides where these children appear.**

In the `Showcase` component, the children are rendered under an `<h2>` heading. If a component declares `children` in its type but never renders them in its JSX, the nested items will be ignored by the browser, even though they are valid.

## The limits of compile-time checks

It's important to remember that `defineItems` only checks the code _you_ write.

A CMS payload is just JSON; it never meets the TypeScript compiler. A CMS could send nested items under a `ListingCard`, and `Widgets` would simply ignore them during render. To catch these structural errors in your data, you must use `validateItems` at runtime. [Checking a CMS payload](../validation) shows how to implement this.
