# URNs from several namespaces

`belongsToNamespace` in `@evanion/urn` picks the game URNs out of a list the
shop's `orders` service received, and `GameURN.parse` reads an order URN without
taking it for a game.

## One namespace class per namespace

The shop names games and orders, so it declares two `@evanion/urn` namespace
classes: `GameURN`, the class [Getting started](../getting-started) mints with,
and `OrderURN` beside it. Each example on this page runs appended to
`game-urn.ts`. `stringify` on either class needs no NID, and
`belongsToNamespace` picks the game URNs out of a list:

```ts twoslash file=libs/urn/README.md region=class-per-namespace

```

`belongsToNamespace` takes the NID as its second argument, even on `GameURN`.
The class supplies only the scheme and the separator, so one class tests a URN
against any namespace. It returns `false` for `'hive'`, which is not a URN, so a
filter over untrusted input needs no `try` block. It compares the scheme and the
NID without regard to case, so `URN:GAME:azul` is a game URN as well.

## What parse returns for a foreign URN

`GameURN.parse` from `@evanion/urn` strips only its own NID, compared without
regard to case, and reads a foreign URN without throwing:

```ts twoslash file=libs/urn/README.md region=parse

```

A foreign NID stays at the front of the `nss` field, and a foreign scheme keeps
the whole identifier there. An order URN read by `GameURN` therefore never
yields an `nss` that passes for a game slug. Every part comes back in the case
it was written in, and `nid` holds the namespace a foreign URN came from.

## One URN class for every namespace

The base `URN` class of `@evanion/urn`, which every namespace class extends,
serves code whose namespaces are open-ended. Its `stringify` takes the NID, and
then the scheme, as arguments after the NSS. The object form,
`{ nss, nid?, urn? }`, names each part and matches what `parse` returns, so it
is the form to prefer:

```ts twoslash file=libs/urn/README.md region=stringify-forms

```

`baize:game:azul` is outside RFC 8141, which fixes the scheme at `urn`.
`stringify` writes whatever NID it is given, but `parse` strips only the class's
own, and the base class's own NID is the placeholder `'nid'`. So
`URN.parse(x).nss` keeps the NID of every real namespace. `extractId` returns
the id after the NID, whatever the namespace:


## Check whether two URNs share a namespace

`sameNamespace` from `@evanion/urn` answers whether two URNs have the same
scheme and the same NID, compared without regard to case. It reads no class's
own NID, so the example calls it on the base `URN` class:

```ts twoslash file=libs/urn/README.md region=same-namespace

```

`sameNamespace` returns `false` for a string that is not a URN, as
`belongsToNamespace` does.
