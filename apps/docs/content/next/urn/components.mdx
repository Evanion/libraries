# r-, q- and f-components

`@evanion/urn`'s `parse` splits the r-, q- and f-components off a URN into fields of their own, and `stringify`, given the parts as an object, writes them back.

## The Problem: Identifying Specific Versions or Sections

A simple URN identifies a resource, but it doesn't identify a *specific version* or *subset* of that resource. For example, if you need to link to a specific edition of a board game, or a specific section of its rules, you can't do that with a bare identifier like `urn:game:brass-birmingham`.

Adding this information as part of the main ID (the NSS) would break the identity of the resource—you'd be treating the "2018 Edition" as a different game entirely rather than a version of the same game.

## Solution: URN Components

RFC 8141 §2.3 defines three components that can be appended to a URN. These allow you to carry metadata and specific pointers without changing the identity of the resource. Each component starts with an **introducer**:

| Component | Introducer | RFC 8141 | Purpose | Example Use Case |
| :--- | :--- | :--- | :--- | :--- |
| **r** | `?+` | §2.3.1 | Parameters for the resolution service | `?+lang=en` (Request English listing) |
| **q** | `?=` | §2.3.2 | Parameters for the named resource | `?=edition=2018` (Specific edition) |
| **f** | `#` | §2.3.3 | A fragment within the resource | `#setup` (The "Setup" section of the rules) |

## Writing Components with `stringify`

To write components, you must pass the parts to `stringify` as an object: `{ nss, rComponent?, qComponent?, fComponent? }`. 

The library automatically ensures the introducers appear in the correct order (r, then q, then f), regardless of the order of keys in your object. An empty `fComponent` writes a bare `#`.

## How Components are Identified

Because the identifier itself (the NSS) cannot contain `?` or `#`, `@evanion/urn` uses these characters as delimiters. It parses components in the following order:

1. **f-component**: Everything after the first `#`. This is the final part of the URN.
2. **r- and q-components**: In the remaining string, the first `?` after the NSS starts the component. If `+` follows, it's an r-component; if `=` follows, it's a q-component. Any other character following `?` throws a `ValidationError`.
3. **r-component bounds**: An r-component continues until it hits `?=`, which marks the start of the q-component.

## Components and URN Equivalence

Crucially, components are **not part of the resource's identity**. RFC 8141 §3.1 excludes all three components from URN equivalence. 

`@evanion/urn`'s `equals` and `extractId` both ignore components. This means a URN with metadata is considered equivalent to the bare URN it describes.

`sameNamespace` and `belongsToNamespace` also ignore components, as they only care about the scheme and NID.
