# r-, q- and f-components

`@evanion/urn`'s `parse` splits the r-, q- and f-components off a URN into
fields of their own, and `stringify`, given the parts as an object, writes them
back.

## The three URN components

A service that needs one edition of a game, or one section of its rules, puts
it in a component after the NSS, and `@evanion/urn` still reads the same game.
RFC 8141 §2.3 defines three components. Each one starts with an
**introducer**, the one or two characters that mark where it begins:

| Component | Introducer | RFC 8141 | Carries                                   | In the shop                         |
| --------- | ---------- | -------- | ----------------------------------------- | ----------------------------------- |
| r         | `?+`       | §2.3.1   | parameters for the service resolving it   | `?+lang=en`, the listing's language |
| q         | `?=`       | §2.3.2   | parameters for the named resource         | `?=edition=2018`, one edition       |
| f         | `#`        | §2.3.3   | a secondary resource within the named one | `#setup`, one section of the rules  |

## Write URN components with stringify

`stringify` in `@evanion/urn` writes a component only when it is given the
parts as an object, `{ nss, urn?, nid?, rComponent?, qComponent?, fComponent? }`.
The introducers always go in the order r, then q, then f, whatever order the
keys were written in, and an empty `fComponent` writes a bare `#`:

included, for a URN in the class's own namespace.

## How parse finds each URN component

No part of a URN's identifier may contain `?` or `#`, so `@evanion/urn`'s
`parse` reads the first of either as the start of a component. It takes the
components off in the order RFC 8141 fixes:

1. The f-component comes off first. It is everything after the first `#`,
   because the r- and q-components may contain `?` characters of their own and
   only a `#` ends them.
2. In what is left, the first `?` after the NSS starts the r-component when `+`
   follows it, and the q-component when `=` follows it. A `?` followed by
   anything else throws a `ValidationError`.
3. An r-component runs to the first `?=` after it, which starts the
   q-component.

## What a URN component may contain

`@evanion/urn` allows the r- and q-components the characters of the NSS, which
[Checking URN input](../validation) lists, plus `?` anywhere but the first
character, and each needs at least one character. The f-component allows the
same set with no first-character rule and may be empty, so `urn:game:azul#`
parses to `fComponent: ''`.

its introducer.

## What ignores URN components

RFC 8141 §3.1 excludes all three components from URN equivalence, so
`@evanion/urn`'s `equals`, which compares two URNs, ignores them. `extractId`
drops them, because a component is not part of the identifier. Neither method
reads the class's NID, so the example calls both on `URN`:
