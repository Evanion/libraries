# @evanion/urn

A bare `42` does not say whether it names a game or an order, and `@evanion/urn` writes Uniform Resource Names (URNs) that do: `urn:game:42` is a game and `urn:order:42` an order.

## The "Ambiguous ID" Trap

In systems that integrate multiple data sources, simple IDs like `123` are a liability, and `@evanion/urn` exists to replace them. You cannot tell if `123` refers to a game, an order, or a customer without knowing the external context, which leads to:

- **Type confusion**: an order ID is accidentally treated as a game ID.
- **Collision risks**: two different entities share the same numeric identifier.

URNs solve this by embedding the context directly into the identifier, so a single string like `urn:game:brass-birmingham` is self-describing and safe to pass across service boundaries.

## How @evanion/urn works

`@evanion/urn` reads a URN with `parse`, which returns its three primary parts, `urn` (the scheme), `nid` (the namespace identifier) and `nss` (the namespace-specific string), and `stringify` joins these parts back into a single URN.

To manage different namespaces, you create a **namespace class**—a subclass of `URN` that sets a static `nid` property. The examples are set in Baize, a board game shop, where the `GameURN` class sets `nid` to `'game'` and a `// ->` comment gives the value of the call on its line:

## The URN vocabulary

Every `@evanion/urn` page uses the following terms to describe the parts of a URN, such as `urn:game:brass-birmingham?=edition=2018`.

- **Scheme**: The first part, which [RFC 8141](https://datatracker.ietf.org/doc/html/rfc8141) fixes at `urn`. `parse` returns it under the key `urn`.
- **Namespace Identifier (NID)**: The second part (`game`), which defines the kind of resource being named.
- **Namespace Specific String (NSS)**: The third part (`brass-birmingham`), which uniquely identifies the resource within that namespace.
- **Component**: An optional tail after the NSS. A URN names the same game with or without one.
  - **r-component** (`?+`): Parameters for the service resolving the URN.
  - **q-component** (`?=`): Parameters for the resource itself (e.g., an edition).
  - **f-component** (`#`): A specific fragment or section within the resource.
- **Namespace Class**: A subclass of `URN` (like `GameURN`) that sets `nid`, and optionally `urn` and `separator`, the `:` between the parts.
- **Foreign URN**: A URN whose scheme or NID differs from the class being used to parse it. If `GameURN` parses `urn:order:42`, it returns `nid: 'order'` and keeps `order:42` together in the `nss`, so code that checks `nid` before a game lookup never mistakes it for game `42`.

| Goal                                       | Tool                                                  |
| :----------------------------------------- | :---------------------------------------------------- |
| Create a URN from an ID                    | `stringify` (on a namespace class or `URN`)           |
| Split a URN into its parts                 | `parse`                                               |
| Verify if a URN is in a specific namespace | `belongsToNamespace`, or `sameNamespace` for two URNs |
| Get the raw ID regardless of namespace     | `extractId`                                           |
| Screen a string without throwing           | `isValidFormat`                                       |
| Handle malformed input                     | `ValidationError` and `InvalidError`                  |
| Attach metadata (editions, sections)       | `parse`, and `stringify` given an object              |
| Safe encoding for titles                   | `encodeNss` and `decodeNss`                           |
| Compare two URNs                           | `equals` (RFC 8141 §3.1 equivalence)                  |

## Design constraints

`@evanion/urn` avoids four behaviors:

- **No automatic normalization**: `parse` preserves the original case, and a percent-encoded character such as `%3A` stays encoded. Use `equals` to compare, which ignores case in the scheme, the NID and the hex digits of a percent-encoded character.
- **No implicit encoding**: `stringify` throws on literal spaces. Encode a title with `encodeNss` before `stringify` will accept it.
- **No deduplication**: `stringify` writes the NSS as given, so `GameURN.stringify('game:azul')` returns `urn:game:game:azul`, with the NID twice.
- **No resolution**: The library names resources; it does not fetch them from a database.
