# @evanion/urn

A bare `42` in a message does not say whether it names a game or an order.
`@evanion/urn` writes and reads Uniform Resource Names (URNs), identifiers that
carry their namespace: `urn:game:42` is a game and `urn:order:42` an order.

## How parse splits a URN

`@evanion/urn` reads a URN with `parse`, which returns its three parts: `urn`,
the scheme; `nid`, the namespace; and `nss`, the id inside that namespace.
`stringify` joins the parts back into a URN. Each namespace gets a class of its
own, a subclass of `URN` that sets the static property `nid`. The examples are
set in Baize, a board game shop, and `GameURN` is its class for games, with
`nid` set to `'game'`. A `// ->` comment gives the value of the call on its
line:

## The @evanion/urn vocabulary

These terms name the parts of `urn:game:brass-birmingham?=edition=2018` and
the classes `@evanion/urn` reads them with. Every later page in this section
uses them.

- The **scheme** is the first part, `urn`.
  [RFC 8141](https://datatracker.ietf.org/doc/html/rfc8141), the URN standard,
  fixes it at `urn`. `parse` returns it under the key `urn`.
- The **namespace identifier** (NID) is the second part, `game`. It says what
  kind of thing the rest names, and `parse` returns it under `nid`.
- The **namespace-specific string** (NSS) is the third part,
  `brass-birmingham`. It names one game inside the namespace, and `parse`
  returns it under `nss`.
- A **component** is an optional tail after the NSS, here `?=edition=2018` for
  one edition of the game. RFC 8141 defines three. The r-component, after `?+`,
  carries parameters for whatever resolves the URN. The q-component, after
  `?=`, carries parameters for the game itself. The f-component, after `#`,
  names a part of it, such as one section of the rules. A component is outside
  the identifier, so a URN names the same game with or without one.
- A **namespace class** is a subclass of `URN` that sets `nid`, and optionally
  `urn` and `separator`, the `:` between the parts. Its `parse` and `stringify`
  read those static properties. `GameURN` is one.
- A **foreign** URN is one whose scheme or NID differs from a namespace class's
  own, as `urn:order:42` is to `GameURN`. `parse` strips only the class's own
  NID, so a foreign NID stays at the front of the `nss` as `order:42`, and a
  game lookup by that `nss` never returns game `42`.

## What @evanion/urn can do

Each row names a task and the `@evanion/urn` export that does it.

| You want to                                      | What @evanion/urn gives you                                                                                   |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| mint a URN from an id                            | `stringify` on a namespace class, or `URN.stringify` with the NID as its second argument                      |
| read a URN into its parts                        | `parse`, which keeps a foreign NID in the `nss`                                                               |
| check which namespace a URN is in                | `belongsToNamespace` for one URN, `sameNamespace` for two                                                     |
| get the id after the NID, whatever the namespace | `extractId`                                                                                                   |
| check a string before reading it                 | `isValidFormat`, which never throws                                                                           |
| tell a malformed URN from one bad part           | `ValidationError` when the string is no URN, and its subclass `InvalidError` when one part breaks its grammar |
| carry an edition or a section of the rules       | the q- and f-components, read by `parse` and written by `stringify`                                           |
| put a title such as `Brass: Birmingham` in a URN | `encodeNss` and `decodeNss`                                                                                   |
| compare two spellings of one URN                 | `equals`, which ignores case in the scheme and the NID, per RFC 8141 §3.1                                     |

## What @evanion/urn does not do

`@evanion/urn` leaves four jobs to the code around it.

- It does not normalise. `parse` returns every part in the case it was written
  in. A percent-encoded character, a `%` and two hex digits such as `%3A` for
  `:`, stays encoded, because RFC 8141 §3.1 keeps an encoded character opaque.
  `equals` is the comparison.
- It does not encode. `stringify` writes the NSS as given and throws on a
  literal space. A title already through `encodeNss` is therefore never encoded
  a second time, and `encodeNss` is the explicit step.
- It does not deduplicate. `stringify('game:azul')` on `GameURN` writes
  `urn:game:game:azul`, and `parse` returns `game:azul` from it unchanged, so an
  id from another system that already contains a `:` survives the round trip.
- It does not resolve. A URN names a game, and finding that game's listing is
  the application's job. The r-component carries parameters to whatever does
  the finding.

## Declare GameURN in a project of your own

A namespace class and the three parts `parse` returns are all of the
`@evanion/urn` model that minting a URN needs.
[Getting started](./getting-started) installs the package, declares `GameURN`
in a file of your own, and mints `urn:game:brass-birmingham` with it.
