# Page data, wrappers and nested items

Pass `ctx` to `Widgets.astro` to give every widget the same page data, and
`chrome` to wrap every widget in the same markup. A widget that holds items
renders its own `Widgets`.

## Give every widget the page's data with ctx

astro-widget's `Widgets.astro` passes its `ctx` prop to every widget, as a prop
named `ctx`, so data the whole page shares, such as which store the page is for,
is written once. An Astro component runs once, top down, and has no context a
widget could read from while it renders, so page data reaches a widget as a
prop. Save this widget as `src/widgets/Stock.astro`. It renders a `stock` item's
`copies` and reads the store's name from `ctx`:

```astro file=libs/astro-widget/examples/src/widgets/Stock.astro region=stock

```

Add `stock: Stock` to the registry in `src/registry.ts`, and import `Stock`
from `./widgets/Stock.astro` there. In `src/pages/brass-birmingham.astro`, pass
`ctx={{ store: 'Gothenburg' }}` to `<Widgets>`. Then add a `stock` item to
`src/data/brass-birmingham.json`, with `"id": "stock"`, `"type": "stock"` and
`"props": { "copies": 3 }`.

## Wrap every widget with chrome

astro-widget's `chrome` prop holds one component, `chrome.item`, which
`Widgets.astro` wraps around every widget. The chrome receives the item's
`type`, `id` and `meta`, and none of its `props`. `meta` says where and how the
item sits, such as its background, and `props` holds the widget's own data. Save
this chrome as `src/chrome/Section.astro`. It puts each widget in a `<section>`
whose class names the item's background:

```astro file=libs/astro-widget/examples/src/chrome/Section.astro region=section

```

The chrome has to render `<slot />`, where Astro puts the widget it wraps. A
chrome with no `<slot />` drops the widget, and Astro reports nothing.

In `src/pages/brass-birmingham.astro`, import `Section` from
`../chrome/Section.astro` and pass `chrome={{ item: Section }}` to `<Widgets>`
beside `ctx`. Give the `stock` item
in the JSON `"meta": { "background": "felt" }`. The test below renders that
`stock` item through the container API, with `ctx` set to
`{ store: 'Gothenburg' }` and `Section` as `chrome.item`:

```ts file=libs/astro-widget/README.md region=ctx-and-chrome

```

The `<section>` and its `id` came from the chrome, `bg-felt` from the item's
`meta`, and `Gothenburg` from `ctx`. On your page the header and the price each
get a `<section>` too.

## Render items nested inside an item

astro-widget's `Widgets.astro` does not render an item's `children`. It passes
them to the widget as data, in a prop named `children`, because an Astro
component takes rendered child content only through `<slot />`. A widget that
holds items renders its own `Widgets` over them, through a registry of its own.
Save the card the grid holds as `src/widgets/GameCard.astro`:

```

```

Save the grid as `src/widgets/GameGrid.astro`. It renders its `title` as an
`<h2>`, and its `children` through `cardRegistry`:

```astro file=libs/astro-widget/examples/src/widgets/GameGrid.astro region=game-grid

```

Add `'game-grid': GameGrid` to `src/registry.ts`, and import `GameGrid` from
`./widgets/GameGrid.astro` there.
`cardRegistry` has a module of its own because `GameGrid` imports it. Inside
`src/registry.ts`, which imports `GameGrid`, it would have `GameGrid` import a
module that imports `GameGrid`.

## Add the new types to the build gate

astro-widget's `validateItems` checks every item, the grid's children included,
against the one `known` it is handed. In `scripts/check-content.ts`, the build
gate from [Check CMS items before Astro renders them](../validation), add
`'stock'`, `'game-grid'` and `'game-card'` to `known`, or the build stops on the
new items as unknown types. Add `'game-grid': ['title']` to `required`, so a
grid saved with no title stops the build.

## What a bad save does to these widgets

Your listing page now reads the store from `ctx`, wraps each widget in a
`<section>`, and holds a grid of game cards, and one `known` list covers both
registries. [What a bad CMS save reports and renders](../bad-items) goes through
each fault `validateItems` reports and what `Widgets.astro` renders for it, and
checks the grid's children against the grid's own registry.
