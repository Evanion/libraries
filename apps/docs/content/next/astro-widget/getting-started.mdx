# Getting started

By the end of this page, you will have a functional Astro page that renders components dynamically based on a JSON payload from a CMS. You'll learn how to define a widget registry and use the `Widgets.astro` component to render your content.

## Prerequisites

To follow this guide, ensure you have the following:

- **An Astro project**: If you don't have one, run `npm create astro@latest`.
- **Astro 7, from 7.3.4**: This is the package's only peer dependency.
- **Node 22.12 or newer and an ESM project**: Astro 7 needs Node 22.12, and `@evanion/astro-widget` is an ESM-only package.

## Install astro-widget

Run the command for your preferred package manager:

```bash
npm install @evanion/astro-widget
```

`@evanion/widget` (the core logic) is installed automatically. You can import all the core tools—like `defineWidgets` and `validateItems`—directly from `@evanion/astro-widget`.

Start the development server:

```bash
npm run dev
```

Open `http://localhost:4321/brass-birmingham`. You will see the header and the price box rendered in the order they appear in the JSON. Note that `Widgets.astro` adds no extra HTML elements of its own inside the `<main>` tag.

## Catch a Stale Type Before it Ships

`Widgets.astro` follows a "fail-soft" strategy: it simply skips any item whose `type` is not in the registry. While this prevents the page from crashing, it can leave gaps in your content.

To prevent this, you should run `validateItems` as a build-time check. [Check CMS items before Astro renders them](../validation) shows how to stop `astro build` if your CMS payload contains an unknown widget type.
