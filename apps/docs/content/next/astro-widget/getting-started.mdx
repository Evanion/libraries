By the end of this page, you will have an Astro page where `Widgets.astro` renders components from the JSON a CMS saved. You'll define a widget registry and render a Baize listing page through it.

## Prerequisites

Before you install astro-widget, you need:

- **An Astro project**: If you don't have one, run `npm create astro@latest`. It makes one with a `dev` script that starts Astro's development server.
- **Astro 7.3.4 or a later 7.x release**: This is the package's only peer dependency. `npx astro --version` prints the version your project has.
- **Node 22.12 or newer and an ESM project**: Astro 7 needs Node 22.12, and `@evanion/astro-widget` is an ESM-only package. A project `npm create astro` made is ESM already.

## Install astro-widget

Run the command for your preferred package manager:

```bash
npm install @evanion/astro-widget
```

```bash
yarn add @evanion/astro-widget
```

```bash
pnpm add @evanion/astro-widget
```

`@evanion/widget` (the core logic) is installed automatically, and you import its item types, `defineWidgets`, `validateItems`, `ERROR_MESSAGES` and `VALIDATION_MESSAGES` directly from `@evanion/astro-widget`. `Widgets.astro` is published as `.astro` source, and Astro compiles it from `node_modules` with no configuration.

## Step 2: Map Each Type to Its Widget

Use the `defineWidgets` helper to keep your type names as literal types, `'listing-header'` and `'price-box'` where an object annotated `WidgetRegistry` would have `string`, which gives you autocomplete in your editor.

## Step 3: Import Your CMS Data

astro-widget renders the items as the CMS saved them, and Astro allows you to import JSON files directly. In a real project, the CMS writes this file. For this example, write it yourself.

Save your items as `src/data/brass-birmingham.json`: the `items` array from [the Overview](../)'s test, as JSON with each key in double quotes. It holds `header`, a `listing-header` whose props are `"title": "Brass: Birmingham"` and `"players": "2-4"`, and `price`, a `price-box` whose one prop is `"price": "649 kr"`.

`astro check` and your editor now type-check the JSON, and report any entry that has no `id`, no `type` or no `props` object. They check no value inside `props`. They also check the file as it was when they ran, so a save the CMS writes later goes unchecked until the next run.

## Catch a Stale Type Before it Ships

astro-widget's `Widgets.astro` follows a "fail-soft" strategy: it skips any item whose `type` is not in the registry. While this prevents the page from crashing, it can leave gaps in your content.

To prevent this, run `validateItems` as a build-time check. [Check CMS items before Astro renders them](../validation) shows how to stop `astro build` if your CMS payload contains an unknown widget type.
