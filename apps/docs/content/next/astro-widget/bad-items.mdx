## Faults in an Item's Shape

Alongside the type check, astro-widget's `validateItems` applies six structural rules to every item, whatever `known` holds. The save below has four broken entries. Entry 3 breaks two rules, so five problems come back:

```ts twoslash file=libs/astro-widget/README.md region=structural-rules

```

| Entry | Structural Fault                         | Resulting Message         |
| :---- | :--------------------------------------- | :------------------------ |
| 0     | Saved as `null` instead of an object     | `item is not an object`   |
| 1     | Missing the `id` field                   | `item id is not a string` |
| 2     | `children` is a string instead of a list | `children is not a list`  |
| 3     | `id` repeats a sibling's `id`            | `duplicate sibling id`    |
| 3     | Missing the `props` object               | `props is not an object`  |

The sixth rule, `item type is not a string`, fires on an item whose `type` is missing or is not a string.

### Special Case: Payload is not a list

If the entire payload is not an array (e.g., it's an object `{ items: [] }`), `validateItems` returns a single problem and checks nothing else. There is no item to name, so the problem's `index` is `-1`, its `id` and `type` are `'-'`, and its message is `items is not a list`:

```ts twoslash file=libs/astro-widget/README.md region=not-a-list

```

### Nested Indexing

`validateItems` walks the tree depth-first, and gives a nested child's problem an `index` relative to its own siblings, so a top-level item and its first child can both report `index: 0`. A problem carries no depth, so `id` tells the two apart only when the CMS keeps ids unique across the whole tree. ## How `Widgets.astro` Renders a Bad Item

astro-widget's `Widgets.astro` renders what it can of a bad save, under the [fail-soft rule and its `NODE_ENV` warning](../validation#the-silent-gap-in-production). Each warning is an [`ERROR_MESSAGES`](../api#error_messages) entry, and each distinct one prints once for the life of the process:

| Fault                                | Render Result                                      | Console Warning                                                                                |
| :----------------------------------- | :------------------------------------------------- | :--------------------------------------------------------------------------------------------- |
| Unknown `type`                       | Nothing renders                                    | `ERROR_MESSAGES.UNKNOWN_WIDGET`                                                                |
| No string `type`                     | Nothing renders                                    | `ERROR_MESSAGES.UNKNOWN_WIDGET` (type: "unknown")                                              |
| Not an object                        | Nothing renders                                    | `ERROR_MESSAGES.UNKNOWN_WIDGET` (type/id: "unknown")                                           |
| Missing prop                         | Widget renders, but with `undefined` for that prop | None                                                                                           |
| `items` is not a list                | Nothing renders                                    | `ERROR_MESSAGES.MALFORMED_ITEMS`                                                               |
| Missing/Repeated `id`, or no `props` | Widget renders (if type is known)                  | None                                                                                           |
| `children` not a list                | Widget renders, and receives the value as it is    | `ERROR_MESSAGES.MALFORMED_ITEMS`, only if the widget passes the value to its own `<Widgets />` |

## The "Double-Validation" Gap

A common point of confusion is when an item passes astro-widget's `validateItems` check but still renders incorrectly. This usually happens with nested registries.

`GameGrid`, the grid [Page data, wrappers and nested items](../layout#rendering-nested-items) built, renders only `game-card` children. A build gate that checks the page with one `known` list passes a `listing-header` inside the grid, and `GameGrid`'s own `cardRegistry` then skips it.
