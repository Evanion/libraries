# @evanion/astro-widget

A CMS saves a page as a list of items, and the page has to render each item
through the component its `type` names. `Widgets.astro` does that as Astro
renders the page, and sends no JavaScript to the browser.

## How Widgets.astro renders a list of items

astro-widget renders a page from the list of items a CMS saved, where each item
names a `type` and carries `props`, the values its component takes.
`Widgets.astro` takes the list as its `items` prop and a `registry` prop that
maps each `type` to an `.astro` component, and renders the items in order, each
through its component with the item's `props`.

The examples on these pages are set in Baize, a board game shop.

A page writes `<Widgets items={items} registry={registry} />`, and Getting
started builds one. The code below is a test, which renders the same component
through Astro's container API and gets its HTML back as a string. Its items are

## The astro-widget vocabulary

These terms recur on the astro-widget pages.

- An **item** is one entry in the list the CMS saved: an `id` unique among its
  siblings, a `type`, and the `props` its component takes. Optionally it carries
  `meta`, data about where the item sits on the page, and `children`, the items
  nested inside it. Its type is `AnyWidgetItem`.
- A **widget** is the `.astro` component an item renders through. It receives
  the item's `props` as its own props.
- The **registry** maps each `type` to its widget. `defineWidgets` builds one
  and keeps its type names as literal types, so an editor completes them.
- A **problem** is one fault `validateItems` finds in a list of items, such as a
  `type` the registry does not hold. `validateItems` returns every problem it
  finds in one list, and never throws.

The item shape, `defineWidgets` and `validateItems` come from `@evanion/widget`,
the framework-free half of the package family. astro-widget installs it at one
exact version and re-exports those names, so you import them from
`@evanion/astro-widget`.

## When astro-widget is the wrong tool

- A page that has to change after it loads. `Widgets.astro` renders once, when
  Astro renders the page. `@evanion/react-widget` renders the same items in
  React, including in an island, the part of an Astro page that runs in the
  browser.
- A project that needs the compiler to check each item's props. An `.astro`
  module's type carries no props, so the compiler has nothing to check an item
  against. `validateItems` checks that the props you list for each type are
  present and not blank, from a script you run before the build.
  `@evanion/react-widget` infers props from its components.
- A page no editor rearranges. Write the components into the page directly.
