# Keeping the check

`@evanion/compose` provides powerful compile-time prop validation, but that validation depends on how you declare your provider arrays. If you move your providers into a named constant or a wrapper component, you might accidentally "silence" the type checker.

## The Danger of Type Widening

In TypeScript, when you declare an array, the compiler often "widens" the type. Instead of seeing a fixed-length tuple of specific components and props, it sees a general array of `(Component | Props)[]`.

When a type is widened, `ComposeProvider` can no longer correlate a specific component with its specific props. As a result, the prop validation fails silently.

### Maintaining Checks in Named Arrays

If you define your provider list as a constant, you **must** use `as const`. This tells TypeScript to treat the array as a read-only tuple with a fixed length and exact values, preserving the a-priori type information needed for validation.


**Comparing Declaration Styles:**

| Declaration | Validation Status | Result |
| :--- | :--- | :--- |
| `providers={[...]}`, inline | ✅ Fully Checked | Every entry is validated. |
| `const providers = [...] as const` | ✅ Fully Checked | Every entry is validated. |
| `const providers = [...]` | ❌ Widened | Prop checks are lost; hand-written tuples are rejected. |
| `const providers: ProviderArray = [...]` | ❌ Silenced | Type is too general; reports no errors. |
| `const providers = [...] satisfies ProviderArray` | ❌ Silenced | Type is too general; reports no errors. |

**Pro Tip**: Using the `provider()` helper avoids this entire problem. Because `provider()` checks props at the call site, the check is preserved regardless of how the resulting tuple is stored.

## Preserving Checks in Wrapper Components

It is common to create a custom wrapper component (e.g., `<AppProviders />`) to encapsulate your root provider logic. However, if you type the `providers` prop simply as `ProviderArray`, you've silenced the check for anyone using your wrapper.

To fix this, use a **const type parameter**. This forces TypeScript to infer the exact, fixed-length tuple of the caller's array.

```tsx twoslash file=libs/compose/README.md region=wrapper

```

### How it Works:
1. **`<const T extends ProviderArray>`**: The `const` modifier tells TypeScript to infer `T` as the most specific literal type possible (a fixed-length tuple).
2. **`ComposeProviderProps<T>`**: By typing the props as `ComposeProviderProps<T>`, the validation logic of `ComposeProvider` is passed through to the caller of your wrapper.

Now, if a developer uses your `<AppProviders />` and passes a `ThemeProvider` with missing props, they will get a compile error at the call site.
