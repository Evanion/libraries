## Prerequisites

To follow this guide with `@evanion/compose`, ensure you have the following:

- **React 18 or 19**: The only dependency of `@evanion/compose`.
- **`react-dom`**: This page's example renders with it.
- **Node 20 or newer**.
- **An ESM project**: A CommonJS project needs a Node whose `require()` loads ES modules: 20.19 or later on Node 20, or 22.12 or later. An older `require()` fails with `ERR_REQUIRE_ESM`.
- **TypeScript 5.0 or newer (Optional)**: Recommended for the compile-time prop checking. The component runs without it.

## Install compose

Run the command for your preferred package manager:

```bash
npm install @evanion/compose
```

```bash
yarn add @evanion/compose
```

```bash
pnpm add @evanion/compose
```

## Flatten your provider tree

`ComposeProvider`, from `@evanion/compose`, nests context providers the way the [Overview](../#the-solution-flat-composition) nested `div`s, first entry outermost.

In the Baize shop example, the root needs to provide a cart, a theme, and a currency, each built on `createContext`. `Shop` passes the three to `ComposeProvider`, and `Basket` reads each value with `useContext`. The file imports `ComposeProvider` and `provider` from `@evanion/compose` and `* as React` from `react`. `renderToStaticMarkup` renders `markup`, as on the Overview:

```tsx twoslash file=libs/compose/README.md region=first-shop

```

`CartProvider` is a [bare component](../#the-compose-vocabulary), and the other two are tuples from `provider()`. The last entry wraps `Shop`'s own children.

`markup` is `Basket`'s paragraph and nothing else. The Overview's providers each rendered a `div`, and these three render only a context provider, which has no element of its own. So `dark` and `SEK` in the markup are the values the providers above `Basket` hold. In a browser, the Components tab of React DevTools shows the nesting: `CartProvider` on the outside and `CurrencyProvider` on the inside, wrapping your application.

## Integrating into your App Root

Render `Shop`, the component that composes the providers with `@evanion/compose`, where your nested providers sit today, around your routes or main page layout.

**Next.js App Router Tip**:
Any file calling `createContext` must be a Client Component. Mark your provider file with `'use client'`, define your providers and your `Shop` wrapper there, and then wrap your layout in `app/layout.tsx` with `<Shop>{children}</Shop>`. `ComposeProvider` itself needs no directive.

## Catching Prop Errors at Compile Time

Baize's root now renders through `@evanion/compose`, and `Basket` reads the values of all three providers. TypeScript checks each entry's props as well: `provider(ThemeProvider, { theme: 'blue' })` fails to compile, because `ThemeProvider` takes `'light' | 'dark'`. [Where the check happens](../type-checking) shows where each kind of entry is checked and what each error means.
