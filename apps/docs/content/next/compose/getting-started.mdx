# Getting started

In this guide, you will clean up your application's root component. You'll learn how to use `ComposeProvider` to flatten a nest of context providers into a simple list, and how to verify that your providers are receiving the correct props at compile time.

## Prerequisites

To follow this guide, ensure you have the following:

- **React 18 or 19**: The only dependency for `@evanion/compose`.
- **`react-dom`**: Required for the `renderToStaticMarkup` example used to visualize the nesting.
- **Node 20 or newer**.
- **An ESM project**: Your project must use ES modules.
  *(Note: CommonJS projects require Node 20.19 or 22.12+ to load ES modules via `require()`)*.
- **TypeScript 5.0 or newer (Optional)**: Highly recommended to take advantage of the compile-time prop checking.

## Install compose

Run the command for your preferred package manager:

```bash
npm install @evanion/compose
```

```bash
yarn add @evanion/compose
```

```bash
pnpm add @evanion/compose
```

## Flatten your provider tree

Instead of nesting providers manually, you can pass them as an array to `ComposeProvider`. The first item in the array becomes the outermost wrapper, and the last item wraps your application's children.

In our Baize shop example, the root needs to provide a cart, a theme, and a currency. We use `ComposeProvider` to orchestrate this:


Here is a breakdown of the setup:
- `CartProvider` is passed as a **bare component**, as it doesn't require any initial props.
- `ThemeProvider` and `CurrencyProvider` are wrapped in the `provider()` helper. This creates a **tuple** `[Component, Props]`, which allows TypeScript to verify that you've provided the correct props for those specific providers.
- The `Shop` component now acts as a clean wrapper that passes these providers to `ComposeProvider`.

If you were to render this to HTML, you'd see a perfectly nested structure where `CartProvider` is on the outside and `CurrencyProvider` is on the inside, wrapping the `Basket` component.

## Integrating into your app root

The `Shop` component we created above is where your provider logic now lives. You should place this component at the very root of your application, typically around your routes or main page layout.

If you are using the **Next.js App Router**, remember that any file calling `createContext` must be a Client Component. Mark your provider file with `'use client'`, define your providers and your `Shop` wrapper there, and then wrap your layout in `app/layout.tsx` with `<Shop>{children}</Shop>`. 

Note that `ComposeProvider` itself is a pure component that doesn't use hooks, so it doesn't require the `'use client'` directive.

## Visualizing the nesting

To understand how the order of your array affects the resulting tree, imagine each provider as a box. Moving a provider up in the array moves its "box" further outward, wrapping more of the application. Moving it down moves it further inward.

Be careful: changing the order of providers while the app is running will cause React to remount the entire subtree, which will reset any local state held by those providers.

## Catching prop errors at compile time

One of the biggest advantages of `@evanion/compose` is that it brings type safety to your provider list. If you pass a string where a number is expected in a provider's props, TypeScript will flag it immediately.

For a detailed look at how this verification works, see [Where the check happens](../type-checking).
