## Prerequisites

To follow this guide with `@evanion/compose`, ensure you have the following:

- **React 18 or 19**: The only dependency of `@evanion/compose`.
- **`react-dom`**: This page's example renders with it.
- **Node 20 or newer**.
- **An ESM project**: A CommonJS project needs a Node whose `require()` loads ES modules: 20.19 or later on Node 20, or 22.12 or later. An older `require()` fails with `ERR_REQUIRE_ESM`.
- **TypeScript 5.0 or newer (Optional)**: Recommended for the compile-time prop checking. The component runs without it.

## Install compose

## Flatten your provider tree

With `@evanion/compose`, you pass your providers as an array to `ComposeProvider` and stop nesting them by hand. The first item in the array becomes the outermost wrapper, and the last item wraps your application's children.

In the Baize shop example, the root needs to provide a cart, a theme, and a currency, each built on `createContext`. `Shop` passes the three to `ComposeProvider`, and `Basket` reads each value with `useContext`. The file imports `ComposeProvider` and `provider` from `@evanion/compose` and `* as React` from `react`. `renderToStaticMarkup`, from `react-dom/server`, turns the tree into the HTML string `markup`:

```tsx twoslash file=libs/compose/README.md region=first-shop

```

### Breakdown of the Setup:

- **Bare Components**: `CartProvider` is passed as a bare component because it doesn't require any props.
- **Tuples**: `ThemeProvider` and `CurrencyProvider` are wrapped in the `provider()` helper. This creates a **tuple** `[Component, Props]`, which allows TypeScript to verify that you've provided the correct props for those specific providers.
- **The Wrapper**: The `Shop` component now acts as a clean wrapper that passes these providers to `ComposeProvider`.

`markup` is `Basket`'s paragraph and nothing else. A context provider renders no element of its own, so `dark` and `SEK` in the markup are the values the providers above `Basket` hold. In a browser, the Components tab of React DevTools shows the nesting: `CartProvider` on the outside and `CurrencyProvider` on the inside, wrapping your application.

## Integrating into your App Root

The `Shop` component is where your `@evanion/compose` provider logic now lives. Place it where your nested providers sit today, around your routes or main page layout.

**Next.js App Router Tip**:
Any file calling `createContext` must be a Client Component. Mark your provider file with `'use client'`, define your providers and your `Shop` wrapper there, and then wrap your layout in `app/layout.tsx` with `<Shop>{children}</Shop>`.

`ComposeProvider` itself is a pure component that doesn't use hooks, so it doesn't require the `'use client'` directive.

## Catching Prop Errors at Compile Time

One of the biggest advantages of `@evanion/compose` is that it brings type safety to your provider list. Because the entries are tuples from the `provider()` helper, TypeScript can verify that the props you pass to a provider match its requirements. If you pass `'blue'` where `ThemeProvider` expects `'light' | 'dark'`, TypeScript will flag it.

For a detailed look at how this verification works, see [Where the check happens](../type-checking).
