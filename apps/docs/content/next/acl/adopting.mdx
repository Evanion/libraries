# How do I use rules another service published?

`parseMatrix(json)` builds an evaluator over a matrix another service published,
and answers `unknown-action` for any permission that document does not carry.

## Adopting another service's acl matrix with `parseMatrix`

Baize's storefront draws buttons from rules another Baize service owns. A
storefront that writes those rules a second time is right until the owner
changes one: the owner keeps refusing correctly, no alarm fires, and the button
stays hidden against a server that would have allowed the call.

The matrix is the JSON document a policy flattens to, which [the Overview](../)
introduces. The owner serves it, and the storefront fetches it and hands it to
`parseMatrix`:

```ts twoslash file=libs/acl/docs/examples.md region=foreign-matrix

```

Each permission carries `key`, `object`, `action` and a `rules` list of allow
rules, and each rule holds a `when` list of conditions that must all hold. This
document grants `question.read` to a subject whose `roles` array holds
`bookseller`. It carries no `question.delete`, so asking for `delete` answers
`unknown-action` with `allowed: false`. A real document holds every key its
owner publishes, across every object kind it owns, and the whole list builds one
evaluator.

## Why `parseMatrix` answers where `hydratePolicy` throws

`parseMatrix(json, options?)` is
`hydratePolicy(json, { ...options, closed: true })`. `closed: true` is the flag
that turns a missing key into a refusal, and it sits after the spread, so no
option a caller passes turns it off. The two calls differ only on a key the
document does not carry:

- `hydratePolicy` throws `UnknownObjectKeyError` for an object kind the
  document lacks, and `UnknownPermissionError` for an action it lacks.
- `parseMatrix` answers `unknown-action` with `allowed: false` for both.

A malformed document throws at construction on either path.

Which path a document gets depends on where it came from. A key your own policy
lacks is a programmer error, and the throw points at the line. A browser
rebuilding your own `access.matrix` with `hydratePolicy` is on that path too,
because your own code wrote both the document and the question. A key a foreign
document lacks means its owner removed the permission, or this consumer was
written against an older revision, and a throw there takes a page down over a
permission nobody holds.

```mermaid caption="Closed mode on the consumer's side. parseMatrix answers from the adopted rules for every key the document carries, and answers unknown-action with allowed false for every key it does not, so a permission the producer removed does not take the page down. Neither path grants a key it does not hold. The owning service decides again on
its own matrix when the call reaches it.

## What `parseMatrix` refuses before an acl evaluator exists

`parseMatrix` holds a foreign document to the same checks a local one passes,
and each refusal extends `AclConfigError`. The common ones:

| Refused at construction    | When                                                       |
| -------------------------- | ---------------------------------------------------------- |
| `InvalidMatrixError`       | not an envelope, no `permissions` array, a bad `version`   |
| `InvalidPermissionError`   | a malformed `object`, `action`, `rules` or `fields`        |
| `InvalidRuleError`         | a rule whose `when` is absent or not an array              |
| `InvalidConditionError`    | an unusable shape, path, depth or operator                 |
| `KeyMismatchError`         | `key` is not exactly `` `${object}.${action}` ``           |
| `DuplicatePermissionError` | two permissions share a key                                |
| `UnknownFieldError`        | a condition names a field the document's `schema` omits    |
| `FieldTypeMismatchError`   | an operator that does not fit the `schema`'s declared type |

[What can throw?](../errors) tables the rest. A document fetched over the
network can fail for reasons your process cannot fix, so keep the last document
that constructed. The `orders:` prefix on the object kind names the service that
owns it:

```ts twoslash file=libs/acl/docs/examples.md region=adopt-keep-last

```

`orders@8` lost its rule's conditions in transit, and `InvalidRuleError` refuses
it, so a damaged document never becomes a permission that grants everyone. A
rule with an empty `when` grants everyone, and a permission with an empty
`rules` list grants nobody. The storefront keeps answering from `orders@7`, and
`readopt` returns the class name for an alarm.

A document may carry a `schema`, which lists the fields of each object kind
under `schema.objects`. It binds per object kind: a permission on a kind the
schema does not list is unchecked, and a document with no schema checks no path.
[What the acl schema refuses](../advanced#what-the-acl-schema-refuses-before-an-evaluator-exists)
works one through.

## Which revision of an acl document is answering

`version` is a string or a number at the top of the document, and it survives
the JSON round trip, so a consumer holding a document for weeks can say which
revision decided. A process that changes a document before building an evaluator
over it runs a revision the owner never shipped. A deny overlay does that: it
merges another team's deny rules into the document, as
[Many services](../federation#cross-cutting-denials-via-overlays)
covers. `hydratePolicy(matrix, { version })` names the revision this process
runs, and `parseMatrix` takes the same option:

```ts twoslash file=libs/acl/docs/examples.md region=version-override

```

The option wins over the document's own `version`, and `access.matrix`, which
the evaluator freezes, carries the winner. So the version that decided is the
version that crosses a server-side rendering (SSR) boundary. A document stating
no version leaves `access.version` undefined, and a comparison against it
decides nothing.
[Refetching an acl matrix when its version moves](../advanced#refetching-an-acl-matrix-when-its-version-moves)
sets out the comparison.

## What adopting an acl document does not verify

The library neither signs a document nor verifies a signature. A matrix arriving
over an unauthenticated channel is a matrix an attacker wrote, and every check
above reads the shape and says nothing about where the bytes came from.
Integrity belongs to the transport, the same way
[resolving a subject](../pitfalls#forged-subjects-the-confused-deputy) belongs
to the session layer.
