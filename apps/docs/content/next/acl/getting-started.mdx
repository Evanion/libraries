`bookseller` role, delete a question and refuses a customer. A copy rebuilt from
its JSON gives the same answers.

## Before you install acl

- Node 20 or newer.
- An ESM project, meaning a `package.json` with `"type": "module"`.
  `@evanion/acl` ships no CommonJS build.
- (Optional) TypeScript 5.5 or newer, for the compiler to check your object
  kinds and actions. The package runs without it, and the examples below run as
  JavaScript once you delete their `type` lines and the `<…>` after `policy`.
- A way to run a TypeScript file. The steps below use `npx tsx`, which downloads
  tsx on first use. A project that already compiles its
  TypeScript runs the file its usual way.
- No API key, no service to run and no environment variable. `policy()` builds
  the matrix in your own process.
- No framework. The `@evanion/acl` entry point imports none, and the React
  provider and hooks are a separate package, [`@evanion/react-acl`](/react-acl).

## Install acl

Pick the line for your package manager.

```bash
npm install @evanion/acl
```

```bash
yarn add @evanion/acl
```

```bash
pnpm add @evanion/acl
```

## Write the smallest policy that answers something

An `@evanion/acl` policy is three chained calls.

- `policy<Subject, Objects>()` names two types. `Subject` is the shape of
  whoever is acting. `Objects` maps each object kind to the shape of its row, so
  `{ question: Question }` declares one kind called `question` whose rows are
  `Question`. Add a kind by adding a key.
- `.for(kind, block)` writes one kind's rules. The `kind` is one of the keys you
  just declared in `Objects`.
- `.build()` returns the evaluator, here `access`.

`.for()` hands your block one argument, conventionally `p`, and every rule and
condition comes off it:

- `p.allow(action, ...conditions)` grants an action when every condition holds.
- `p.contains(path, value)` holds when the array at `path` contains `value`. A
  path is a string rooted at `subject` or at `object`, so `'subject.roles'`
  reads `roles` off the subject.

Baize's staff carry the `bookseller` role, and a bookseller may delete any
question. Save this as `access.ts` in your project:

```ts twoslash file=libs/acl/README.md region=first-policy

```

Wrap each line that ends in a `// ->` comment in `console.log` and run
`npx tsx access.ts`. The three lines print `true`, `false` and
`no-rule-matched`, and acl is answering in your project.

`no-rule-matched` is the customer's `reason`, the default deny
[the Overview](../) named.

## Rebuild the acl evaluator from its JSON

`access.matrix` is the `@evanion/acl` matrix that the diagram on
[the Overview](../) sends to the browser, and `hydratePolicy` rebuilds an
evaluator from it. Change the first line of `access.ts` to
`import { hydratePolicy, policy } from '@evanion/acl';`, then add these lines at
the end of the file:

```ts twoslash file=libs/acl/README.md region=first-copy

```

Wrap the two new `// ->` lines in `console.log` and run the file again. They
print `true` and `false`, the answers the server's evaluator gave. Here the JSON
stays inside one process. In your app the server writes the same string into the
page or an API response, and the browser's code parses it and passes the result
to `hydratePolicy`.

With no type arguments, the evaluator `hydratePolicy` returns accepts any object
kind and action string, so the compiler no longer checks them.

## Refuse a suspended bookseller

Your `@evanion/acl` policy now grants one action by role, and a copy rebuilt
from its JSON answers the same way.
[Rules about who the user is](../subject-rules) adds a stock report that a
suspended bookseller may not read, and names each rule so a decision reports
which one decided.
