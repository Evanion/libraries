# Getting started

Before you can secure your application, you need a way to define who is allowed to do what. In `@evanion/acl`, this is called a **policy**.

By the end of this page, you will have written your first policy. You'll see how to grant the `bookseller` role the ability to delete questions while ensuring customers are refused, and you'll learn how to rebuild that same logic from a JSON snapshot.

## Prerequisites

To follow this guide, ensure you have the following:

- **Node 20 or newer.**
- **An ESM project**: Your `package.json` must include `"type": "module"`, as `@evanion/acl` does not ship a CommonJS build.
- **TypeScript 5.5 or newer (Optional)**: While the package runs in plain JavaScript, TypeScript allows the compiler to check your object kinds and actions for errors.
- **A way to run TypeScript**: We use `npx tsx` in the examples below, which handles TypeScript execution on the fly.

Note that `@evanion/acl` is completely self-contained. There are no API keys to manage, no external services to run, and no environment variables to configure—the policy is built directly within your own process.

## Install acl

Run the command for your preferred package manager:

```bash
npm install @evanion/acl
```

```bash
yarn add @evanion/acl
```

```bash
pnpm add @evanion/acl
```

## Create your first policy

Defining an authorization policy in `@evanion/acl` is a straightforward three-step chain:

1. **Name your types**: Use `policy<Subject, Objects>()` to define the shape of the user (`Subject`) and the kinds of objects being protected (`Objects`).
2. **Define the rules**: Use `.for(kind, block)` to write rules for a specific object kind.
3. **Build the evaluator**: Call `.build()` to create the `access` object, which you will use to check permissions.

Within the `.for()` block, you use a helper (conventionally named `p`) to grant or deny access:

- `p.allow(action, ...conditions)`: Grants access if all provided conditions are true.
- `p.contains(path, value)`: A condition that checks if an array (at a given path) contains a specific value (e.g., checking if `subject.roles` contains `'bookseller'`).

## Share your policy with the browser

One of the most powerful features of `@evanion/acl` is that the server and browser can share the exact same rules without duplicating code.

The `access.matrix` property contains the policy as a plain JSON document. You can send this JSON to the browser, where `hydratePolicy` rebuilds a fully functional evaluator.

Run the file again. The results will match the server's answers exactly. In a real application, your server would send this JSON string in a page or API response, allowing the browser to make instant, local authorization decisions without calling the server.

_Note: When using `hydratePolicy` without type arguments, the evaluator accepts any object kind or action string, meaning the TypeScript compiler can no longer verify them._
