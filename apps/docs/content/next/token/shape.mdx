# Code shape

To mint an `@evanion/token` code longer or shorter than a pickup code, or grouped differently, you pass `length`, `chunkSize` and `separator` to `createToken`.

## Why a Gift Card Needs a Longer Code

A short, 8-character `@evanion/token` code suits a pickup order: it's easy to read and type. But a gift card holds a balance, so a guessed code spends someone else's money, and an attacker can enumerate the 35 random bits of an 8-character code. You need a longer identifier that still feels "human-readable" through proper chunking.

Conversely, a code that staff call out across a room needs a specific shape (perhaps two groups of three characters separated by a space) to reduce miscommunication.

## Choosing a Code Shape

Using a `chunkSize` of 4 creates a visually organized code with three hyphens, resulting in a 19-character value.

### `createToken` options

| Option       | Type     | Default              | Meaning                                            |
| :----------- | :------- | :------------------- | :------------------------------------------------- |
| `length`     | `number` | `8`                  | Total characters, including the check character.   |
| `chunkSize`  | `number` | `4`                  | Characters per chunk; must divide `length` evenly. |
| `separator`  | `string` | `'-'`                | Placed between chunks and after a prefix.          |
| `dictionary` | `string` | `DEFAULT_DICTIONARY` | The characters a code draws from, in order.        |

`createToken` checks these options once, when it builds the instance. `generate` and `validate` check nothing. Every code an instance mints without a prefix passes that instance's `validate`.

## Invalid Shapes and `InvalidShapeError`

Not every combination of `@evanion/token` shape options describes a code. `createToken` throws `InvalidShapeError` when the shape is invalid. Build the instance at module scope and a bad shape throws when the process starts.

In the example below, `refusal` is a helper of your own: it takes a `TokenOptions` object, the type of `createToken`'s options, and returns the error `createToken` throws, or `undefined` when the options are accepted.


`reason` names one option, and another can fix the same shape: `length: 10, chunkSize: 4` passes with a `chunkSize` of 5 or with a `length` of 12. So the error also carries `length`, `chunkSize` and `separator` as `createToken` resolved them, defaults included, which is why the last line reads the default `length` of 8.

### Common Shape Errors

| `reason`                  | Cause                                                 | Fix                                                                              |
| :------------------------ | :---------------------------------------------------- | :------------------------------------------------------------------------------- |
| `length`                  | `length` is not an integer or is below 2.             | Set an integer of at least 2.                                                    |
| `chunk-size`              | `chunkSize` is not an integer or is below 1.          | Set an integer of at least 1.                                                    |
| `chunk-size-indivisible`  | `chunkSize` does not divide `length` evenly.          | Adjust either `length` or `chunkSize`.                                           |
| `separator-empty`         | `separator` is an empty string.                       | Provide a separator, or set `chunkSize` equal to `length` for an unchunked code. |
| `separator-in-dictionary` | `separator` shares a character with the `dictionary`. | Choose a separator that doesn't appear in the dictionary.                        |

If the `separator` shared a character with the `dictionary`, `validate` would be unable to strip it without accidentally removing part of the code's body, which is why this is forbidden. A dictionary of your own throws `InvalidShapeError` with `separator-in-dictionary` when it holds the separator, as `'0123456789abcde-'` does with the default hyphen.
