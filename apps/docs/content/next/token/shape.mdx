# Code shape

To mint an `@evanion/token` code longer or shorter than a pickup code, or grouped differently, you pass `length`, `chunkSize` and `separator` to `createToken`.

## The Problem: One Size Doesn't Fit All

A short, 8-character code is perfect for a pickup order—it's easy to read and type. But for a high-value gift card, an 8-character code is too easy to guess or collide. You need a longer, more secure identifier that still feels "human-readable" through proper chunking.

Conversely, a "counter code" meant to be spoken aloud might need a very specific shape—perhaps two short words separated by a space—to reduce miscommunication.

## Solution: Custom Token Shapes

`createToken` allows you to define the exact geometry of your codes. By adjusting the length and chunking, you can balance security (entropy) with usability.

For a gift card, you might want more characters to reduce the risk of collisions:

In this example, `giftCard` draws 15 random characters and appends a check character. With the default 32-character dictionary, this provides significant entropy (75 bits). Using a `chunkSize` of 4 creates a visually organized code with three hyphens, resulting in a 19-character value.

### Shape Options Reference

| Option       | Type     | Default            | Meaning                                            |
| :----------- | :------- | :----------------- | :------------------------------------------------- |
| `length`     | `number` | `8`                | Total characters, including the check character.   |
| `chunkSize`  | `number` | `4`                | Characters per chunk; must divide `length` evenly. |
| `separator`  | `string` | `'-'`              | Character used between chunks and after a prefix.  |
| `dictionary` | `string` | (Default alphabet) | The set of characters used to generate the code.   |

`createToken` validates these options once during instance creation. Every code minted by that instance is guaranteed to match this shape.

If you need a code that is easy to call out across a room, you can use a space as a separator and a smaller chunk size. This turns a string of characters into something that reads like two short words:

## Invalid Shapes and `InvalidShapeError`

Not every combination of options is mathematically possible. `createToken` will throw an `InvalidShapeError` if the shape is invalid. This is designed to stop your application at start-up rather than failing silently at runtime.

```ts twoslash file=libs/token/README.md region=shape-errors

```

### Common Shape Errors

| `reason`                  | Cause                                                | Fix                                                     |
| :------------------------ | :--------------------------------------------------- | :------------------------------------------------------ |
| `length`                  | `length` is not an integer or is below 2.            | Set a valid positive integer.                           |
| `chunk-size`              | `chunkSize` is not an integer or is below 1.         | Set a valid positive integer.                           |
| `chunk-size-indivisible`  | `chunkSize` does not divide `length` evenly.         | Adjust either `length` or `chunkSize`.                  |
| `separator-empty`         | `separator` is an empty string.                      | Provide a separator character.                          |
| `separator-in-dictionary` | `separator` is also a character in the `dictionary`. | Choose a separator that doesn't appear in the alphabet. |

If the `separator` is also in the `dictionary`, `validate` would be unable to strip it without accidentally removing part of the code's body, which is why this is forbidden.
