# Code shape

To mint an `@evanion/token` code longer or shorter than a pickup code, or
grouped differently, pass `length`, `chunkSize` and `separator` to
`createToken`.

## Configure a gift card code

Token's `createToken` takes the shape of its codes as options, and a Baize gift
card code wants more characters than a pickup code:

```ts twoslash file=libs/token/README.md region=instances

```

`giftCard` draws 15 random characters and appends a check character. A
character of the default 32-character dictionary carries 5 bits, because 32 is
2⁵, so `entropyBits` is 75. Four chunks of four take three hyphens, so its
`value` is 19 characters long.

| Option       | Type     | Default                              | Meaning                                             |
| ------------ | -------- | ------------------------------------ | --------------------------------------------------- |
| `length`     | `number` | `8`                                  | total characters, the check character included      |
| `chunkSize`  | `number` | `4`                                  | characters between separators; must divide `length` |
| `separator`  | `string` | `'-'`                                | between chunks, and between a prefix and the code   |
| `dictionary` | `string` | `'0123456789abcdefghjkmnpqrstuvxyz'` | the characters a code draws from, in order          |

`createToken` checks every option once, when it builds the instance, and
nothing when the instance is used. An instance you hold cannot mint an
unprefixed code its own `validate` rejects.

## Shapes createToken refuses

Token's `createToken` throws `InvalidShapeError` when `length`, `chunkSize` and
`separator` cannot describe a code. In an app the throw stops start-up at the
line that builds the instance. `refusal` below takes a `TokenOptions`, the type
of the object `createToken` takes, and catches the error so each line can show
it. It returns `undefined` when the options are accepted:

```ts twoslash file=libs/token/README.md region=shape-errors

```

A `chunkSize` of 4 does not divide a `length` of 10, so the last chunk would be
shorter than the rest. `reason` names `chunkSize`, yet a `length` of 12 fixes
the shape too. Set `chunkSize` equal to `length` for an unchunked code. A
`separator` of `'a'` is refused because `a` is in the dictionary, and `validate`
could not strip it without removing part of the code.

Because the value to change is not always the one `reason` names, the error
also carries `length`, `chunkSize` and `separator` as properties. Each holds the
value `createToken` used, defaults included. In the last line, `?.length` reads
the error's `length` property, the default 8, which that call never passed.

| `reason`                  | The shape                                        |
| ------------------------- | ------------------------------------------------ |
| `length`                  | `length` is not an integer, or is below 2        |
| `chunk-size`              | `chunkSize` is not an integer, or is below 1     |
| `chunk-size-indivisible`  | `chunkSize` does not divide `length`             |
| `separator-empty`         | `separator` is the empty string                  |
| `separator-in-dictionary` | `separator` shares a character with `dictionary` |

Those five are every `reason` an `InvalidShapeError` carries. A `dictionary`
that `createToken` refuses throws a different error.

## Try a token shape and alphabet

The card below mints codes with token's `generate` in your browser. Every option
its two controls offer is a configuration `createToken` accepts:

- The shape control sets the `length` and `chunkSize` pair.
- The alphabet control picks the default 32 characters or the 16 of
  hexadecimal, `0123456789abcdef`.

The caption reports the code's random bits, and the number of codes the shop
can issue before the chance that two of them match reaches one in two.
