# Getting started

In this guide, you will implement a pickup code system for a store. You'll learn how to issue a unique, human-readable code at checkout and how to use `validate` to ensure that a code read back at the counter is well-formed before searching your database.

## Prerequisites

To follow this guide, you will need:

- **Node 20 or newer**, or any modern browser. `generate` uses `crypto.getRandomValues`, which is available in both environments without additional imports.
- **An ESM project**: Your project must be an ES module. If you are starting in an empty folder, run `npm init -y` followed by `npm pkg set type=module`.
  _(Note: CommonJS projects require Node 20.19 or 22.12+ to load ES modules via `require()`)_.

## Install token

Run the command for your preferred package manager:

```bash
npm install @evanion/token
```

`@evanion/token` automatically installs `@evanion/luhn`, which handles the check-character calculations.

## Implement the checkout and pickup flow

Now, let's use the token instance to handle a real-world scenario: issuing a code at checkout and validating it at the counter.

The workflow is simple:

1. **At Checkout**: Call `generate()`. This returns both the `value` (which you print on the receipt) and the `body` (which you store in your database).
2. **At Pickup**: Pass the customer's spoken or typed code to `validate`.

In this example, `validate` acts as a gate. If a customer mishears a character (e.g., `m` as `n`), `validate` refuses the code immediately. This prevents your system from performing a database lookup for a code that is mathematically impossible, allowing you to tell the customer their code is mistyped rather than simply "not found."

## Professional touch: Adding a prefix

To make your codes more recognizable, you can add a prefix like `ORD-`. This helps users and staff identify the code's purpose at a glance.

You can mint prefixed codes by passing a `prefix` option to `generate`. For more advanced usage—such as redeeming codes regardless of how the user types them—see [Generating and validating](../usage).
