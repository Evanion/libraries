By the end of this page `@evanion/token` issues a pickup code at checkout, and
the counter finds the order again from the code a customer reads back.

## Before you install token

- Node 20 or newer, or any browser. `generate` draws from
  `crypto.getRandomValues`, which both supply with no import and no polyfill.
- An ESM project. A CommonJS project needs Node 20.19, 22.12 or newer, whose
  `require()` loads ES modules. An older `require()` fails with
  `ERR_REQUIRE_ESM`.

## Install token

Pick the line for your package manager.

```bash
npm install @evanion/token
```

```bash
yarn add @evanion/token
```

```bash
pnpm add @evanion/token
```

The package manager installs `@evanion/luhn` with it, which computes the check
character.

## Construct a token instance

`createToken` checks its options and returns a frozen token instance. Build it
at module scope, so the options are checked once, at start-up. `generate()`
returns the code a person reads as `value`:

```ts twoslash file=libs/token/README.md region=construct

```

`createToken()` with no options takes the defaults, and the shop's pickup codes
need nothing else. `length` is 8 and counts the check character, so seven of
the eight characters are random. A hyphen splits the code into two chunks of
four, which is why `value` is nine characters long.

## Issue a pickup code at checkout and find its order at the counter

`generate` returns `value`, such as `a4kp-9mxa`, which the shop prints on the
receipt, and `body`, such as `a4kp9mx`, which the orders table stores. At the
counter, token's `validate` turns the code a customer reads back into the same
`body`, or refuses it with a `reason` before the table is read. A `Map` stands
in for the orders table:

```ts twoslash file=libs/token/README.md region=checkout

```

The code `generate` minted finds `order-2026-0042`. `a4kp-9mxa`, the Overview's
example, is well formed, so `validate` accepts it. The table answers "no such
order" because this `Map` holds only the code `generate` just minted.
`a4kp-9nxa` is `a4kp-9mxa` with `m` heard as `n`, and the counter refuses it
without a lookup, so a code with one character misheard never reads as a missing
order.

## Print pickup codes with the ORD prefix

The counter now tells a misheard token code from one the shop never issued.
Baize prints its pickup codes as `ORD-a4kp-9mxa`, and
[Generating and validating](../usage) mints one with that prefix, redeems it
however the customer types it, and lists every reason `validate` refuses a code.
