# Generating and validating

To print a pickup code as `ORD-a4kp-9mxa` and redeem it regardless of how a customer types it, you combine `generate` with a custom prefix and use `validate` to screen the input.

## Minting a Pickup Code with a Prefix

When you pass a `prefix` to the `@evanion/token` `generate` method, it returns the code in four fields:

```ts twoslash file=libs/token/README.md region=generate

```

- **`value`**: The printed code, prefix included (`ORD-a4kp-9mxa`), 13 characters in all.
- **`body`**: The seven random characters used as the database key.
- **`check`**: The final check character, the last character of `value`.
- **`prefix`**: The prefix you provided.

## Redeeming a Prefixed Code

The `@evanion/token` `validate` method works on the code's body and check character, and takes no prefix option.

If you pass `ORD-a4kp-9mxa` directly to `validate`, it strips the hyphen, the default separator, and lowercases `ORD` into part of the code. The default dictionary has no `o`, so `validate` refuses the code as `outside-alphabet`. You must strip the prefix before validating:

```ts twoslash file=libs/token/README.md region=prefix

```

In the example above, `validatePickupCode` is a function of your own that handles the stripping. Because the default dictionary excludes the letter `o`, no valid code can start with `ord`. This makes it safe to strip any leading `ord` (case-insensitively, with or without its hyphen) without risk of accidentally removing part of the actual code. A prefix typed wrong, such as `ODR-`, is left in place, and `validate` refuses the code.

## Why token Refuses a Code

The `@evanion/token` `validate` method returns `valid: true` and the `body` if the code is well-formed, or `valid: false` and a `reason` if it fails.

```ts twoslash file=libs/token/README.md region=validate

```

| `reason`           | Meaning                                                                                   |
| :----------------- | :---------------------------------------------------------------------------------------- |
| `outside-alphabet` | The code contains a character not found in the dictionary, after separators are stripped. |
| `wrong-length`     | The code does not match the required `length`.                                            |
| `check-failed`     | The check character does not match the calculated value for the body.                     |

`validate` checks these conditions in order and reports the first failure. Since it has no side effects and never throws, you can run it on every request before performing a database lookup.

## How token Reads Hyphens and Capitals

Customers rarely type an `@evanion/token` code exactly as it was printed. They might omit hyphens, use different grouping, or type everything in capitals.

`validate` handles this by stripping the separator and reading uppercase as lowercase before it checks anything.

```ts twoslash file=libs/token/README.md region=separators

```

Because every variation of the spelling returns the same `body`, they all resolve to the same record in your database.

## What the Check Character Catches

`@evanion/token` computes the check character with the Luhn algorithm, which catches:

- **Single-Character Substitutions**: Any single character misread or mistyped at any position, including the check character itself, is always caught.
- **Adjacent Swaps**: Every swap of two neighboring characters is caught, except a swap of `0` and `z`, which the blind spot below explains.

```ts twoslash file=libs/token/README.md region=check-catches

```

`a4kp-9mza` substitutes `z` for `x`, and `a4pk-9mxa` swaps `k` and `p`, so both fail. `b0zg-7kqb` and `bz0g-7kqb` differ by a swap of `0` and `z`, and both pass.

### The Blind Spot

The `@evanion/token` check character misses one adjacent swap: the dictionary's first and last characters, `0` and `z` by default, at dictionary indexes 0 and 31. Luhn doubles the dictionary index of every second character. A doubled index of 32 or more is two digits in base 32, and Luhn adds the two: 31 doubles to 62, which is 1 and 30 in base 32, so it counts as 31.

Over an even dictionary size every index doubles to a different value, which is why Luhn needs an even size. Doubled that way, 0 stays 0 and 31 stays 31, so swapping the two leaves the total unchanged. Two mistakes in one code can also cancel each other out and pass.

## A Longer Code for Gift Cards

A gift card is issued in larger numbers than a pickup code, so it needs a longer `@evanion/token` code than the default eight characters. [Code shape](../shape) sets `length`, `chunkSize` and `separator` on `createToken`.
