# Generating and validating

To issue a pickup code as `ORD-a4kp-9mxa` and redeem it regardless of how a customer types it, you combine `generate` with a custom prefix and use `validate` to screen the input.

## Minting a Pickup Code with a Prefix

You can make your `@evanion/token` codes more recognizable by adding a prefix like `ORD-`. This helps both users and staff identify the code's purpose at a glance.

When you pass a `prefix` to `generate`, it returns the code in four fields:

```ts twoslash file=libs/token/README.md region=generate

```

- **`value`**: The full code as printed (`ORD-a4kp-9mxa`), 13 characters in all.
- **`body`**: The seven random characters used as the database key.
- **`check`**: The final check character, the last character of `value`.
- **`prefix`**: The prefix you provided.

## Redeeming a Prefixed Code

The `@evanion/token` `validate` method works on the code's body and check character, and takes no prefix option.

If you pass `ORD-a4kp-9mxa` directly to `validate`, it strips the hyphen like any separator, treats `ORD` as part of the code, and refuses it as `outside-alphabet`, because the default dictionary has no `o`. You must strip the prefix before validating:


In the example above, `validatePickupCode` is a function of your own that handles the stripping. Because the default dictionary excludes the letter `o`, no valid code can start with `ord`. This makes it safe to strip any leading `ord` (case-insensitively, with or without its hyphen) without risk of accidentally removing part of the actual code.

## Understanding Validation Failures

The `@evanion/token` `validate` method returns `valid: true` and the `body` if the code is well-formed, or `valid: false` and a `reason` if it fails.

```ts twoslash file=libs/token/README.md region=validate

```

| `reason`           | Meaning                                                                                   |
| :----------------- | :---------------------------------------------------------------------------------------- |
| `outside-alphabet` | The code contains a character not found in the dictionary, after separators are stripped. |
| `wrong-length`     | The code does not match the required `length`.                                            |
| `check-failed`     | The check character does not match the calculated value for the body.                     |

`validate` checks these conditions in order and reports the first failure. Since it has no side effects and never throws, you can run it on every request before performing a database lookup.

## Flexible User Input

Customers rarely type an `@evanion/token` code exactly as it was printed. They might omit hyphens, use different grouping, or type everything in capitals.

`validate` handles this by automatically stripping the separator and folding the case before performing its checks.

```ts twoslash file=libs/token/README.md region=separators

```

Because every variation of the spelling returns the same `body`, they all resolve to the same record in your database.

## What the Check Character Catches

`@evanion/token` uses the Luhn algorithm to compute the check character. This provides a high degree of confidence in detecting common human errors:

- **Single-Character Substitutions**: Any single character misread or mistyped at any position, including the check character itself, is always caught.
- **Adjacent Swaps**: Almost every swap of two neighboring characters is caught.

```ts twoslash file=libs/token/README.md region=check-catches

```

`a4kp-9mza` substitutes `z` for `x`, and `a4pk-9mxa` swaps `k` and `p`, so both fail. `b0zg-7kqb` and `bz0g-7kqb` differ by a swap of `0` and `z`, and both pass.

### The "Blind Spot"

There is one rare exception: an adjacent swap of the first and last characters of the dictionary (by default, `0` and `z`). Because of the way the Luhn doubling step works, these two characters are mathematically interchangeable in the sum. Two mistakes in one code can also cancel each other out and pass.

While this is a technical limitation of the Luhn algorithm, it is an acceptable trade-off for the speed and simplicity of the check.

## A Longer Code for Gift Cards

Every `@evanion/token` example on this page uses the default shape: eight characters in two chunks. If you need a longer code for something like a gift card, you can customize the shape. [Code shape](../shape) shows how to set `length`, `chunkSize` and `separator`.
