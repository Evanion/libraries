# Generating and validating

To print a pickup code as `ORD-a4kp-9mxa` and redeem it however a customer
types it, pass `prefix` to the `generate` call of `@evanion/token`, and strip
the prefix before `validate`.

## Mint a pickup code with the ORD prefix

Token's `generate` takes an optional `prefix` and returns the code in four
fields:

```ts twoslash file=libs/token/README.md region=generate

```

- `value` is the code as printed: `ORD`, the separator and the nine-character
  code, 13 characters in all.
- `body` is the seven random characters, the key
  [Getting started](../getting-started) stores the order under.
- `check` is the check character, the last character of `value`.
- `prefix` is the prefix you passed.

## Redeem a pickup code read back with its prefix

Token's `validate` takes no `prefix` option. It strips the hyphen after `ORD`
like any separator, then refuses the `o` as `outside-alphabet`, so strip the
prefix before validating:

```ts twoslash file=libs/token/README.md region=prefix

```

`validatePickupCode` is the example's own function, not a token export. It
strips `ord` in any case, with or without the hyphen after it, so
`ORD-a4kp-9mxa`, `ord-a4kp-9mxa` and `ORDa4kp9mxa` all pass. The strip is safe
because the dictionary has no `o`. No code starts with one, so a leading `ord`
is always the prefix. A prefix typed wrong is left in place, and `validate`
refuses the code.

## Reasons validate refuses a pickup code

Token's `validate` returns `valid: true` and the `body`, or `valid: false` and a
`reason`. `b0zg-7kqb` below is another well-formed default code, and its `0`
shows what happens when a reader types `o`:

```ts twoslash file=libs/token/README.md region=validate

```

| `reason`           | Meaning                                                          |
| ------------------ | ---------------------------------------------------------------- |
| `outside-alphabet` | a character not in the dictionary, after separators are stripped |
| `wrong-length`     | the code is not `length` characters long                         |
| `check-failed`     | the last character does not check out against the ones before it |

`validate` checks in the table's order and reports the first failure. It never
throws and has no side effects, so it can run on every request ahead of the
lookup.

The field below calls `validate` on what you type. It opens on `b0zg-7kqb`:
change the last character, type an `o` for the `0`, or drop a character.

## Mistakes a pickup code's check character catches

`@evanion/luhn` computes token's check character with the Luhn algorithm,
extended from ten digits to any dictionary with an even number of characters.
It catches two kinds of mistake:

- Every single-character substitution, at every position, including the check
  character itself.
- Every swap of two adjacent characters, except one pair: the first and last
  entries of the dictionary, `0` and `z` by default.

```ts twoslash file=libs/token/README.md region=check-catches

```

`a4kp-9mza` substitutes `z` for `x`, and `a4pk-9mxa` swaps `k` and `p`. Both
fail. `b0zg-7kqb` and `bz0g-7kqb` differ by a swap of `0` and `z`, and both
pass. Two mistakes in one code can also cancel each other and pass.

The blind spot comes from Luhn's doubling step. Luhn computes the check
character from a code's other characters:

1. It takes each character's index in the dictionary.
2. It doubles every second index. A doubled index that reaches `n`, the
   dictionary's size, counts as the sum of its two digits in base `n`. On a card
   number, where `n` is 10, `8 × 2 = 16` counts as `1 + 6 = 7`.
3. It adds up the results, and picks the check character that brings the sum to
   a multiple of `n`.

Over an even `n` every index doubles to a different value, which is why Luhn
needs an even size. Two indexes double to themselves: `0` doubles to `0`, and
the last index, `n - 1`, doubles back to `n - 1`. At `n = 32`, index 31 doubles
to 62, which is `1` and `30` in base 32 and counts as 31. A swap of two
neighbouring characters at those indexes, such as the default dictionary's `0`
and `z`, leaves the sum unchanged, the way `0` and `9` swap undetected on a card
number.

## A longer code for gift cards

Every token code on this page had the default shape, eight characters in two
chunks. A Baize gift card needs a longer one. [Code shape](../shape) sets
`length`, `chunkSize` and `separator`, and lists the shapes `createToken`
refuses.
