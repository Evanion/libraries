# The alphabet

To mint codes from your own set of characters, pass a `dictionary` string to `createToken`. `createToken` refuses a dictionary that holds `i`, `l`, `o` or `w`, holds an uppercase character, or has a size that does not divide 256, and `@evanion/luhn` adds rules of its own.

## Why Some Characters and Sizes Are Refused

When an `@evanion/token` code is read aloud or typed from a printed receipt, some characters are confused: a `1` for an `l` or an `i`, and a `0` for an `o`. If a dictionary held both `1` and `l`, a customer who typed `l` for a printed `1` would get `check-failed`, which does not say which character is wrong. The default dictionary has no `l`, so a typed `l` fails as `outside-alphabet`: the code holds a character that no code contains.

`generate` picks each character with `byte % n`, where `byte` is a random value from 0 to 255 and `n` is the dictionary size. When `n` does not divide 256, the first `256 % n` characters come up more often than the rest, and the codes are slightly more predictable.

## The Default token Dictionary

By default, `@evanion/token` uses `DEFAULT_DICTIONARY`, which consists of lowercase alphanumerics minus the **confusable characters**, `CONFUSABLE_CHARACTERS`: `i`, `l`, `o`, and `w`.


Why these four?

- `i`, `l`, and `o` are visually similar to `1` and `0`. The digits stay, because a digit is unambiguous on a keypad.
- `w` is phonetically similar to `u` ("double-u"), which leads to transcription errors when codes are dictated over the phone. A fourth character had to go anyway: dropping only three leaves 33, which is odd and does not divide 256.

This leaves exactly 32 characters. This is an ideal number because it is even (required for the Luhn algorithm) and it divides 256 evenly (preventing random bias).

## What `createToken` Checks in a Dictionary

When you provide a custom `dictionary` to `createToken`, `@evanion/token` validates it against several constraints. If any are broken, it throws either an `InvalidAlphabetError` or an `InvalidDictionaryError`, with the `reason` in the table below.

| Constraint         | Enforced by      | `reason`      | Why it matters                                                                                                                                                                    |
| :----------------- | :--------------- | :------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **No Confusables** | `@evanion/token` | `confusable`  | Prevents `1/l/i` and `0/o` and `w/u` confusion.                                                                                                                                   |
| **Lowercase Only** | `@evanion/token` | `unfolded`    | `validate` folds input to lowercase; uppercase in the dictionary could never be reached.                                                                                          |
| **Divides 256**    | `@evanion/token` | `non-uniform` | Ensures every character is equally likely to be drawn.                                                                                                                            |
| **Min Length 2**   | `@evanion/luhn`  | `too-short`   | A 1-character dictionary makes every code valid.                                                                                                                                  |
| **Even Size**      | `@evanion/luhn`  | `odd-length`  | Luhn's [doubling step](../usage) needs an even-sized dictionary.                                                                                                                  |
| **No Repeats**     | `@evanion/luhn`  | `duplicate`   | Each character must have a unique index for the checksum.                                                                                                                         |
| **No Case Pairs**  | `@evanion/luhn`  | `case-pairs`  | Case folding would turn a letter and its uppercase form into one character with two indexes. Luhn checks first, so a dictionary holding `a` and `A` fails here before `unfolded`. |

## Why the Dictionary Size Must Divide 256

The `@evanion/token` `generate` method draws characters using the formula `byte % n`, where the byte is a random value from 0 to 255.

If `n` (the dictionary size) is 32, the division is exact: $256 / 32 = 8$. Every character appears exactly 8 times in the range.

If `n` were 36, $256 / 36 = 7$ with a remainder of $4$. The first four characters in the dictionary would appear 8 times, while the others appear only 7 times. This 14.3% bias makes the codes mathematically non-uniform. Rejection sampling would fix the bias by redrawing any byte that lands in the uneven remainder, which makes generation take a variable time. `@evanion/token` keeps generation constant-time by requiring that `n` divides 256.

Note: To import `InvalidDictionaryError`, add `@evanion/luhn` to your own `package.json` at the exact version that `@evanion/token` lists in its `dependencies`, which `node_modules/@evanion/token/package.json` shows. pnpm, and any package manager that does not hoist a dependency's dependencies, cannot resolve the import otherwise. A copy at another version defines a second `InvalidDictionaryError` class, and `instanceof` against it misses the error token throws.

## Reordering a Dictionary Changes Its Check Characters

The order of an `@evanion/token` dictionary decides which index each character occupies, and therefore every check character it produces. Two dictionaries with the same characters in a different order give different check characters, and a code minted under one can fail `validate` under the other.

Store your dictionary as a constant string, and never sort it.

## Hexadecimal Gift Cards

Hexadecimal (`0123456789abcdef`) is an alternative `@evanion/token` dictionary that passes every rule. It is even, lowercase, free of confusables, and 16 divides 256.

`hexCard.n` is the dictionary size, 16. A hex character carries only 4 bits of entropy (compared to 5 bits for the default 32-character set), so the 16-character `hexCard` carries 60 bits where the default dictionary's 16 characters carry 75. A hex code needs more characters for the same bits. [Entropy and collisions](../entropy) turns bits into the number of codes you can issue before two match.
