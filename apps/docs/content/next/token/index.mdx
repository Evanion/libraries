# @evanion/token

At Baize, a board game shop, the counter cannot tell a misheard pickup code
from one never issued: both get "no such order". `@evanion/token` mints codes
without misread characters, and its `validate` refuses a misheard one before
the lookup.

## How a misheard pickup code is refused

A default `@evanion/token` code is seven random characters followed by one check
character, which is computed from the seven. `a4kp-9mxa` below is a Baize
pickup code:


`createToken()` returns a token instance, an object fixed to one shape of code
(its length and how its characters are grouped), carrying `generate` and
`validate`. The last character of `a4kp-9mxa`, `a`, is its check character.
`a4kp-9mx8` is the same code with that `a` heard as `8`, and `validate` refuses
it with `reason: 'check-failed'` before any order table is read. `body` is the
code with its hyphen and its check character removed, which is the string the
shop stores.

## The token vocabulary

These seven words name the parts of an `@evanion/token` code.

- A **code** is the string a person reads, such as `a4kp-9mxa`.
- The **body** is the code's random characters, `a4kp9mx`, without separators
  or check character. The shop stores and indexes on it.
- The **check character** is the last character of a code. `@evanion/luhn`, a
  dependency that installs with token, computes it from the body with the Luhn
  algorithm, the check-digit scheme on a credit card number. It catches the
  mistakes the dictionary cannot remove, such as `a` heard as `8`.
- The **dictionary** is the string of characters a code draws from, in order.
  The default holds 32 characters and leaves out `i`, `l`, `o` and `w`, which
  people misread or mishear. The token API also calls it the alphabet, in
  `InvalidAlphabetError` and the reason `outside-alphabet`.
- A **chunk** is a group of characters, four by default.
- A **separator** sits between two chunks, a hyphen by default. It is there for
  the reader, and `validate` removes it before checking.
- A **prefix**, such as `ORD`, is written ahead of a code, and the check
  character does not cover it.

## What token can do

Each task below maps to one call or option of `@evanion/token`.

| You want to                                        | What token gives you                                        |
| -------------------------------------------------- | ----------------------------------------------------------- |
| mint a code a person reads aloud                   | `generate()`, which draws from `crypto.getRandomValues`     |
| refuse a mistyped code before the lookup           | `validate()`, which returns a `reason` and never throws     |
| accept a code typed without hyphens or in capitals | `validate`, which strips separators and folds case first    |
| mark a code as an order's                          | `generate({ prefix: 'ORD' })`                               |
| set the length, the chunk size or the separator    | `createToken({ length, chunkSize, separator })`             |
| draw from your own characters                      | `createToken({ dictionary })`, which checks the dictionary  |
| size a code for the number you will issue          | `entropyBits`, the instance's count of random bits per code |

## What token does not do

`@evanion/token` leaves five jobs to your code or to another package.

- It does not keep codes unique. `generate` never checks for collisions and
  never retries, so uniqueness is a unique index on your table.
- It does not say a code exists. `valid: true` means well formed, and one in 32
  random 8-character strings over the default dictionary passes the check.
- It does not make a credential. A default code's seven random characters carry
  5 bits each, 35 in all, which an attacker can enumerate.
- It does not check the prefix. `ORD-a4kp-9mxa` carries a check character over
  `a4kp9mx` only, and your code cuts `ORD-` off before it calls `validate`.
- It does not add a check character to an identifier you already have.
  `@evanion/luhn` computes one over any string.
