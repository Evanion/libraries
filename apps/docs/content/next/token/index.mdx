# @evanion/token

**Built-in error detection for human-readable codes.** `@evanion/token` mints codes with a check character, so its `validate` function can refuse a misheard code before your application ever touches the database.

## The Problem: The "Invisible Typo"

When a customer reads a Baize pickup code over the phone or types it into a form, a single misheard character can turn a valid code into a "no such order" error, and a system without `@evanion/token` cannot tell the two apart. If a user types `a4kp-9mx8` instead of `a4kp-9mxa`, the system performs a database lookup, finds nothing, and returns a generic `404 Not Found`.

This creates a poor user experience:

- **User Frustration**: The user knows they typed _something_ and doesn't know where the error is.
- **Staff Blindness**: Support staff cannot tell the difference between a malicious probe and a simple typo.
- **Database Waste**: Every mistyped code triggers an unnecessary database query.

## The Solution: Check Characters

`@evanion/token` implements a check-character system (similar to how credit card numbers work). A token consists of a random body followed by a single **check character** computed from that body: in the code `a4kp-9mxa`, the final `a` is the check character.

`createToken()` returns a token instance, an object fixed to one shape of code, carrying `generate` and `validate`:

When you call `validate`, the library recalculates the check character from the body. If a customer reads `a4kp-9mx8` (where the `a` was misheard as `8`), `validate` immediately returns `reason: 'check-failed'`.

Your system can now refuse the code instantly, distinguishing a typo from a non-existent order without a single database call.

## The Token Vocabulary

These terms name the parts of an `@evanion/token` code, and every later page uses them:

- **Code**: The full string the user sees, such as `a4kp-9mxa`.
- **Body**: The random characters excluding separators and the check character, such as `a4kp9mx`. This is the part you store in your database.
- **Check Character**: The final character used for error detection, computed by `@evanion/luhn` (a dependency that installs with token) using the Luhn algorithm.
- **Dictionary**: The set of characters used to generate the code. The default dictionary excludes confusing characters like `i`, `l`, `o`, and `w` to prevent misreads. The API also calls it the alphabet, in `InvalidAlphabetError` and the reason `outside-alphabet`.
- **Chunk**: A group of characters (four by default) used to make codes easier to read.
- **Separator**: The character between chunks (a hyphen by default). `validate` removes it before checking.
- **Prefix**: An optional identifier, such as `ORD`, added to the front of a code for categorization.

## Core Capabilities

Each task below maps to one call or option of `@evanion/token`.

| You want to...                            | Use this tool                                                              |
| :---------------------------------------- | :------------------------------------------------------------------------- |
| Mint a human-readable code                | `generate()`, using cryptographically strong random values                 |
| Refuse a mistyped code instantly          | `validate()`, which returns a specific reason for failure and never throws |
| Support flexible user input               | `validate()`, which strips separators and folds case before checking       |
| Categorize codes (e.g., "ORD-")           | `generate({ prefix: 'ORD' })`                                              |
| Customize length or chunks                | `createToken({ length, chunkSize, separator })`                            |
| Use a custom character set                | `createToken({ dictionary })`, which checks the dictionary                 |
| Size a code for the volume you will issue | `entropyBits`, the random bits in one code                                 |

## Important Constraints

`@evanion/token` is an error-detection library. Five jobs stay with your code or another package:

- **Uniqueness**: `generate` does not check your database and never retries. Use a `UNIQUE` index on your database column to ensure uniqueness.
- **Existence**: A `valid: true` result only means the code is _well-formed_. It does not mean the code was actually issued: one in 32 random 8-character strings over the default dictionary passes the check.
- **Security**: These codes are for convenience (like pickup codes), not high-security credentials. A default code carries 35 random bits, which an attacker can enumerate.
- **Prefixes**: The check character only covers the body. You must strip the prefix (e.g., `ORD-`) manually before calling `validate`.
- **Retrofitting**: It cannot add check characters to existing IDs. For that, use the `@evanion/luhn` package directly.

## Install and Issue Your First Code

`@evanion/token` refuses a misheard code by its check character, and leaves the question of whether a code was issued to your database. [Getting started](./getting-started) installs the package and implements a pickup code flow, from checkout to the counter.
