By the end of this page a script hands `validateItems` a Baize listing page as
the content management system (CMS) saved it, prints the one item no renderer
can draw, and exits with status 1.

## Before you install the widget core

- Node 20 or newer.
- An ECMAScript module (ESM) file. `check.mts` below is one in any project,
  because Node and `tsx` load a `.mts` file as ESM. A CommonJS file that calls
  `require('@evanion/widget')` needs Node 20.19, 22.12 or newer, and an older
  `require()` fails with `ERR_REQUIRE_ESM`.
- `tsx`, which runs a TypeScript file with no build step. `npx tsx` fetches it
  on first use.

The package has no dependencies. If your project already depends on
`@evanion/react-widget` or `@evanion/astro-widget`, skip the install and import
`validateItems` from that renderer. Each renderer pins `@evanion/widget` exactly
and re-exports every name this page uses.

## Install the widget core

Pick the line for your package manager.

```bash
npm install @evanion/widget
```

```bash
yarn add @evanion/widget
```

```bash
pnpm add @evanion/widget
```

## Check a saved page with validateItems

`validateItems` from `@evanion/widget` types its first argument `unknown`, so it
takes a payload straight from `JSON.parse` with no annotation to trust. In a
file named `check.mts`:

1. Parse the page the CMS saved. Here the text is inline, and in your project
   it is the body the CMS posts to a webhook or a file it exports.
2. List the [known types](../#the-widget-vocabulary), the types your renderer
   has a component for.
3. Turn each problem `validateItems` returns into one line a log or a CMS editor
   reads.
4. Print each line, and set `process.exitCode` to 1 when there is one.
   `@evanion/widget` leaves the exit status to your script.

```ts twoslash file=libs/widget/README.md region=gate

```

`report` holds one line. The shelf `tonight` names the type `featured-shelf`,
which is not in `known`, so a renderer would skip the shelf, and the page would
lose it and its heading "On the table tonight". `process.exitCode` is 1, so the
run fails.

## Run the widget check from a terminal

`check.mts`, the script above that checks a saved page with `@evanion/widget`,
sets `process.exitCode` to 1 when it prints a problem. Run it with `tsx`:

```bash
npx tsx check.mts; echo "exit $?"
```

The terminal prints `tonight (featured-shelf): unknown widget type`, then
`exit 1`. Change `featured-shelf` in `saved` back to `shelf` and run it again:
the terminal prints only `exit 0`.

The same few lines gate a payload wherever one enters your system:

- in the webhook handler your CMS posts a save to
- in a continuous integration (CI) job over the payloads committed to the
  repository
- in the build script, before it writes the pages
- in a test over the fixtures your pages render

## Every problem one widget check reports

`check.mts` now fails on a type no renderer draws, which is one of nine faults
`@evanion/widget` knows. [What it reports](../problems) runs `validateItems`
over a payload with three faults at once, one of them nested, and lists every
message it returns.
