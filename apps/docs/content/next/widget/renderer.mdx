# Write your own widget renderer

A renderer for a framework with no published package passes
`ERROR_MESSAGES.UNKNOWN_WIDGET(type, id)` to `warnOnce` for each item it skips,
so its warnings match the published renderers'. React and Astro projects need
neither.

## The warning a widget renderer prints

A renderer that meets an item whose `type` it has no component for skips the
item and warns. Both `@evanion/react-widget` and `@evanion/astro-widget` take
that warning from `ERROR_MESSAGES` in `@evanion/widget`, so the same item gets
the same line from either one:

```ts twoslash file=libs/widget/README.md region=warning

```

`ERROR_MESSAGES` is the text a renderer prints to the console while it draws.
[`VALIDATION_MESSAGES`](../problems#the-messages-validateitems-returns) is the
text `validateItems` returns in a problem, before anything is drawn. Search
`ERROR_MESSAGES` for a line your console printed, and `VALIDATION_MESSAGES` for
a line your check printed.

`warnOnce` prints a message the first time it meets it and never again in that
process, and it prints nothing when `NODE_ENV` is `production`. A renderer warns
from render, so without `warnOnce` one item whose type the registry lacks would
warn on every re-render.

## Draw widget items and warn once

The renderer below draws `@evanion/widget` items as lines of text, looks each
`type` up in a registry, and passes the warning for a type it cannot draw to
`warnOnce`. It imports `warnOnce` and `resetWarnings` from `@evanion/widget`,
because neither published renderer re-exports them:

- `Listing` is `AnyWidgetItem<string, { title?: string }>`: an item whose
  `type` is any string and whose `props` may carry a `title`.
- `WidgetRegistry<T>` maps each type to a `T`, here a function from props to a
  line of text.
- `Object.prototype.hasOwnProperty` is the own-key test
  [`validateItems` applies](../problems#check-against-the-registry-a-renderer-draws-from).
  `item.type in registry` or `registry[item.type]` alone finds what every
  object inherits: a function for `constructor` and `toString`, and
  `Object.prototype` itself for `__proto__`.
- `resetWarnings` clears the set of messages `warnOnce` has printed. A
  renderer's tests call it before each case, so one case's warning cannot
  silence the next. The example calls it once, before its first render.

`production` neither call prints, and only a `validateItems` call reports the
missing listing.

## What else a widget renderer handles

A renderer built on `@evanion/widget` handles four more things:

- Children. Draw them inside the parent, as `@evanion/react-widget` does, or
  hand them to the parent's component as data, as `@evanion/astro-widget` does.
  [Order and nesting](../layout#how-each-renderer-draws-children-and-the-wrapper)
  compares the two.
- `meta`. Hand it to the [wrapper](../#how-a-widget-item-array-describes-a-page)
  the application supplies, never to the component's `props`.
- The other warnings, each passed to `warnOnce`: `MALFORMED_ITEMS` when the
  items handed to the renderer are not an array, `MALFORMED_ITEM(id, type)` for
  an entry that is not an object or has no string `type`, and
  `MALFORMED_CHILDREN(id)` for `children` that is present and not an array.
  `ERROR_MESSAGES.UNKNOWN` stands in for an `id` or `type` a message lacks.
- `validateItems`. Neither published renderer calls it. A renderer skips and
  warns, and the check runs where the payload enters, as
  [Getting started](../getting-started) sets it up.
