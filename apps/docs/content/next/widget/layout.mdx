# Order and nesting

`@evanion/react-widget` draws widget items in array order with each item's `children` inside it; in `@evanion/astro-widget` each parent draws its own `children`. Reorder the items in your content management system (CMS), and the page follows on its next render.

## Nesting with `children`

`@evanion/widget` models the page as a tree. An item holds its nested items in its `children` property, so a parent and everything nested in it move as one entry.

Consider the dashboard Baize's staff read each week, written as seven items in four types:

- `columns` lays its children side by side in one row.
- `metric` is one figure with a label and a change, such as `+6`.
- `tables` and `reprints` are titled boards.

Because the children are nested _inside_ the parent item, moving the `week` item to the bottom of the array moves all three metrics with it, preserving the group's integrity.

## Placement with `meta`

In an `@evanion/widget` item, `props` contains the widget's data and `meta` contains **placement data**. A renderer hands `meta` to the [item chrome](../#item-fields), which uses it to determine how the widget should be positioned (e.g., in a grid).

In the dashboard example, the `tables` widget has `meta: { span: 2 }`. The demo's item chrome below reads this and assigns the widget two grid columns; item chrome of yours decides what `span` means. If you move the `tables` widget to a different position in the array, its `span: 2` metadata moves with it, ensuring the layout remains consistent regardless of where the widget sits on the page.

## Renderer Differences: React vs. Astro

While `@evanion/react-widget` and `@evanion/astro-widget` both use the same core widget items and follow the same order, they handle the rendering process differently:

### 1. Handling Children

- **`@evanion/react-widget`**: Draws each child first and passes the resulting React elements as the `children` prop to the parent component.
- **`@evanion/astro-widget`**: Passes the raw child items to the parent component as a `children` prop. The parent is then responsible for rendering its own `<Widgets />` component over those items.

### 2. Item Chrome

- **React**: Uses a default item chrome (a `div`) that drops `meta` unless you provide a custom `chrome.item`.
- **Astro**: Draws no item chrome until you pass one as `chrome.item`. The component you pass must render a `<slot />`, or the widget inside will not appear on the page.

## Move a Widget Item and Watch the Page Follow

`@evanion/react-widget` draws the dashboard below from the seven items above, and draws it again after every move. The items are printed under the page, and each line that opens an item has two move controls beside it.

- Move `counter` above `week`. The two rows swap, and each row keeps its own items, because an item's `children` move with it.
- Move the board `tables` past the board `reprints`. The wide board changes sides, because `meta` belongs to the item it sits on, so the width moves with `tables`.

You have now moved `@evanion/widget` items and watched `@evanion/react-widget` redraw the page, with each item's `children` and `meta` moving with it.
