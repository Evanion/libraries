# @evanion/widget

When a content management system (CMS) saves a page, it typically stores the content as a list of "items." Each item specifies a `type` (which component should be used) and `props` (the data for that component). 

The danger is that if a CMS saves an item with a type that your frontend doesn't recognize, the renderer will simply skip it. In production, this often happens silently, leaving a mysterious gap in your page where a widget should have been.

`@evanion/widget` is the core engine that identifies these "missing" widgets before they ever hit the browser, allowing you to catch content errors during the save process or in your CI pipeline.

## How a widget item array describes a page

In this system, a **widget** is a single block of a page—such as a game listing or a featured shelf. A **widget item** is the data representation of that block.

A **renderer** (like `@evanion/react-widget` or `@evanion/astro-widget`) is the package that actually turns these items into UI components.

### The anatomy of a widget item

Every item consists of a few key fields:
- `id`: A unique string used for React keys and DOM attributes.
- `type`: The name of the component used to render the widget.
- `props`: The actual data passed to the component.
- `meta`: Optional placement data (like `span: 2` for a grid). This is handled by the **wrapper** (the element that surrounds each widget) rather than the widget itself.
- `children`: An optional array of nested items, allowing you to create complex layouts like shelves containing listings.

## The widget vocabulary

To help you build your renderer, we use the following terms:

- **Known Types**: The list of widget types that your renderer actually has components for.
- **Registry**: A map that links each known type to its corresponding component.
- **Problem**: An error report generated by `validateItems`, containing the index and type of the faulty item.

## What the widget core can do

`@evanion/widget` provides the logic for validating your CMS payloads:

| You want to                                        | What the widget core gives you                                                                                                         |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| describe a page as JSON data                      | `AnyWidgetItem`, a type for items that can be written by a CMS                                                                    |
| define which types are supported                   | a registry from `defineWidgets`, or a simple list of type names                                                                        |
| reject a bad payload before it renders             | `validateItems(items, known)`, which reports all problems without throwing                                                          |
| enforce required fields in the CMS                | a `required` map for `validateItems` to ensure essential props are present                                                          |
| run checks without a frontend framework           | `validateItems` is framework-agnostic and has no dependencies                                                                       |
| standardize error messages                        | `ERROR_MESSAGES` and `warnOnce` to keep warnings consistent across your app                                                            |

## What the widget core does not do

It is important to distinguish the core from the renderer:

- **No UI Rendering**: The core does not draw anything on the screen; that is the job of the renderer.
- **No Compile-time Prop Checks**: The core only knows if a `type` exists. It cannot check if the `props` match a component's TypeScript definition (though `@evanion/react-widget` can).
- **No Automatic Execution**: The library doesn't run `validateItems` automatically; you must call it in your own code (e.g., in a webhook or build script).
- **No Data Fetching**: The core only validates the data it is given; it doesn't know where the data comes from.

## Set up the widget core

The core's model is simple: an array of items, a list of supported types, and a validation call. [Getting started](./getting-started) shows you how to install the package and use `validateItems` as a quality gate for your saved pages.
