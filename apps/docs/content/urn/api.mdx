# API reference

`@evanion/urn` exports one class, two functions, two errors and four types, one
heading each below. Node 20 or newer, ESM only.

## `URN`

<!-- reference @evanion/urn#URN example=basic-usage -->

`URN` is never instantiated. A subclass overrides the three static properties
below, and every static method reads them off `this`.

| Static              | Default                      | What it is                                                                     |
| ------------------- | ---------------------------- | ------------------------------------------------------------------------------ |
| `urn`               | `'urn'`                      | the scheme this class writes and reads as its own                              |
| `nid`               | `'nid'`                      | the namespace identifier this class writes and reads as its own                |
| `separator`         | `':'`                        | what the three parts are joined by and split on                                |
| `schemeGrammar`     | RFC 3986 `scheme`            | a letter, then letters, digits, `+`, `-` and `.`                               |
| `nidGrammar`        | RFC 8141 `NID`               | letters, digits and interior `-`, 2 to 32 characters, on write                 |
| `nssGrammar`        | RFC 8141 `NSS`               | `pchar` and percent-triplets, plus `/` after the first character               |
| `rComponentGrammar` | `pchar *(pchar / "/" / "?")` | the NSS set plus `?` after the first character                                 |
| `qComponentGrammar` | `pchar *(pchar / "/" / "?")` | the same production as the r-component                                         |
| `fComponentGrammar` | RFC 3986 `fragment`          | the NSS set plus `?`, no first-character rule, and the only one to accept `''` |

`'nid'` is a placeholder, and IANA's URN namespace registry holds the registered
namespaces. Under a separator other than `:`, `schemeGrammar` and `nidGrammar`
become a character class that excludes the separator, with no length bounds.
`parse` accepts a one-character NID, which RFC 2141 permitted and `nidGrammar`
refuses:


Every static reads `this`, so a static cannot be destructured or passed as a
bare callback:

```ts twoslash file=libs/urn/README.md region=unbound

```

### `URN.stringify`

`stringify(parts)` and `stringify(nss, nid?, urn?)` write a URN string. `nid`
and `urn` default to the calling class's own statics. Both forms throw
`InvalidError` when a part is empty or breaks its grammar:

```ts twoslash file=libs/urn/README.md region=stringify-forms

```

The object form's keys match what `parse` returns, and only the object form
writes the r-, q- and f-components. The positional arguments run in the reverse
order of `parse`'s return, so `stringify(...Object.values(parse(x)))` puts the
scheme where the NSS belongs. `stringify` writes the NSS verbatim, so it neither
deduplicates nor is idempotent:

```ts twoslash file=libs/urn/README.md region=round-trip

```

### `URN.parse`

`parse(urnString)` returns a `ParsedURN`, with every part in the case it was
written in and every percent-triplet intact. A scheme or NID that differs from
the class's own, compared case-folded, stays in the `nss`:

```ts twoslash file=libs/urn/README.md region=parse

```

`parse` throws `ValidationError` for a string that is not a URN, and
`InvalidError` for a part that breaks its grammar.

### `URN.isValidFormat`

`isValidFormat(urnString)` returns `true` when `parse` would succeed. It calls
`parse`, so the two cannot disagree, and it never throws:

```ts twoslash file=libs/urn/README.md region=screening

```

### `URN.extractId`

`extractId(urnString)` returns everything after the scheme and the NID, with
any r-, q- or f-component dropped. On a foreign namespace it differs from
`parse(urnString).nss`, which keeps the NID:

```ts twoslash file=libs/urn/README.md region=extract-id

```

`extractId` throws `ValidationError` on malformed input.

### `URN.sameNamespace`

`sameNamespace(a, b)` returns `true` when both URNs have the same scheme and
the same NID, compared case-folded. Malformed input returns `false`:

```ts twoslash file=libs/urn/README.md region=same-namespace

```

### `URN.belongsToNamespace`

`belongsToNamespace(urnString, nid, urn?)` returns `true` when the URN is in the
named namespace. `urn` defaults to the calling class's own scheme. Malformed
input returns `false`:

```ts twoslash file=libs/urn/README.md region=belongs-to-namespace

```

### `URN.equals`

`equals(a, b)` is RFC 8141 §3.1 equivalence. The scheme and the NID fold case.
The NSS compares character for character, except that the hex digits of a
percent-triplet fold to uppercase. A percent-encoded octet is never decoded, and
the r-, q- and f-components are ignored. Malformed input returns `false`:

```ts twoslash file=libs/urn/README.md region=equality

```

## `encodeNss`

<!-- reference @evanion/urn#encodeNss example=nss-encoding -->

`encodeNss(raw)` encodes everything outside RFC 3986's `unreserved` set
(`A-Z a-z 0-9 - . _ ~`) as UTF-8 percent-triplets with uppercase hex, `:`
included, so the result is valid in any position of an NSS.

## `decodeNss`

<!-- reference @evanion/urn#decodeNss example=decode-nss -->

`decodeNss(encoded)` reverses `encodeNss`. It throws `ValidationError` on a `%`
that is not followed by two hex digits, and on triplets that do not decode as
UTF-8.

## `ValidationError`

<!-- reference @evanion/urn#ValidationError example=error-handling -->

`ValidationError` is the base class of every error `@evanion/urn` throws.
`parse`, `extractId` and `decodeNss` throw it directly for input that is not a
URN or not a valid encoding, so catching it covers `InvalidError` too.

## `InvalidError`

<!-- reference @evanion/urn#InvalidError example=invalid-error -->

`InvalidError` extends `ValidationError`, and `stringify` and `parse` throw it
for one part that is empty or breaks its grammar.

| Property      | What it holds                                                                                           |
| ------------- | ------------------------------------------------------------------------------------------------------- |
| `property`    | the part: `'URN'`, `'NID'`, `'NSS'`, `'R-COMPONENT'`, `'Q-COMPONENT'`, `'F-COMPONENT'` or `'COMPONENT'` |
| `value`       | the value of that part                                                                                  |
| `invalidChar` | the first character outside the part's set, when one is at fault                                        |
| `reason`      | the structural rule broken when every character is allowed, such as a length bound                      |

`'COMPONENT'` is the property when a subclass whose separator contains `?` or
`#` is asked to write a component.

## `ParsedURN`

<!-- reference @evanion/urn#ParsedURN example=parse -->

`ParsedURN` is what `parse` returns: `urn`, `nid` and `nss`, plus whichever
components the URN carries. The parts are plain `string`, because `parse` reads
a runtime string and cannot know their literal types.

## `URNParts`

<!-- reference @evanion/urn#URNParts example=parsed-types -->

`URNParts` is what the object form of `stringify` takes. Only `nss` is
required, and `urn` and `nid` fall back to the class's own. A `ParsedURN` is
assignable to it.

## `URNComponents`

<!-- reference @evanion/urn#URNComponents example=components-type -->

`URNComponents` holds `rComponent`, `qComponent` and `fComponent`, each
optional. A key is absent when the URN carries no such component, and
`fComponent` may be `''`. [r-, q- and f-components](/urn/components) covers the
syntax.

## `IFullURN`

<!-- reference @evanion/urn#IFullURN example=full-urn-type -->

`IFullURN<URN, NID, NSS>` is the template literal type
`` `${URN}:${NID}:${NSS}` ``. It assumes the default `:` separator, so it cannot
describe a subclass with another one, and `stringify` returns plain `string`
for the same reason.
