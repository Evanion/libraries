# Examples

A shop's services mostly read URNs that another service wrote. `parse`,
`isValidFormat` and `equals` do the reading, and `stringify` with `encodeNss`
does the writing.

## One URN class per namespace

The shop names games and orders, so it has two namespace classes: `GameURN`,
from Getting started, and an `OrderURN` beside it. `stringify` on either class
needs no NID. `belongsToNamespace` still takes the NID as its second argument,
and picks one kind out of a mixed list:

```

`belongsToNamespace` returns `false` for `'hive'`, which is not a URN, so a
filter over untrusted input needs no `try` block.

Each class strips only its own NID on `parse`, compared without regard to case,
so `URN:GAME:azul` is in `GameURN`'s namespace. A foreign NID stays at the front
of the `nss`, a foreign scheme keeps the whole identifier, and every part comes
back in the case it was written in:

```

## Mint a batch of game URNs

`stringify` throws an `InvalidError` on a part that breaks its grammar. A job
minting URNs for a batch of slugs catches per slug, so one bad slug skips and
the rest are minted:

```ts twoslash file=libs/urn/README.md region=batch-mint

```

The NSS grammar is RFC 3986's `pchar`: letters, digits, `-._~!$&'()*+,;=:@` and
percent-triplets such as `%20`, with `/` allowed after the first character. A space is outside
it. The NID is stricter: letters, digits and interior hyphens, 2 to 32
characters.

## Put a game title into a URN

A title a person typed carries spaces and punctuation. `encodeNss` leaves
letters, digits and `-._~` alone and percent-encodes every other character, and
`decodeNss` reverses it. `stringify` and `parse` do neither:

```ts twoslash file=libs/urn/README.md region=nss-encoding

```

`encodeNss` also encodes the `:`, which the NSS grammar allows unencoded. Two
services that both encode a title write the same NSS, and `equals` treats `%3A`
and `:` as different characters.

## Carry a URN in a URL path

`encodeURIComponent` makes a whole URN safe as one path segment, where `:` and
`%` mean something to a router. `encodeNss` makes a string safe as an NSS. A URN
built from a title needs both, NSS first:

```ts twoslash file=libs/urn/README.md region=url-segment

```

The `%3A` inside the NSS becomes `%253A` in the path, and one
`decodeURIComponent` turns it back. A second decode would turn `%3A` into `:`
and `%20` into a space, and `parse` throws on the space.

## Compare URNs from two sources

Two services can write the same URN differently. RFC 8141 §3.1 folds the case of
the scheme, of the NID and of a percent-triplet's hex digits, and nothing else:

```ts twoslash file=libs/urn/README.md region=equality

```

The third call is where decoding before comparing goes wrong, because `equals`
never decodes `%3A`. The fourth is where lowercasing goes wrong, because the
NSS keeps its case. Call `equals` wherever URNs arrive from more than one
producer.

## A URN key with a custom separator

A separator other than `:` takes the class outside RFC 8141, which suits a key
that has to read as a dotted path. The scheme and the NID are then checked
against a character class that excludes the separator. `schemeGrammar` and
`nidGrammar` hold the pattern each of the two must match:

```ts twoslash file=libs/urn/README.md region=custom-separator

```

`GameKey` refuses the scheme `baize.shop`, which `URN` accepts, because the `.`
would be read as a separator.
