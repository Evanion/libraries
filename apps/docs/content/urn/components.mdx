# r-, q- and f-components

`parse` splits the r-, q- and f-components off a URN into fields of their own,
and the object form of `stringify` writes them back.

## The three URN components

RFC 8141 §2.3 allows three optional components after the NSS. The identifier is
`scheme:NID:NSS`, and a component addresses something about resolving or using
the resource that identifier names.

| Component | Introducer | RFC 8141 | Carries                                   | In the shop                         |
| --------- | ---------- | -------- | ----------------------------------------- | ----------------------------------- |
| r         | `?+`       | §2.3.1   | parameters for the resolution service     | `?+lang=en`, the listing's language |
| q         | `?=`       | §2.3.2   | parameters for the named resource         | `?=edition=2018`, one edition       |
| f         | `#`        | §2.3.3   | a secondary resource within the named one | `#setup`, one section of the rules  |

## Write URN components with stringify

Only the object form of `stringify` can express a component. The wire order is
always r, then q, then f, whatever order the keys were written in:

```ts twoslash file=libs/urn/README.md region=components-write

```

`GameURN.stringify(GameURN.parse(written))` returns `written`, components
included, for a URN in the class's own namespace. An empty `fComponent` writes a
bare `#`.

## How parse finds each URN component

`pchar`, the character set of the NSS, contains neither `?` nor `#`, so neither
delimiter can occur inside the identifier. `parse` takes the components off in
the order the grammar fixes:

1. The f-component comes off first, at the first `#`. A `#` ends the r- and
   q-components, and both of those may contain a bare `?`.
2. The first `?` of what is left introduces the r-component when followed by
   `+`, and the q-component when followed by `=`. A bare `?` throws a
   `ValidationError`.
3. An r-component runs to the first following `?=`, which starts the
   q-component.

## URN component grammars

The r- and q-components take the NSS set plus `?` after the first character. The
f-component is RFC 3986's `fragment`: the same set, with no first-character rule
and no minimum length, so `urn:game:azul#` parses to `fComponent: ''`:

```ts twoslash file=libs/urn/README.md region=component-grammars

```

`parse` decodes nothing. A component comes back in its wire form, without its
introducing delimiter.

## Custom separators switch URN components off

A subclass whose `separator` contains `?` or `#` cannot tell a separator from a
component delimiter. On such a class `parse` keeps the whole tail in the NSS,
and `stringify` throws an `InvalidError` with `property: 'COMPONENT'` for any
component. Every other separator parses components normally.
