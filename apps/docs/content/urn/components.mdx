# r-, q- and f-components

`parse` splits the r-, q- and f-components off a URN into fields of their own,
and `stringify`, given the parts as an object, writes them back.

## The three URN components

A service that needs one edition of a game, or one section of its rules, puts
it in a component after the NSS. `equals` and `extractId` then still see the
same game. RFC 8141 §2.3 allows three components, each named by its introducer:

| Component | Introducer | RFC 8141 | Carries                                   | In the shop                         |
| --------- | ---------- | -------- | ----------------------------------------- | ----------------------------------- |
| r         | `?+`       | §2.3.1   | parameters for the service resolving it   | `?+lang=en`, the listing's language |
| q         | `?=`       | §2.3.2   | parameters for the named resource         | `?=edition=2018`, one edition       |
| f         | `#`        | §2.3.3   | a secondary resource within the named one | `#setup`, one section of the rules  |

## Write URN components with stringify

`stringify` writes a component only when it is given the parts as an object,
`{ nss, urn?, nid?, rComponent?, qComponent?, fComponent? }`. The introducers
always go in the order r, then q, then f, whatever order the keys were written
in, and an empty `fComponent` writes a bare `#`:

`GameURN.stringify(GameURN.parse(written))` returns `written`, components

## How parse finds each URN component

No part of the identifier may contain `?` or `#`, so the first of either in a
URN starts a component. `parse` takes the components off in the order RFC 8141
fixes:

1. The f-component comes off first, at the first `#`. A `#` ends the r- and
   q-components, and both of those may contain a bare `?`.
2. The first `?` of what is left introduces the r-component when followed by
   `+`, and the q-component when followed by `=`. A bare `?` throws a
   `ValidationError`.
3. An r-component runs to the first following `?=`, which starts the
   q-component.

## URN component grammars

The r- and q-components allow the characters the NSS allows, plus `?` anywhere
but the first character. The f-component allows the same set with no
first-character rule and no minimum length, so `urn:game:azul#` parses to
`fComponent: ''`. `URN.rComponentGrammar`, `URN.qComponentGrammar` and
`URN.fComponentGrammar` hold the three patterns:

## Custom separators switch URN components off

A subclass that sets `static override readonly separator = '#'`, or any other
separator containing `?` or `#`, cannot tell a separator from a component
introducer. On such a class `parse` throws an `InvalidError` with
`property: 'NSS'` for any URN carrying `?` or `#` after the NID, and `stringify`
throws one with `property: 'COMPONENT'` for any component. Every other separator
parses components normally.
