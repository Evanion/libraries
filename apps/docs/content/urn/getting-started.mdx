# Getting started

By the end of this page a `GameURN` class of your own writes
`urn:game:brass-birmingham` and reads it back into its three parts.

## Before you install urn

- Node 20 or newer.
- An ESM project. A CommonJS project needs Node 20.19, 22.12 or newer, whose
  `require()` loads ES modules. An older `require()` fails with
  `ERR_REQUIRE_ESM`.
- Nothing else. The package has no runtime dependencies and no peer
  dependencies, and it ships its own types.

## Install urn

Pick the line for your package manager.

```bash
npm install @evanion/urn
```

```bash
yarn add @evanion/urn
```

```bash
pnpm add @evanion/urn
```

## Write a namespace class for urn

`GameURN` extends `URN` and overrides one static, `nid`, the namespace
identifier. That is the whole configuration: the scheme defaults to `urn` and
the separator to `:`. Under TypeScript's `noImplicitOverride`, the `override`
keyword is required. Import `URN` from `@evanion/urn`:

```ts twoslash file=libs/urn/README.md region=basic-usage

```

`GameURN.stringify('brass-birmingham')` reads the scheme and the NID off the
class and returns `'urn:game:brass-birmingham'`. `GameURN.parse(id)` splits it
back into `urn`, `nid` and `nss`. In your code, call `stringify` where a game id
leaves a service and `parse` where one arrives.

(Optional) Override `urn` as well to mint in a scheme of your own, such as
`baize:game:azul`. RFC 8141 fixes the scheme at `urn`, so a URN in any other
scheme is outside the RFC.
