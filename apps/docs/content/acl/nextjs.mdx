# Next.js (React Server Components)

A Next.js server component calls `@evanion/acl`'s `access.can` in the Node
process, so its decision enforces what it renders. A Server Action is a second entry point that a caller posts to
directly, and it decides again.

## Adopting shop-api's acl document in a Next.js app

`apps/storefront-rsc` is Baize's Next 16 App Router app, and no file in it
carries `'use client'`. It authors no rules and adopts the document
`apps/shop-api` publishes. `PolicyDocument` is the `{ version, matrix }` body
shop-api answers with, `ShopAccess` is the evaluator typed over this app's
subject and rows, and `adopt` holds the result:

```ts file=apps/storefront-rsc/app/access.ts region=version-keyed-memo

```

`parseMatrix` and never `hydratePolicy`. The document crossed the wire from
another process, so the app adopts it in closed mode, where a key the document
does not carry decides `unknown-action` and refuses. Under `hydratePolicy` the
same key throws mid-render.

`adopt` compares versions with `!==`. A document republished under a new version
replaces the held evaluator on the next page view, and a matching version skips
the validate, deep-clone and deep-freeze.

An app that owns its rules builds them with `policy(…).build()` at module scope,
as [NestJS](/acl/nestjs) and [Express](/acl/express) both show. Put that module
behind `import 'server-only'`, so a client component importing it is a build
error.

## One fetch and one subject for a Next.js render

`fetchJson` is this app's typed client for shop-api, `currentSubject` reads the
visitor's cookie, and `authorize` returns an `Authorized<ShopObjects>` bound to
that subject and one clock instant:

```ts file=apps/storefront-rsc/app/access.ts region=per-request-cache

```

React's `cache` scopes to one request. Three widgets render independently, one
`GET /api/policy` answers all three, and two concurrent page views each get
their own fetch, which a module-level promise does not give them.

```mermaid caption="What one page view does with the fetched document. React's cache scopes the GET to the render, and adopt compares the fetched version with the one this process holds: a matching version re-uses the held evaluator, and a new version is validated, deep-cloned and deep-frozen once before it replaces the held one."

  V["a page view"] --> F["GET /api/policy, once per render"]
  F --> C{"version !== the held one?"}:::accent

```

A rule change reaches this app's gates on the next page view. An app that holds
a document across requests needs a revalidation window, which

## The Next.js render and the Server Action are two boundaries

A route has two trusted entry points, the render and each Server Action, and a
caller reaches either one without the other.

| Where                     | Runtime | Decides?                               |
| ------------------------- | ------- | -------------------------------------- |
| Server component          | trusted | yes, for what it renders               |
| `'use client'` component  | browser | never; it toggles what the user sees   |
| Server Action             | trusted | yes, independently, for what it writes |
| Route handler / API route | trusted | yes, independently                     |

```mermaid caption="Two trusted entry points into one route, reached independently. A page view runs the server component, which decides what it renders and hands a client component a verdict that only toggles; a caller posting to the Server Action skips the render entirely, so the action resolves the subject and decides for itself."
flowchart TD
  V["a page view"] --> SC["server component: can"]:::accent
  SC --> CC["client component<br>toggles, decides nothing"]
  CC --> SA["the Server Action endpoint"]
  CURL["a caller posting directly"] --> SA
  SA --> AD["the action: re-resolve the subject,<br>re-read the row, decide again"]
  AD --> W["the write happens, or it throws"]
```

## `@evanion/react-acl` cannot gate a Next.js server tree

`@evanion/react-acl` ships `'use client'` as the first line of its entry point.
A server component importing `useCan` from it imports a client reference, and
calling that reference during the server render throws. A server tree decides
with `@evanion/acl` directly: `parseMatrix` builds the evaluator and
`access.can` answers in the same process.

## Handing the document to a Next.js client tree

An app with a client tree hands it the document, because `Access` is a set of
closures over a frozen document and does not serialize. `structuredClone` throws
on the functions and `JSON.stringify` drops every method:

```ts twoslash file=libs/acl/README.md region=matrix-round-trip

```

A server component passes `access.matrix`, the subject and a `now` string to a
`'use client'` boundary, which rebuilds the evaluator and mounts
`@evanion/react-acl`'s provider. [Getting started with
react-acl](/react-acl/getting-started) builds that boundary. Resolve `now` on the
server, so the server render and the client's first render agree. A `now` read
from a client payload hands the client every time window in the matrix. A `useCan` that returns `null` hides a button and stops nobody posting
to the action behind it.
