# NestJS

`@evanion/acl` ships no NestJS module. In `apps/shop-api`, Baize's Nest service,
`AclGuard` refuses a request before the row is read wherever the subject alone
decides it, and `GamesService` decides `game.declare` on the title it loaded.

## Baize's acl matrix, built once when the Nest app boots

`apps/shop-api` calls `@evanion/acl` directly, and every fence on this page is a
region of that app, run by its own test suite. `ShopSubject` carries `id`, `roles` and `shop`, and `ShopObjects` maps each of the
four object kinds to its row shape:

```ts file=apps/shop-api/src/acl/shop.policy.ts region=shop-matrix

```

Six permissions, and every one but `inventory.read` carries `visibility`, which
marks what the service publishes. `game.declare` lets an operator set
`availability`, and `game.reprice` adds `price` for a manager. Both read
`object.shop === subject.shop`, so an operator in Gothenburg cannot touch a title
Stockholm lists.

`SHOP_MATRIX` is the document that builder produced. `hydratePolicy` adopts it,
because this process wrote it:

```ts file=apps/shop-api/src/acl/shop.policy.ts region=build-shop-access

```

`hydratePolicy` validates, deep-clones and deep-freezes the document. An unknown
field, or two permissions sharing a key, stops the boot.

## Binding the acl matrix in a global Nest module

`AclModule.forRoot()` returns a `global: true` `DynamicModule` with the matrix as
a `useValue` provider under the token `ACL_ACCESS`, and registers `AclGuard` and
`PolicyController`:

```ts file=apps/shop-api/src/acl/acl.module.ts region=acl-module

```

`APP_GUARD` binds the guard to every route, and the `@Requires` metadata decides
which routes it gates. The token is a package-namespaced string:

```ts twoslash file=apps/shop-api/src/acl/acl.constants.ts region=acl-token

```

A bare `'ACL_ACCESS'` in a global module collides with any other provider of that
name, and nothing reports it. A symbol is identity-based, so two copies of the
package mint two tokens and Nest fails to resolve one of them.

## Resolving the acl subject in a Nest request

`SubjectService` holds the request's subject in an `AsyncLocalStorage`
singleton. `Scope.REQUEST` propagates upward: under it, every provider depending
on the subject, `GamesService` and `InventoryClient` among them, becomes
request-scoped, is rebuilt per request and never receives `onModuleInit`.

```ts file=apps/shop-api/src/acl/subject.service.ts region=subject-service

```

`SubjectMiddleware` fills it. The middleware types its arguments against
`node:http`, so one class works under the Express and the Fastify adapter.
`SHOP_SUBJECT_HEADER` is `X-Shop-Subject`, and `subjectFrom` parses it or falls
back to a shopper who works for no shop:

```ts file=apps/shop-api/src/acl/subject.middleware.ts region=subject-middleware

```

## Two seats, the Nest guard and the service

A Nest write passes two places that can call `can`. The guard runs before the
controller method and holds the subject with no row. The service runs after the
read and holds both.

| Seat           | Holds              | Decides                                                        |
| -------------- | ------------------ | -------------------------------------------------------------- |
| `AclGuard`     | the subject        | every permission whose rules read the subject alone            |
| `GamesService` | the subject, a row | `game.declare` and `game.reprice`, on the title it just loaded |

A permission whose rules read `object.*`, asked with no row, answers
`unevaluable`, which is no refusal. A guard that reads that as a grant lets a
Gothenburg operator edit a Stockholm title, so the row-level decision belongs in
the service.

```mermaid caption="The two seats one write passes through.   G -->|"refused, readsObject true"| C
  C --> S["GamesService loads the title"]

```

## The Nest guard refuses what the subject decides

`@Requires` writes the permission onto the handler under the metadata key
`REQUIRES_PERMISSION`. `RequiredPermission` types `key` against `ShopObjects`, so
a route naming a kind the matrix does not carry fails to compile:

```ts file=apps/shop-api/src/acl/requires.decorator.ts region=requires-decorator

```

```ts file=apps/shop-api/src/acl/acl.guard.ts region=acl-guard

```

`access.readsObject(key, action)` is true when any allow or deny rule of that
permission reads an `object.*` path. `order.create` reads the subject's roles
alone, so the guard refuses a caller who is no customer and `OrdersController`
never runs. `game.declare` reads the title's shop, so the guard passes it on.

`action` stays a string, so the guard does not catch a `@Requires` naming an
action the document lacks. `hydratePolicy` builds an open `Access`, where that
`can` throws `UnknownPermissionError` and Nest renders a 500.

## The Nest service decides on the row

`GamesService.declare` loads the title with `findByUrn`, then decides. The action
comes from the body, because `declare` and `reprice` allow different fields:

```ts file=apps/shop-api/src/games/games.service.ts region=row-decision

```

`decision.action.allowed` is checked first, so a refusal is a
`ForbiddenException` and never the `ActionNotAllowedError` that
`pickAllowedFields` throws on a refused action. A `@Body()` carries whatever the
caller put in it, and the write keeps only the keys the decision marked
`allowed`. A whitelisting `ValidationPipe` answers whether a key is a legal field
of the endpoint, and the decision answers whether this subject may set it on this
row, so keep both.

The service spec runs the app's real matrix. The same Stockholm operator changes
Wingspan and is refused on Gloomhaven:

```ts file=apps/shop-api/src/games/games.service.spec.ts region=declare-on-the-row

```

## Publishing the matrix from a Nest controller

`PolicyController` answers `GET /api/policy` with the reduced document:

```ts file=apps/shop-api/src/acl/policy.controller.ts region=policy-endpoint

```

`serialize(access, 'reduced')` keeps the permissions marked
`visibility: 'public'`, each whole, and drops `inventory.read`. Baize's three
frontends fetch it and evaluate locally, and shop-api decides again on every
request they send.

## Testing the Nest wiring against the real matrix

`games.controller.spec.ts` builds a testing module over the real matrix and stubs
only the subject, with `useValue` on the class token:

```ts file=apps/shop-api/src/games/games.controller.spec.ts region=controller-for

```

A stubbed decision asserts only that the controller called something.
`acl.guard.spec.ts` covers the guard, `games.service.spec.ts` the service, and
`orders.e2e.spec.ts` boots the real `AppModule` on a real port.
