# API reference

<WorkshopNotice slug="acl" />

`@evanion/acl` exports the evaluator, the typed builder, the document types and
the construction errors, one heading each below. Node 20 or newer, ESM only.
`@evanion/acl/testing` is a second entry point holding the assertions a
consumer of a published contract writes, and its exports are headed the same
way from [`contractDrift`](#contractdrift) down. The React provider and hooks
are [`@evanion/react-acl`](/react-acl/api).

## `hydratePolicy`

<!-- reference @evanion/acl#hydratePolicy example=matrix-round-trip -->

`hydratePolicy` copies the document, freezes and validates the copy, and throws
on an unknown key. All three type parameters default to the open forms JSON
carries.

## `parseMatrix`

<!-- reference @evanion/acl#parseMatrix example=foreign-matrix -->

`parseMatrix` is `hydratePolicy` with `closed: true`, for a document another
service published.

An unknown object kind or action answers `unknown-action` and nothing throws.
`Keys` is the union the consumer expects, unchecked against the document. See
[Adopting a foreign matrix](/acl/matrix#adopting-a-foreign-matrix).

## `policy`

<!-- reference @evanion/acl#policy example=field-permissions -->

`policy` returns the typed builder, one `.for()` per object kind. See
[Typed authoring](/acl/authoring).

| Type parameter | What it is                                                                                                                         |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `Sub`          | the subject type every `subject.*` path is checked against                                                                         |
| `Objects`      | each object kind mapped to its row type                                                                                            |
| `Vocabs`       | each kind mapped to the actions it answers for                                                                                     |
| `Action`       | the vocabulary a kind `Vocabs` omits gets, carrying no wildcard member; `docs/specs/2026-09-17-acl-wildcard-action.md` records why |
| `VocabularyOf` | what one kind's block may declare from; `string` there opens the kind to any action                                                |

## `Policy`

<!-- reference @evanion/acl#Policy -->

| Member or type   | What it is                                                                                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `for`            | takes no type arguments, reading the object type out of `Objects`, the vocabulary out of `Vocabs` and `Act` off the chain its block returns             |
| `matrix`         | flattens the blocks without building one                                                                                                                |
| `build`          | validates every block once and returns the `Access`                                                                                                     |
| `PermissionKeys` | the keys one block contributes; an `Act` the compiler reads as `string` contributes `string`, widening the document's whole key union                   |
| `KeysOf`         | lifts those keys out of an `Access` type; a producer exports `KeysOf<typeof access>` for a consumer compiled against its source                         |
| `ActionOf`       | the action half of the keys one object kind holds, checked against every query's action parameter; open, empty and unmatched key unions answer `string` |

Both are document fields, so they land in the flattened JSON.

## `AccessOptions`

<!-- reference @evanion/acl#AccessOptions -->

| Option      | What it is                                                                                          |
| ----------- | --------------------------------------------------------------------------------------------------- |
| `version`   | overrides the document's own `version`                                                              |

| `fetchedAt` | when this holder last validated; a holder that supplies it obliges the document to state `maxStale` |
| `maxStale`  | a local ceiling, `min`-ed with the document's                                                       |

## `Access`

<!-- reference @evanion/acl#Access example=revalidate -->

`Access` is the evaluator over one frozen document.

| Member                        | What it answers                                             |
| ----------------------------- | ----------------------------------------------------------- |
| `can`                         | one decision for one action on one row                      |
| `canMany`                     | one decision per row, settling one clock for the whole list |
| `canFields`                   | the field-level decision on the `read` or `write` axis      |
| `capabilities`                | every permission key, decided against one subject           |
| `authorize`                   | an `Authorized` handle carrying the subject                 |
| `object`                      | a `BoundKind` handle carrying the object kind               |
| `readsObject`                 | whether the permission needs the row before it can decide   |
| `matrix`, `version`, `schema` | the frozen document, and the two envelope fields off it     |

Every object parameter takes a partial: a projection is the
[`unevaluable`](/acl/refusals#when-the-answer-is-unevaluable) case. An absent
`subject.*` path is a definite miss.

## `Authorized`

<!-- reference @evanion/acl#Authorized -->

`Authorized` is what `authorize(subject)` returns.

`Authorized` omits `matrix`, `version`, `schema` and `readsObject`, which are
not facts about one subject.

## `BoundKind`

<!-- reference @evanion/acl#BoundKind -->

`BoundKind` is what `object(key)` returns.

`authorize` binds the other axis; the two compose.

## `pickAllowedFields`

<!-- reference @evanion/acl#pickAllowedFields example=write-path -->

`pickAllowedFields` returns the subset of a proposed write the decision marked
`allowed`, and throws `ActionNotAllowedError` on a refused action. See
[the write path](/acl/fields#writing).

## `serialize`

<!-- reference @evanion/acl#serialize example=typed-contract -->

`full` hands back `access.matrix`. `reduced` keeps each permission marked
`visibility: 'public'` whole, strips the marking, and adds the `schema` entries
for the kinds they name. See
[Many services](/acl/federation#publishing-the-rules-to-a-consumer).

## `federatedPolicies`

<!-- reference @evanion/acl#federatedPolicies example=federation -->

`federatedPolicies` composes one `Access` per origin and merges no document. See

## `FederatedAccess`

<!-- reference @evanion/acl#FederatedAccess -->

`can` routes to the origin holding `` `${object}.${action}` ``; a key no member
holds answers `unknown-action`. `capabilities` settles one instant for all.

## `applyDenyOverlay`

<!-- reference @evanion/acl#applyDenyOverlay example=deny-overlay -->

`applyDenyOverlay` appends another team's deny rules to the keys this document
opens for veto. See
[Many services](/acl/federation#a-cross-cutting-deny-is-an-overlay-the-owner-applies).

## `DenyOverlay`

<!-- reference @evanion/acl#DenyOverlay example=deny-overlay -->

A `Rule` spells no allow and no field rule, so an overlay only subtracts.

## `DenyOverlayOptions`

<!-- reference @evanion/acl#DenyOverlayOptions -->

A key listed in `vetoable` obliges the matrix to declare that key's object kind
in `schema.objects`.

## `diffMatrix`

<!-- reference @evanion/acl#diffMatrix example=drift-seam -->

`diffMatrix` compares two matrix documents and reports access rather than text.
See [What did this change do to access?](/acl/changes).

The evaluator ORs the rules on a side, so a side that matched goes on matching
whatever is appended. An added allow branch can therefore only widen and an
added deny branch only narrow. A finding is a direction and an upper bound,
never an exact set.

## `MatrixDiff`

<!-- reference @evanion/acl#MatrixDiff -->

`unchanged` is true when the two documents state one policy. Rule order and
condition key order are not policy, so a reordered document reports nothing.

## `DiffFinding`

<!-- reference @evanion/acl#DiffFinding -->

Discriminated on `kind`. Every member carries `key`, the permission key the
finding is about.

## `findingsOf`

<!-- reference @evanion/acl#findingsOf example=diff-matrix -->

`findingsOf` returns the findings of one kind, narrowed to that member.

`MatrixDiff.findings` is one list because a report is read in order. A caller
rendering a section of that report wants one kind, and reaching it otherwise
means a `filter` and a narrowing written the same way at every call site.
The order `diffMatrix` built the report in is kept.

## `GrantedFinding`

<!-- reference @evanion/acl#GrantedFinding -->

`when` is the added branch whole and `groups` is it split for rendering.
`fields` carries the field names added, where `cause` is `field-list-widened`.

<!-- reference @evanion/acl#WithdrawnFinding -->

<!-- reference @evanion/acl#WithdrawnCause -->

## `UndeterminedFinding`

<!-- reference @evanion/acl#UndeterminedFinding -->

A change `diffMatrix` declines to call a widening or a narrowing, with both

## `UndeterminedCause`

<!-- reference @evanion/acl#UndeterminedCause -->

`rule-edited` is a rule that kept an author-supplied `id` and changed its
conditions. `both-sides-changed` is a permission whose allow side and deny side
both moved. `fields-changed` is a field-rule change outside the one decidable
case, which is two literal name lists carrying no `*` and no `!` entry.

## `ReadsObjectFinding`

<!-- reference @evanion/acl#ReadsObjectFinding -->

A change in which `object.*` paths a decision reads. No access moved, and a
caller that decides in front of the fetch gets `unevaluable` where it got
`allow`.

## `ConditionGroups`

<!-- reference @evanion/acl#ConditionGroups -->

`subject` is who gained or lost the access, `object` is which rows, and
`window` is the `now` conditions. A condition comparing a subject path against
an object path lands in `object`.

## `Matrix`

<!-- reference @evanion/acl#Matrix example=schema-binding -->

`Matrix` is a JSON envelope over a flat list of permissions. See
[The matrix document](/acl/matrix).

| Type           | What it holds                                                                                                                 |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `Permission`   | one `` `${object}.${action}` `` key, its allow rules, its deny rules and its field rules                                      |
| `Rule`         | an id and a list of AND-ed conditions                                                                                         |
| `Condition`    | one comparison; [The matrix document](/acl/matrix#conditions) has the operator table                                          |
| `FieldRules`   | the `fields` list, then one key per field carrying a write-axis config, so a field named `fields` cannot be configured        |
| `FieldConfig`  | `targets` allow-lists the proposed value and `transitions` is a state machine over the current one; see [Fields](/acl/fields) |
| `MatrixSchema` | optional for a producer, binding where present, per kind: a kind `objects` omits is unchecked                                 |
| `ObjectSchema` | a kind's field types, and the `relations` naming the kinds it points at, one hop; no condition compares a relation            |
| `FieldType`    | a flat string any language emits by reflection, where `?` marks a field that may be absent                                    |
| `Instant`      | an ISO 8601 string, epoch milliseconds, or a `Date`; the string and number forms survive JSON                                 |

## `@evanion/acl/testing`

`@evanion/acl/testing` is the second entry point. `@evanion/acl` re-exports
none of it, so an application importing the engine pulls none of it into its
bundle, and nothing here imports a test framework. See [Testing a contract I
consume](/acl/testing).

```ts twoslash
import {
  assertAllowed,
  assertNoContractDrift,
  fixtureClock,
} from '@evanion/acl/testing';
```

## `contractDrift`

<!-- reference @evanion/acl/testing#contractDrift example=contract-drift -->

`contractDrift` replays a consumer's own decisions against two versions of one
contract and reports what moved.

Both documents are adopted with `parseMatrix`, which fails closed, so a removed
key answers `unknown-action` and is reported in `changed`. Nothing throws
partway through the run.

## `assertNoContractDrift`

<!-- reference @evanion/acl/testing#assertNoContractDrift example=drift-assert -->

`assertNoContractDrift` throws a `ContractDriftError` when the producer removed
a published key or a replayed decision changed, and returns the report
otherwise.

An added key passes, so a producer that only widened its surface leaves the
consumer's build green.

## `describeContractDrift`

<!-- reference @evanion/acl/testing#describeContractDrift example=drift-assert -->

`describeContractDrift` renders a report as a reader sees it, removals first.

A removal is spelled as a broken contract and a changed decision is spelled as
a change, because one report that spelled them alike would leave the consumer
to work out which of the two it is looking at.

## `ContractDriftOptions`

<!-- reference @evanion/acl/testing#ContractDriftOptions -->

`pinned` is the contract this consumer compiled against and `fetched` is the
one the producer publishes now. `contractDrift` settles `now` once, so it
decides a time-windowed permission at one epoch in both documents and never at
two readings of the wall clock.

## `ContractDriftReport`

<!-- reference @evanion/acl/testing#ContractDriftReport -->

`removed` holds the permission keys the pinned contract carries and the fetched
one does not, which is a producer breaking a published contract. `added` is not
a break. `diff` is whatever `options.diff` returned.

## `DecisionCase`

<!-- reference @evanion/acl/testing#DecisionCase -->

The three positional arguments of `can` in a bag, plus a name for the report.
`key` is the object kind and `action` the action, so the permission key the
document carries is `` `${key}.${action}` ``.

## `DecisionChange`

<!-- reference @evanion/acl/testing#DecisionChange -->

Two decisions are the same when `key`, `allowed`, `reason`, `rule` and every
element of `missing` match, so a refusal that started naming a second
unreadable path arrives as a change.

## `MatrixDiffer`

<!-- reference @evanion/acl/testing#MatrixDiffer -->

The type of `options.diff`, which [`diffMatrix`](#diffmatrix) satisfies.
`contractDrift` reads nothing out of the result and carries it onto
`report.diff`, so the diff's own shape stays the diff's business and arrives
here as `D`.

## `fixtureClock`

<!-- reference @evanion/acl/testing#fixtureClock example=fixture-clock -->

`fixtureClock` computes a document's freshness budget the way the engine
computes it and names the two instants that bracket it.

Every argument is validated as `hydratePolicy` validates it, so a document
stating no `maxStale` raises `MissingFreshnessBudgetError` from `fixtureClock`,
before the test reaches the construction it was about to write.

## `FixtureClockOptions`

<!-- reference @evanion/acl/testing#FixtureClockOptions -->

## `FixtureClock`

<!-- reference @evanion/acl/testing#FixtureClock -->

`options` carries the two numbers the instants were derived from, so the holder
and the test cannot disagree about the budget.

## `assertAllowed`

<!-- reference @evanion/acl/testing#assertAllowed example=consumer-assertions -->

`assertAllowed` returns the decision when it allows, and throws naming why it
did not.

The decision is returned so a caller chains on it, and `context` is a label
prefixed onto the message.

## `assertRefused`

<!-- reference @evanion/acl/testing#assertRefused example=fixture-clock -->

`assertRefused` returns the decision when it refuses, and throws naming what it
answered.

Naming `reason` asserts which refusal arrived, and a UI treats three of them
differently: `unevaluable` asks for a refetch of the row, `stale-contract` for
a refetch of the document, and `denied` for neither.

## `assertFieldState`

<!-- reference @evanion/acl/testing#assertFieldState example=consumer-assertions -->

`assertFieldState` returns the field decision when the named field is in
`state`, and throws naming the whole decision when it is not.

A field the decision carries no entry for is reported apart, because
`decision.fields` and `decision.reasons` are keyed by the names the document
declares and an absent name means the test named a field the permission never
had.

## `explainDecision`

<!-- reference @evanion/acl/testing#explainDecision example=consumer-assertions -->

`explainDecision` renders one line naming everything a `Decision` carries.

A failed `expect(decision.allowed).toBe(true)` reports `true !== false` and
names neither the key, the reason, the rule that decided, nor the paths a
refusal is waiting on.

## `explainFieldDecision`

<!-- reference @evanion/acl/testing#explainFieldDecision example=consumer-assertions -->

`explainFieldDecision` renders the action decision a field decision hangs off,
then every field beside its state and its reason.

`FieldDecision.allowed` is true only when the action is allowed and every field
is, so a false one has at least two places to look: `decision.action` and
`decision.fields`.

## `AclAssertionError`

<!-- reference @evanion/acl/testing#AclAssertionError example=drift-assert -->

Every assertion in `@evanion/acl/testing` throws this class or a subclass of
it. A plain `Error` subclass and no matcher, so vitest, `node:test` and jest
each report a throw from a test body the same way.

## `ContractDriftError`

<!-- reference @evanion/acl/testing#ContractDriftError example=drift-assert -->

Raised by `assertNoContractDrift` for a removed key or a changed decision, with
the whole report attached and `describeContractDrift` of that report as the
message.

## `AclConfigError`

<!-- reference @evanion/acl#AclConfigError example=errors-catching -->

`AclConfigError` is the base of every class below. [Typed
authoring](/acl/authoring#construction-errors) tables the same set by authoring
step.

| Error                             | Raised when                                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------------------- |
| `InvalidMatrixError`              | the envelope carries no `permissions` array, or a `version` of the wrong type                     |
| `InvalidSchemaError`              | the schema's own shape is wrong; `where` locates it inside the document                           |
| `InvalidPermissionError`          | a permission's `object`, `action`, `rules` or `fields` is malformed                               |
| `InvalidRuleError`                | a rule is not an object, or its `when` is not an array                                            |
| `InvalidConditionError`           | a condition's shape, namespace, path depth or operator pairing is unusable                        |
| `KeyMismatchError`                | `key` is not exactly `` `${object}.${action}` ``                                                  |
| `DuplicatePermissionError`        | two permissions share a key                                                                       |
| `DuplicateRuleIdError`            | two rules of one permission carry the same `id`, counting both sides                              |
| `AmbiguousRuleIdError`            | `p.id()` follows an `allow` or `deny` that flattened to other than one rule                       |
| `UnknownFieldError`               | a condition names a field the schema does not declare                                             |
| `FieldTypeMismatchError`          | `contains` runs against a non-array, or a literal is of the wrong type                            |
| `BangInAllowListError`            | a `!name` entry sits inside an allow-list                                                         |
| `DenyWithoutBaselineError`        | a `!name` entry has no `*` baseline to subtract from                                              |
| `TargetsTransitionsConflictError` | one field configures both `targets` and `transitions`                                             |
| `UnknownObjectKeyError`           | a query on the open path names an unknown object kind; `parseMatrix` fails closed                 |
| `UnknownPermissionError`          | a query on the open path names an unknown key; `parseMatrix` answers `unknown-action`             |
| `OriginCollisionError`            | two origins claim one key, which `federatedPolicies` raises while composing                       |
| `UnvetoablePermissionError`       | an overlay names a key the target does not list as `vetoable`                                     |
| `MissingVetoSchemaError`          | a vetoable key's object kind has no `schema.objects` entry                                        |
| `UnpublishedVetoableError`        | `serialize` reduces away a vetoable key the contract would not ship                               |
| `MissingFreshnessBudgetError`     | a holder reports `fetchedAt` against a document stating no `maxStale`                             |
| `InvalidFreshnessError`           | `fetchedAt` is not an instant, or `maxStale` is not a finite, non-negative number of milliseconds |

## `DuplicateRuleIdError`

<!-- reference @evanion/acl#DuplicateRuleIdError example=rule-ids -->

Two rules of one permission carrying the same `id`. `diffMatrix` indexes each
side by rule id, so the second rule under a taken id replaces the first there
and a branch added beside it is reported as no change. The allow side and the
deny side of one permission share one id space. [Naming a
rule](/acl/authoring#naming-a-rule-with-pid) has the example.

## `AmbiguousRuleIdError`

<!-- reference @evanion/acl#AmbiguousRuleIdError example=rule-ids -->

A `p.id()` following an `allow` or a `deny` that flattened to other than one
rule. `rules` is how many that call wrote, and an `or()` inside it wrote one per
branch.

## What is not exported

`@evanion/acl` exports no `decide`, `decideFields` or `evaluateCondition`. Each
answers a fragment and trusts its caller for the rest.
