# Getting started

By the end of this page your own `policy()` answers two questions correctly: it
lets a customer edit their own question and it refuses a stranger.

## Before you start

- Node 20 or newer.
- An ESM project. `@evanion/acl` ships no CommonJS build.
- TypeScript 5.5 or newer, if you want the compiler to check your object kinds
  and actions. The package runs without it, and the example below runs as
  JavaScript once you delete its `type` line and the `<…>` after `policy`.
- A subject your server already resolves, meaning the user object your auth layer
  loaded with every field on it. acl never authenticates anybody; it takes the
  subject you hand it.

You need no API key, no service to run and no environment variable. `policy()`
turns your rules into a JSON document in your own process, the document
[the Overview](/acl) calls the matrix.

## Write the smallest policy that answers something

Three calls build a policy.

- `policy<Subject, Objects>()` names two types. `Subject` is the shape of whoever
  is acting, so `{ id: string }` at its smallest. `Objects` maps each object kind
  to the shape of its row, so `{ question: Question }` declares one kind called
  `question` whose rows are `Question`. Add a kind by adding a key.
- `.for(kind, block)` writes one kind's rules. The `kind` is one of the keys you
  just declared in `Objects`.
- `.build()` returns the evaluator. Name it `access`; every page in this section
  calls it that.

`.for()` hands your block one argument, conventionally `p`, and every condition
comes off it. `p.allow(action, ...conditions)` grants an action when every
condition holds. `p.eq(a, b)` compares two values named by path, and a path is a
string rooted at `subject` or at `object`:
`p.eq('object.askedBy', 'subject.id')` reads `askedBy` off the row and `id` off
the subject and asks whether they match.

That is the whole minimum configuration. Baize's rule is that the customer who
asked a question may edit it:


Two questions, two answers. The asker gets `true`. The stranger gets `false`,
and `reason` is `no-rule-matched`, which is the evaluator refusing because
nothing in the document granted the action. You configured no default and got
default deny.

Each `// ->` comment is the value its line returns. Paste the fence into a
module your project runs and wrap those lines in `console.log`: they print
`true`, `false` and `no-rule-matched`, and acl is working in your project.

## Two rules for the code around an acl policy

Build the policy once, at module scope. A rebuild per request walks every rule
again and returns an evaluator that gives the same answers, so the rebuild is
wasted work.

Gate on `allowed` and nothing else. No part of the library reads `reason` back
to decide anything, so a handler that branches on `reason` is writing a second
rule of its own, next to the one the policy already holds.
