**The concept.** A React Router route has two server entry points, the loader
and the action, with a browser tree between them that is neither. A
`<Form method="post">` reaches the action. So does `curl`, and the loader that
decided what to render never ran for that caller.

**What you will have.** What `apps/admin` runs: middleware binding the subject
and deferring the contract read, loaders deciding what a page returns, the action
deciding again on the row, and `useCan` picking the form or the sentence.

**Why you would want it.** Baize grants `game.declare` to an operator whose own
shop lists the title. Ines works in Stockholm, so the availability form is drawn
on Wingspan and withheld on Azul, which Gothenburg lists. The URL resolves
either way.

**How the library gets you there.** `parseMatrix` adopts the fetched document in
this process, so the loader, the action and the browser tree evaluate the same
rules and none of them asks shop-api a question.

## Two boundaries, not one

  <Text as="div" size="sm">

    the action, and the action carries none of its conclusions. Every action
    re-resolves the subject and decides again.
  </Text>

| Where           | Runtime | Decides?                               |
| --------------- | ------- | -------------------------------------- |
| `middleware`    | server  | binds the subject; decides nothing     |
| `loader`        | server  | yes, for what it returns               |
| Route component | browser | never; it toggles what the user sees   |
| `action`        | server  | yes, independently, for what it writes |
| `clientLoader`  | browser | never                                  |

A `clientLoader` runs in the browser and is no trust boundary, whatever it
fetches from. `apps/admin` has none and loads everything server-side, which is
the shape this page assumes.

## Adopting the document shop-api published

`apps/admin` authors no rules. `AdminSubject` carries `id`, `roles` and `shop`,
`AdminObjects` maps each key to the row shape it decides over, and `adoptMatrix`
turns a fetched document into an evaluator:

```ts file=apps/admin/app/access.ts region=adopt-matrix

```

`parseMatrix` and never `hydratePolicy`: the document is foreign input, and the
closed mode makes an unknown permission a refusal where `hydratePolicy` throws
inside a loader. The version keys the memo, because `parseMatrix` validates,
deep-clones and deep-freezes, and none of that changes between requests over one
document.

`access.ts` is deliberately not a `.server` module. The server evaluates the
matrix to enforce and the browser evaluates it to toggle, and the fetch is the
server's alone: it lives in `access.server.ts`, which the Vite plugin keeps out
of the browser bundle. A request that cannot reach shop-api falls back to
`NO_ACCESS`, a parsed document carrying no permissions, so every key answers
`unknown-action` and the page draws its chrome and writes nothing.

## Middleware binds, loaders decide

React Router 8's stable `middleware` plus `createContext` is where the subject
is resolved. `demoSubject()` is this app's whole identity story, `newCorrelationId`
mints the page view's id, and `readAccess` and `readShelf` are the two fetches
the contexts below defer:

```ts file=apps/admin/app/page-view.server.ts region=bind-subject

```

`subjectContext` takes a value and `accessContext` and `shelfContext` take
functions. React Router runs middleware, then the action, then the revalidating
loaders, so a memo cell the first caller fills keeps a page view to one fetch and
makes it happen after any action.

```ts file=apps/admin/app/page-context.ts region=subject-context

```

The default is a subject with no roles and no shop, so a loader reached without
the middleware having run decides against an actor Baize's matrix refuses
everywhere. A `Subject | null` default with a 401 at every read is the other
defensible choice; this app declines it, because a roles-less subject reaches
the same refusal through the rules the page is already about.

## The loader decides what a page returns

`allows` reads one permission out of a capability map, and `telemetry.read`
belongs to a manager:


The nav entry pointing here is hidden from every other subject, and it is still

A thrown `Response` is a genuine refusal, which the root `ErrorBoundary` renders
through `isRouteErrorResponse`. A degraded page returns a field:
`unavailable?: string`.

## What crosses to the tree

Loader return values are the serialization boundary, and `Access` is a set of
closures that does not survive it. What crosses is the document:

```ts file=libs/acl/README.md region=matrix-round-trip

```

`apps/admin`'s shell loader returns `access.matrix`, the subject and a `now`
string once for the whole tree. The matrix is an envelope carrying its own
`version` and `schema`, so nothing travels beside it. The subject is no
credential: the server resolves its own on the next request.

The shell component adopts that document with the same `adoptMatrix` the server
used, and composes the providers with `ComposeProvider` from `@evanion/compose`:

```tsx file=apps/admin/app/shell.tsx region=mount-provider

```

`now` crosses as a string, because the hooks key their memos on it by value and a
`Date` is a new object each render. The document crosses on every server render,
so a navigation replaces what the browser holds.

## The tree toggles, and enforces nothing

`useCan` comes from `createPolicyContext<AdminSubject, AdminObjects>`, so the
key and the row are both checked where the call is written:

```tsx file=apps/admin/app/routes/title.tsx region=tree-toggles

```

`mayDeclare` picks the availability form or a sentence naming the shop that
declares this title. The action behind the form is a URL, and the URL is still
there.

## Every action decides again

```tsx file=apps/admin/app/routes/title.tsx region=action-decides

```

`decision.action.allowed` is checked first, so a refusal returns the union
member the component narrows with `in`, and `pickAllowedFields` is reached only
on an allowed action. That call throws `ActionNotAllowedError` on a refused one,
so the check keeps the refusal off the exception path.

A `formData` bag is the mass-assignment shape: whatever the sender put a `name`
on arrives in it, including keys the title has never held. Filtering the returned
map by hand on `!== 'denied'` would write the `unevaluable` fields.

The row is re-read inside the action. Between the render that showed the button
and this action landing, the title can move to another shop and the ownership
rule can stop matching.
