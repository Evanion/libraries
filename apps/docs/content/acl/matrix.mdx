# The matrix document

<WorkshopNotice slug="acl" />

A matrix is a plain JSON envelope over a flat list of permissions. It is the
whole configuration: what it does not say, the library does not know.

```json
{ "version": 3, "schema": { "objects": {} }, "permissions": [] }
```

There is no bare-array form. `version` and `schema` are document fields rather
than construction options, so a producer in any language states both in the JSON
it emits, and one value crosses an SSR boundary with nothing assembled around
it.

## One permission

```ts
interface Permission {
  key: string; // exactly `${object}.${action}`
  object: string;
  action: string;
  rules?: Rule[]; // allows, OR-ed
  denyRules?: Rule[]; // denies, OR-ed; a matched deny wins
  fields?: FieldRules; // the field axis
}

interface Rule {
  id?: string; // what a decision reports as `rule`; defaults to `#0`, `#1`, …
  when?: Condition[]; // AND-ed
}
```

`key` must equal `` `${object}.${action}` ``, and neither half may contain the
dot. Lookup is by key alone, so a key that disagreed with its own `object` and
`action` would answer for a pair it was never written for; construction refuses
it with `KeyMismatchError`.

A rule with an empty `when` is the unconditional grant. That spelling is
deliberate: `when` is required and must be an array, so a document that lost its
conditions in transit — `null`, absent, a string — is a construction error
rather than a permission that grants everything.

## Conditions

One condition reads one path and compares it to one comparand.

```ts
{ field: 'object.authorId', op: 'eq', path: 'subject.id' }  // path comparand
{ field: 'subject.roles', op: 'contains', value: 'editor' } // literal comparand
{ field: 'now', op: 'after', value: '2026-01-01T00:00:00Z' }
```

| `op`       | Holds when                                   |
| ---------- | -------------------------------------------- |
| `eq`       | the two sides are `===`                      |
| `ne`       | they are not                                 |
| `in`       | `value` is an array containing the field     |
| `not-in`   | `value` is an array not containing the field |
| `contains` | the field is an array containing `value`     |
| `before`   | the clock is earlier than `value`            |
| `after`    | the clock is later than `value`              |

`path` is the `eq`/`ne` form only; every other operator compares against a
literal `value`. Comparison is strict on both sides of a JSON boundary: `'1'` is
not `1`, a `Date` is not the string that spells it, and `null` is not absence.

A path is namespaced and one level deep — `subject.x`, `object.y`, or the bare
`now`. There is no nesting and no relation traversal inside a condition; a
consumer that needs a related row resolves it and passes it as the object.

## The version

`version` is a string or a number, and the revalidate contract compares it with
`!==`. A content digest or a composite such as `orders@7+veto@41` works where a
counter cannot, which is what a construction site needs when it merges the
authored document with something else before building.


`createPolicy(matrix, { version })` overrides the document's value. The document
states what a producer shipped; the option states what this site is actually
running, which the producer cannot know. The option wins, and the frozen
`access.matrix` carries the winner — so the version that decided is the version
that crosses.

A document that states no version leaves `access.version` undefined, and a `!==`
against undefined decides nothing. A producer that wants the freshness contract
to hold states one; a hash of the document is enough.

## The schema

A document may declare the shapes its conditions read. It is optional for a
producer and binding when it is present.


Field types are flat strings, so the whole schema is JSON a producer emits by
reflection: `string`, `number`, `boolean`, `instant`, a `[]` suffix for an array
of one, a `?` suffix for a field that may be absent from a complete instance. A
declared field that is present and `null` is present — nullability is not an
optionality axis.

A present schema checks two things, both at construction:

1. a condition naming a field the declared kind does not declare —
   `UnknownFieldError`;
2. a condition whose operator or comparand does not fit the declared type —
   `FieldTypeMismatchError`: `contains` against a non-array, an equality against
   an array, a literal of the wrong type, or a `path` comparand whose two sides
   disagree.

It does not check the names in `fields` rules, the `targets` and `transitions`
keys, or whether a permission can ever decide `unevaluable`. Granularity is per
kind: a permission on an object kind absent from `schema.objects` is unchecked,
and `subject.*` paths are unchecked unless `schema.subject` is declared.

The typo class this closes is the expensive one. Without a schema,
`object.authorld` is not an error — it is a path that never reads, so the
permission reports `unevaluable` forever and a UI refetches forever.

## Adopting a foreign matrix

A backend with its own ACL can publish its matrix as JSON, and the frontend
adopts it. `parseMatrix` is `createPolicy` with `closed: true`: the key universe
is untrusted, so an unknown object kind or action fails closed instead of
throwing.


The two behaviours are the difference between a bug and a data problem. A key
the local typed policy does not carry is a programmer error and throws
`UnknownPermissionError`. A key a foreign document does not carry is a document
that has moved on, and a thrown error there would take down a page over a
permission nobody has.

## What construction does to the document

`createPolicy` does not keep your object. It rebuilds the envelope from one read
of each member, deep-clones every permission, freezes the result, and validates
that copy.

Reading twice is what this avoids. A caller's document is a live object, and an
accessor or a proxy on it can answer a second read differently — a `when` that
validates as a condition and clones as the empty, unconditional form is an open
grant that passed the gate. Nothing downstream reads the caller's object again,
and nothing can mutate what evaluates afterwards, including through the exposed
`access.matrix`.

The subject and the object are not copied. They are the app's data, they are
read live as the decision walks the rules, and copying them would hide the cost
of doing so. What that implies for a lazy ORM row is in [the security
contract](/acl/security).
