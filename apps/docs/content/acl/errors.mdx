**The concept.** `AclConfigError` is the base of every class construction
raises, and `ActionNotAllowedError` is the one throw that sits outside it.

**What you get.** The malformed input that raises each one, as code that runs.

**Why you want it.** A refusal names a class, and the class alone does not say
which value to change.

**How the library gets you there.** Each error carries `key`, `field` or
`where` beside its message, locating the value inside the document.

## When acl throws, and when it refuses instead

A refusal is a `Decision` carrying `allowed: false`, and a throw ends the call.
Which one a caller meets is decided by where the document came from.

`hydratePolicy` is the open path, for a document this service authored. A key
it never held is an authoring mistake, so a query naming one throws.

`parseMatrix` is the closed path, for a document another service published. A
key it never holds is ordinary, because the producer's next release removes
keys this consumer still asks about, so a query naming one answers
`unknown-action` and refuses.

Everything else throws at construction, which is startup for a local matrix and
adoption time for a foreign one, so a malformed document fails a deploy rather
than a request. [The API reference](/acl/api#aclconfigerror) carries every
class and the properties each one adds.

## What refuses an acl schema or field rule

A schema is checked for its own shape first. Every condition naming a declared
kind is then checked against it, which is what turns a renamed column into a
failed deploy rather than a permission that silently stops matching. Field
rules are checked whether a schema is present or not.

`*` and `!name` are authoring syntax and never field names, so
`BangInAllowListError` and `DenyWithoutBaselineError` are raised by the shape
of the list rather than by any field it mentions. [Which fields may they

## Catching every acl configuration fault at once

`AclConfigError` is the base of every class construction raises, so a startup
guard catches the set without naming each member.

It does not cover `ActionNotAllowedError`, which extends `Error` directly. That
one comes from `pickAllowedFields` when the action was refused, on a document
that is entirely valid, so it is a request-time refusal rather than a
configuration fault. A handler catches it where the write happens. [Which
fields may they write?](/acl/writing#the-acl-action-gate) has the pair of
booleans behind it.


A service that wraps construction in one `catch (error) { if (error instanceof
AclConfigError) ... }` reports every malformed document the same way, and still
has to handle the write refusal where the write is attempted.
