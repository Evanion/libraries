# What can throw?

Every error `@evanion/acl` throws extends `AclConfigError` except one:
`pickAllowedFields` throws `ActionNotAllowedError` when the action it was handed
was refused.

## Catching every acl configuration fault at once

A service builds its evaluator at startup, and a malformed document should fail
the deploy with a message naming the value to change. `AclConfigError` is the
base of every class construction raises, so one `catch` around construction
reports the whole set:

```ts twoslash file=libs/acl/README.md region=errors-catching

```

`ActionNotAllowedError` extends `Error` directly. `pickAllowedFields` raises it
at request time, on a document that is entirely valid, when the subject may not
take the action at all. A startup guard around construction does not catch it,
so the handler that writes has to.
[When the acl action itself is refused](/acl/writing#when-the-acl-action-itself-is-refused)
covers the two booleans behind it.

The assertions in `@evanion/acl/testing` throw `AclAssertionError`, which
[How do I test a contract I consume?](/acl/testing) covers.

## When an acl query throws, and when it refuses

A refusal is a decision carrying `allowed: false`, and a throw ends the call.
Where the document came from decides which one a query meets:

- `hydratePolicy` is the open path, for a document this service wrote. A key
  the document never held is an authoring mistake, so a query naming one
  throws.
- `parseMatrix` is the closed path, for a document another service published.
  The owner's next release can remove a key this consumer still asks about, so
  a query naming one answers `unknown-action`.

```ts twoslash file=libs/acl/README.md region=errors-query

```

The open path throws `UnknownPermissionError` for an action the document never
declared, and `UnknownObjectKeyError` for an object kind it never configured.
Everything else on this page throws at construction, which is startup for your
own document and adoption for a foreign one, so a malformed document fails a
deploy and never a request.

## What refuses an acl document

Each case names its input first, and `raised` reports the class, so one case
reads as one line:

```ts twoslash file=libs/acl/README.md region=errors-document

```

| Class                      | The input that raises it                                                        |
| -------------------------- | ------------------------------------------------------------------------------- |
| `InvalidMatrixError`       | no `permissions` array, or a `version` that is not a string or a number         |
| `KeyMismatchError`         | a `key` that is not exactly `` `${object}.${action}` ``                         |
| `DuplicatePermissionError` | two permissions sharing one key                                                 |
| `InvalidPermissionError`   | a permission missing its `action`, or a malformed `object`, `rules` or `fields` |
| `InvalidRuleError`         | a rule whose `when` is absent or not an array                                   |
| `InvalidConditionError`    | an unknown `op`, a path nested below its scope, or an unknown scope             |

`InvalidConditionError` carries `key`, `field` and `where`, and `where` is the
path to the condition inside the permission, so a document with forty rules
names the one to fix:


## What refuses an acl schema or field rule

A schema is checked for its own shape first, and then every condition naming a
declared kind is checked against it. Field rules are checked whether a schema is
present or not.

```ts twoslash file=libs/acl/README.md region=errors-schema-fields

```

| Class                             | The input that raises it                                               |
| --------------------------------- | ---------------------------------------------------------------------- |
| `InvalidSchemaError`              | a field type the schema vocabulary does not have                       |
| `UnknownFieldError`               | a condition naming a field the schema does not declare                 |
| `FieldTypeMismatchError`          | an operator that does not fit the type, such as `contains` on a string |
| `BangInAllowListError`            | a `!name` inside a list of names                                       |
| `DenyWithoutBaselineError`        | a `!name` with no `*` beside it                                        |
| `TargetsTransitionsConflictError` | one field given both `targets` and `transitions`                       |

`*` and `!name` are syntax in a list of fields, so the last three are raised by
the shape of the list. [Which fields may they write?](/acl/writing) has that
syntax. A typed author meets two more while naming rules, `DuplicateRuleIdError`
and `AmbiguousRuleIdError`, which
[Typed authoring](/acl/authoring#construction-errors) tables.

## What refuses an acl consumer's freshness settings

A consumer that reports `fetchedAt` is asking for a freshness budget, and the
check runs where the evaluator is built, so a misconfigured consumer fails at
startup:

```ts twoslash file=libs/acl/README.md region=errors-freshness

```

`MissingFreshnessBudgetError` means the consumer reported `fetchedAt` against a
document that states no `maxStale`, and the owner has to state how long a check
lasts. `InvalidFreshnessError` means the consumer's `fetchedAt` does not parse as an
instant, or its own `maxStale` is not a finite, non-negative number of
milliseconds.
[How long a consumer may keep deciding on an acl contract](/acl/publishing#how-long-a-consumer-may-keep-deciding-on-an-acl-contract)
has the budget.

## What refuses an acl composition

Composing documents across services is the last place acl checks one, and each
refusal names the key it refused:

```ts twoslash file=libs/acl/README.md region=errors-composition

```

| Class                       | The input that raises it                                           |
| --------------------------- | ------------------------------------------------------------------ |
| `OriginCollisionError`      | two origins in `federatedPolicies` claiming one key                |
| `UnvetoablePermissionError` | a deny overlay reaching a key the owner did not list as `vetoable` |
| `MissingVetoSchemaError`    | a `vetoable` key whose object kind the schema does not declare     |
| `UnpublishedVetoableError`  | a `vetoable` key that `serialize(access, 'reduced')` would drop    |

[Many services](/acl/federation) has the topology `OriginCollisionError` comes
from, and
[the cross-cutting deny](/acl/federation#a-cross-cutting-deny-is-an-acl-overlay-the-owner-applies)
is where the three veto errors belong.
