An access-control matrix written once, serialized as JSON, and evaluated locally
by whatever JS runtime holds it — a Node service, an SSR graph, a browser SPA,
React Native, Electron. The matrix is a frozen document. There is no per-subject
snapshot to build and no round trip to a policy server to make one decision.

`can` answers with a decision, not a boolean. `allowed` is the answer;
`reason`, `rule`, `blockedBy`, `cause` and `missing` are why.

## When to reach for it

- Permissions that depend on the row, not only on the role — "the author may
  edit their own comment", "a draft may be deleted and a published one may not".
- The same rules needed on a server and in a UI, without writing them twice and
  without an endpoint per question. The document crosses an SSR boundary as
  `access.matrix` and rebuilds on the other side.
- A UI that has to explain a block rather than only enforce it: which rule
  refused, which parent permission is off, which field is read-only, what is
  still missing before the question can be answered at all.
- A field-level write path, where the answer is "these keys of the write are
  yours" rather than a single yes.

## When not to

- Anything the document cannot state in the open. The matrix ships to the
  client in full, so every object kind, action, role string, field name and time
  boundary in it is public. Opaque predicates stay server-side, outside the
  matrix.
- Filtering a collection in the database. A decision is per instance; there is
  no row-scoping query language, and generating a `WHERE` clause from the matrix
  is out of scope.
- Rules that need to call a function. Conditions are declarative because the
  matrix must survive `JSON.stringify` losslessly.
- A non-JS backend. Only the JSON crosses; a .NET or Go service uses its own
  evaluator.

## What is in the package

| Export                                  | What it is                                                        |
| --------------------------------------- | ----------------------------------------------------------------- |
| `createPolicy(matrix, options?)`        | the access object, from a document you trust                      |
| `parseMatrix(json, options?)`           | the same, from a foreign document; fails closed on unknown keys   |
| `policy<Subject>()`                     | the typed builder, one `.for()` block per object kind             |
| `access.can` / `canMany` / `canFields`  | one decision, a decision per instance, the field-level decision   |
| `pickAllowedFields(decision, proposed)` | the subset of a proposed write to actually write                  |
| `access.capabilities` / `authorize`     | every decision at once, and a subject bound for the request       |
| `access.matrix` / `version` / `schema`  | the frozen document and its two header fields                     |
| `AclConfigError` and its subclasses     | every construction failure; see [Typed authoring](/acl/authoring) |

The React provider and hooks are a separate package,
[`@evanion/react-acl`](https://github.com/Evanion/libraries/tree/main/libs/react-acl#readme).
This entry imports no framework.
