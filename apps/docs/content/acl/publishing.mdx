# How do I give my rules to another service?

`serialize(access, 'reduced')` emits the permissions you marked public as a JSON
document another service adopts with `parseMatrix` and decides from in its own
process.

## Publishing an acl contract with `serialize`

Baize's storefront draws a refund button, and the refund rules live in the
`orders` service. A storefront that cannot read those rules writes its own copy,
which the `orders` team does not own and cannot correct. The copy diverges the
first time `orders` changes a rule, and the button stays hidden against a server
that would have allowed the call.

`.visibility('public')` marks the action the chain declared last for
publication, and `serialize(access, 'reduced')` keeps the marked permissions and
drops the rest:

```ts twoslash file=libs/acl/README.md region=typed-contract

```

The reduced document is the contract. It holds `orders:order.refund` and not
the ledger permission, because an unmarked permission is internal, and so is a
permission whose author forgot the mark. The storefront adopts the contract with
`parseMatrix`, which [How do I use rules another service published?](/acl/adopting)
covers, and answers the refund question with no call back to `orders`. The
`orders:` prefix names the service that owns the object kind, which
[Many services](/acl/federation) explains.

The storefront's answer draws the button, and `orders` decides again on its own
matrix when the refund call arrives.

## A published acl permission goes out whole

`serialize` emits a kept permission with every rule it carries, deny rules
included. Below, the document is written as JSON, which is what a service in
another language emits:

```ts twoslash file=libs/acl/README.md region=contract

```

Drop one deny rule and a refusal becomes an allow. Drop an allow rule or a
field config and the answer moves the other way. So the refund permission ships
with its deny rule, and every consumer reads `subject.tier` and the word
`probation`. A permission whose deny rules read an internal concept discloses
that concept, so publish it and accept the disclosure, or leave it unmarked.

The schema keeps only the object kinds a kept permission names, so the ledger's
entry is gone. The contract's decisions equal the owner's, key for key: a
contract that answered more cautiously would be a second copy again, and a
button hidden by caution looks exactly like a button hidden by a rule.

## How long a consumer may keep deciding on an acl contract

`maxStale` is the owner's ceiling, in milliseconds, measured from the consumer's
last successful check that its copy is current. The consumer reports that
instant as `fetchedAt`, as the storefront does with `Date.now()` above, and may
tighten the bound with its own `maxStale`. Past `fetchedAt + min(the two)` every
key answers `stale-contract`, and a fetch of the document repairs it.

| Bound                      | Who states it | What it does                                   |
| -------------------------- | ------------- | ---------------------------------------------- |
| `maxStale` on the document | the owner     | sets the ceiling, in milliseconds              |
| `maxStale` on the consumer | the consumer  | tightens the owner's ceiling, never extends it |
| `fetchedAt`                | the consumer  | names the instant the bound measures from      |
| neither of the two         | nobody        | leaves the consumer claiming no freshness      |

State `maxStale` on the document before any consumer reports `fetchedAt`. A
consumer reporting one against a document with no ceiling gets
`MissingFreshnessBudgetError` at construction, because the owner's bound is the
only one that expires a copy. A consumer that reports no `fetchedAt` runs under
no bound, which is every matrix a service authors in its own process.

A stale contract errs toward drawing the button. The consumer draws a control
the owner has since revoked, and the write behind it still fails, because
`orders` evaluates its own matrix on every call.

## A key another team may veto has to be published

`serialize(access, 'reduced', { vetoable })` refuses to drop a key the list
names, with `UnpublishedVetoableError`. A compliance team checks its own deny
rules against the published contract with
[`applyDenyOverlay`](/acl/federation#a-cross-cutting-deny-is-an-acl-overlay-the-owner-applies),
which merges another team's deny rules into a document before it is built. An
internal key that team may veto is absent from the contract, along with its
object kind's schema entry, so that check refuses every rule it was written to
accept.
