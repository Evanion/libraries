# Rules that another service wrote

`parseMatrix` evaluates a matrix that another service built and served as JSON.
The producer's `schema` lets construction refuse a condition that misreads a
field, and its `version` tells the consumer when its copy is out of date.

## Publishing an acl matrix with a version and a schema

Baize's `orders` service owns the rules about questions and serves its
`access.matrix`, the JSON document [the Overview](/acl) introduced, to the
storefront over HTTP. It passes `version` and `schema` to `policy()`, because
both belong to the document and travel inside it:

```ts twoslash file=libs/acl/README.md region=typed-document

```

`version` is a string or a number naming this revision of the document.
`schema` declares the type of every field a condition reads, on the subject and
per object kind. The `Objects` type that catches a misspelled `object.askedBy`
stays in the `orders` codebase, so once the document leaves it the schema is
what checks the paths. Field types are flat strings: `string`, `number`,
`boolean`, `instant`, a `[]` suffix for an array and a `?` suffix for a field
that may be absent. A producer in any language can emit one.

The library writes no file and reads none. Serving the document and fetching it
are the application's.

## Adopting an acl matrix with `parseMatrix`

The storefront builds its evaluator from the fetched JSON with `parseMatrix` and
asks it questions through the same `can`. `parseMatrix` is `hydratePolicy` with
`closed: true`, so a key the document does not carry answers `unknown-action`
with `allowed: false` and throws nothing:

```ts twoslash file=libs/acl/README.md region=foreign-matrix

```

The document grants `question.read` to a bookseller and carries no
`question.delete`, so asking for `delete` answers `unknown-action`.

`hydratePolicy`, which the Overview used for your own document coming back, runs
open, and the same question throws `UnknownPermissionError`. A key your own
policy lacks is a programmer error, and the throw points at the line. A key a
foreign document lacks means the producer removed the permission, and a throw
there takes the storefront's page down over a permission nobody holds.
[A policy from another service](/acl/adopting) lists every check `parseMatrix`
runs on the way in.

## What the acl schema refuses at construction

`hydratePolicy` and `parseMatrix` both check a document against its `schema`
before they return an evaluator. This document declares `status` as a string and
tests it with `contains`, which tests an array:

```ts twoslash file=libs/acl/README.md region=schema-binding

```

Construction throws `FieldTypeMismatchError`, and no evaluator exists to answer
anything. A condition naming a field the schema does not declare throws
`UnknownFieldError` the same way.

Without a schema, a misspelled `object.askedBv` builds cleanly and decides
`unevaluable` on every call, with `missing` naming a path no query ever
selects. The schema is optional for a producer and binds per object kind, so a
kind absent from `schema.objects` is unchecked.

## Refetch when the version moves

The storefront's copy grants what it granted when it was fetched, so a
permission `orders` withdraws stays granted in the browser until the storefront
fetches again. The library never pushes an update and never fetches. It exposes
`access.version` for the consumer to compare with the version the server now
serves:

```ts twoslash file=libs/acl/README.md region=revalidate

```

`revalidate` keeps the evaluator in hand while the versions match and adopts the
served document when they differ. The held `orders@7` copy granted
`question.update` to Jo, `orders@8` dropped it, and after the rebuild the same
call answers `unknown-action`. `revalidate` rebuilds with `parseMatrix` because
`hydratePolicy` throws `UnknownPermissionError` on the dropped key.

```mermaid caption="The document's loop across two services. orders builds the matrix with a version and a schema, the storefront adopts it with parseMatrix and answers can from it, and a served version that differs from the held one sends the storefront back for the document."
flowchart LR
  A["orders service<br>policy() + schema"] --> B[("matrix JSON<br>version · schema · permissions")]
  B --> C["storefront<br>parseMatrix(json)"]:::accent
  C --> D["can(subject, …)"]
  C --> V{"served version<br>!== held version?"}
  V -->|yes| F["fetch the document again"]
  F --> B
```

A document with no `version` leaves `access.version` undefined on both copies,
so the comparison always matches and the storefront never rebuilds. Any string
or number works as a version, a content digest included. The `orders` service
never reads the storefront's copy: it evaluates its own document before it
writes anything.
