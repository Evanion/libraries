**The concept.** Baize's `orders` service writes the matrix. The storefront
fetches it and evaluates it, and nobody on the storefront ever imports the file
it was written in. By the time the storefront asks a question, the process that
wrote the answer has exited, and every question on this page follows from
that.

**What you will have.** A document that states the field shapes its own
conditions read, a version string a reader can compare, and a `parseMatrix` that
takes somebody else's document without throwing on a permission you have never
heard of.

**Why you would want it.** Without the schema, Priya renames `buyerId` to
`customerId` in `orders` on a Tuesday, and the storefront goes on asking about a
path that no longer reads: the permission answers `unevaluable` forever, the
screen refetches forever, and nothing anywhere raises an error. Without the
version, a bookseller is handed an Edit button for a permission the owner
revoked an hour ago, and the browser holding the old document has no way to
notice.

**How the library gets you there.** A `schema` on the document turns a mistyped
path into an `UnknownFieldError` at construction. `version` gives the client one
value to compare with `!==`. `parseMatrix` fails closed on a key the document
does not carry, so a producer that moved on cannot take a page down.

## Declare the shape

The typed builder held you to `object.authorId` while you were writing the
policy. That type stays in your editor and the document leaves without it, so a
document that travels may declare the shapes its conditions read. The schema is
optional for a producer and binding wherever it is present.

```ts file=libs/acl/README.md region=schema-binding

```

Field types are flat strings — `string`, `number`, `boolean`, `instant`, a `[]`
suffix for an array, a `?` suffix for a field that may be absent — so a producer
in any language emits the whole schema by reflection.

Two checks, both at construction: a condition naming an undeclared field is
`UnknownFieldError`; an operator or comparand that does not fit the declared
type is `FieldTypeMismatchError`. Granularity is per kind, so a permission on a
kind absent from `schema.objects` is unchecked.

Priya authors against the TypeScript types and ships the schema beside them:

```ts file=libs/acl/README.md region=typed-document

```

The two are checked independently and can disagree. A path TypeScript accepts is
still an `UnknownFieldError` when the schema does not declare it — the schema is
binding wherever it is present.

## Drive a UI from the whole matrix

`capabilities` answered the whole policy at once while every condition read the
subject, and it goes on doing that once conditions read the object too: every
permission in the document against one subject, in document order, in a single
pass.

```ts file=libs/acl/README.md region=capabilities

```

Two kinds, three permissions, every condition on `subject.roles`, so all three
come back decided. A permission whose rules read `object.*` is the other case.
The call passes no object, so that permission decides `unevaluable`: with no
listing in hand there is nothing for `object.status` to be compared against, and
the engine says so. [What can they do at all?](/acl/capabilities) is about the
half of a matrix that reads only the subject, which is the half this call
answers outright.

## Adopt a document somebody else wrote

Every document so far is one this process built, and the storefront builds
none: `orders` does. `parseMatrix` is `hydratePolicy` with `closed: true` for
exactly that case. The key universe is untrusted, so an unknown object kind or
action fails closed instead of throwing.

```ts file=libs/acl/README.md region=foreign-matrix

```

The difference is between a bug and a data problem. A key the local typed policy
does not carry is a programmer error and throws `UnknownPermissionError`. A key a
foreign document does not carry is a document that has moved on, and throwing
there would take down a page over a permission nobody has. [My policy came from
another service](/acl/adopting) is the whole story.

## Version the document, and revalidate against it

A foreign document now evaluates without throwing. The question left is which
foreign document arrived. `version` is a string or a number and the contract
compares it with `!==`, so a content digest or a composite such as
`orders@7+veto@41` works where a counter cannot. The document states what a producer shipped; `hydratePolicy(matrix, {
version })` states what this construction site is actually running, which the
producer cannot know. The option wins, and the frozen `access.matrix` carries the
winner.

## Refetch when the version moves

You can compare the two version strings. Nothing compares them for you: the
storefront holds the matrix it last fetched, and when the owner revokes a
permission that copy goes on granting it until somebody fetches again. The
library supplies the comparison and leaves the fetch to you:

```ts file=libs/acl/README.md region=revalidate

```

There is no push, no expiry and no staleness flag. A document that states no
`version` leaves `access.version` undefined, where a `!==` decides nothing, so a
producer who wants the contract to hold states one. The `orders` service never
depends on the storefront's copy in any case: it evaluates its own before it
writes anything.
