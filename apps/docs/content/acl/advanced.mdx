**The concept.** Baize's `orders` service writes the matrix. The storefront
fetches it and evaluates it, and nobody on the storefront ever imports the file
it was written in. By the time the storefront asks a question, the process that
wrote the answer has exited, and every question on this page follows from
that.

**What you will have.** A document that states the field shapes its own
conditions read, a version string a reader can compare, and a `parseMatrix` that
takes somebody else's document without throwing on a permission you have never
heard of.

```mermaid caption="The document's life across two processes. The orders service builds a matrix and declares in its schema the field shapes its conditions read, which the builder checks at construction. The storefront calls parseMatrix, which fails closed on a key it does not know, and compares the version it just fetched against the one it already holds to decide whether to fetch again."
flowchart LR
  A["orders service<br>policy() + schema"] --> B[("matrix JSON<br>version · schema · permissions")]
  B --> C["storefront<br>parseMatrix(json)"]:::accent
  C --> D["can(subject, …)"]
  C --> V{"version !== the<br>version held?"}
  V -->|yes| F["fetch the document again"]
  F --> B
```

**Why you would want it.** Priya maintains Baize's `orders` service. Without the
schema she publishes a rule that tests `object.status` with `contains`, the
operator for an array, against a field holding a string. Nothing refuses the
document. The condition never holds, so the storefront draws that control for
nobody, and a shopper files the first report of it. Without the version a
bookseller is handed an Edit button for a permission the owner revoked an hour
ago, and the browser holding the old document has no way to notice.

**How the library gets you there.** A `schema` on the document refuses an
undeclared path with an `UnknownFieldError` and an ill-fitting operator with a
`FieldTypeMismatchError`, both at construction. `version` gives the client one
value to compare with `!==`. `parseMatrix` fails closed on a key the document
does not carry, so a producer that moved on cannot take a page down.

## Declare the shape

The typed builder held you to `object.askedBy` while you were writing the
policy. That type stays in your editor and the document leaves without it, so a
document that travels may declare the shapes its conditions read. The schema is
optional for a producer and binding wherever it is present.

```ts file=libs/acl/README.md region=schema-binding

```

Field types are flat strings: `string`, `number`, `boolean`, `instant`, a `[]`
suffix for an array, a `?` suffix for a field that may be absent. A producer in
any language emits the whole schema by reflection.

Two checks, both at construction: a condition naming an undeclared field is
`UnknownFieldError`; an operator or comparand that does not fit the declared
type is `FieldTypeMismatchError`. The schema binds per kind, so a permission on
a kind absent from `schema.objects` is unchecked.

Priya authors `orders` against the TypeScript types and writes the schema beside
them:

```ts file=libs/acl/README.md region=typed-document

```

The two are checked independently and can disagree. A path TypeScript accepts is
still an `UnknownFieldError` when the schema does not declare it, because the
schema is binding wherever it is present.

## What `capabilities` answers on a travelling document

[Rules that read the subject](/acl/simple#write-the-acl-policy) built the shop's
report policy and read every permission out of it with one `capabilities` call.
That call works the same on a document `orders` wrote: every permission in it,
against one subject, in document order, in a single pass. It passes no object,
so a permission whose rules read `object.*` decides `unevaluable`.
[What can they do at all?](/acl/capabilities) has the contract.

## Adopt a document somebody else wrote

Every document so far is one this process built, and the storefront builds
none: `orders` does. `parseMatrix` is `hydratePolicy` with `closed: true` for
exactly that case. The key universe is untrusted, so an unknown object kind or
action fails closed and throws nothing.

```ts file=libs/acl/README.md region=foreign-matrix

```

`hydratePolicy` and `parseMatrix` treat an unknown key differently, because the
two cases are different. A key the local typed policy does not carry is a
programmer error, and `hydratePolicy` throws `UnknownPermissionError`. A key a
foreign document does not carry means the producer has moved on, and throwing
there would take a page down over a permission nobody has. [A policy from
another service](/acl/adopting) is the whole story.

## Version the document, and revalidate against it

A foreign document now evaluates without throwing. You still do not know which
foreign document arrived. `version` is a string or a number and the contract
compares it with `!==`, so a content digest or a composite such as
`orders@7+veto@41` works where a counter cannot. The document states what the
producer published. `hydratePolicy(matrix, { version })` states what this
construction site is actually running, which the producer cannot know. The
option wins, and the frozen `access.matrix` carries the winner.

## Refetch when the version moves

Compare the two version strings yourself. Nothing compares them for you: the
storefront holds the matrix it last fetched, and when the owner revokes a
permission that copy goes on granting it until somebody fetches again. The
library supplies the comparison and leaves the fetch to you:

```ts file=libs/acl/README.md region=revalidate

```

The library never pushes an update and never expires a copy. A document that
states no `version` leaves `access.version` undefined, and a `!==` over
`undefined` decides nothing. A producer who wants the contract to hold states a
version. The `orders` service never depends on the storefront's copy in any
case: it evaluates its own document before it writes anything.
