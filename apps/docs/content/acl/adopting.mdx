## Adopting another service's acl matrix with `parseMatrix`

Baize's storefront draws buttons from rules another Baize service owns. A
storefront that writes those rules a second time is right until the owner
changes one: the owner keeps refusing correctly, no alarm fires, and the button
stays hidden against a server that would have allowed the call.

The matrix is the JSON document a policy flattens to, which
[the Overview](/acl) introduces. The owner serves it, and the storefront fetches
it and hands it to `parseMatrix`:

```ts twoslash file=libs/acl/README.md region=foreign-matrix

```

Each permission carries `key`, `object`, `action` and a `rules` list, and each
rule holds a `when` list of conditions the engine ANDs. This document grants
`question.read` to a subject whose `roles` holds `bookseller`. It carries no
`question.delete`, so asking for `delete` answers `unknown-action` with
`allowed: false`. A real document holds every key its owner publishes, across
every object kind it owns, and the whole list builds one evaluator.

## Why `parseMatrix` answers where `hydratePolicy` throws

`parseMatrix(json, options?)` is `hydratePolicy(json, { ...options, closed: true })`.
The flag is written last, so no option a caller passes re-opens a foreign
document. The two differ only on a key the document does not carry:

- `hydratePolicy` throws `UnknownObjectKeyError` for an object kind the
  document lacks, and `UnknownPermissionError` for an action it lacks.
- `parseMatrix` answers `unknown-action` with `allowed: false` for both.

A malformed document throws at construction on either path.

Which path a document gets depends on where it came from. A key your own policy
lacks is a programmer error, and the throw points at the line. A key a foreign
document lacks means its owner removed the permission, or this consumer was
written against an older revision, and a throw there takes a page down over a
permission nobody holds.

Neither path grants a key it does not hold. The owning service decides again on
its own matrix when the call reaches it.

## What `parseMatrix` refuses before an acl evaluator exists

`parseMatrix` holds a foreign document to every check a local one passes, and
each refusal extends `AclConfigError`:

| Refused at construction    | When                                                       |
| -------------------------- | ---------------------------------------------------------- |
| `InvalidMatrixError`       | not an envelope, no `permissions` array, a bad `version`   |
| `InvalidPermissionError`   | a malformed `object`, `action`, `rules` or `fields`        |
| `InvalidRuleError`         | a rule whose `when` is absent or not an array              |
| `InvalidConditionError`    | an unusable shape, path, depth or operator                 |
| `KeyMismatchError`         | `key` is not exactly `` `${object}.${action}` ``           |
| `DuplicatePermissionError` | two permissions share a key                                |
| `UnknownFieldError`        | a condition names a field the document's `schema` omits    |
| `FieldTypeMismatchError`   | an operator that does not fit the `schema`'s declared type |

A document fetched over the network can fail for reasons your process cannot
fix, so keep the last document that constructed:

```ts twoslash file=libs/acl/README.md region=adopt-keep-last

```

`orders@8` lost its rule's conditions in transit, and `InvalidRuleError` refuses
it, so a damaged document never becomes a permission that grants everyone. An
unconditional grant is spelled as an empty `when`. The storefront keeps
answering from `orders@7`, and `readopt` returns the class name for an alarm.

The `schema` rows bind per object kind: a permission on a kind absent from
`schema.objects` is unchecked, and a document with no schema checks no path.
[What the acl schema refuses](/acl/advanced#what-the-acl-schema-refuses-before-an-evaluator-exists)
works one through.

## Which revision of an acl document is answering

`version` is a string or a number on the document's envelope, and it survives
the JSON round trip, so a consumer holding a document for weeks can say which
revision decided. `hydratePolicy(matrix, { version })` overrides the document's
own:

```ts twoslash file=libs/acl/README.md region=version-override

```

The document states what its owner shipped, and the option states what this
process runs, which the owner cannot know. The option wins, and the frozen
`access.matrix` carries the winner, so the version that decided is the version
that crosses a server-side rendering (SSR) boundary. A document stating no
version leaves `access.version` undefined, and a comparison against it decides
nothing.
[Refetching an acl matrix when its version moves](/acl/advanced#refetching-an-acl-matrix-when-its-version-moves)
sets out the comparison.

## What adopting an acl document does not verify

The library neither signs a document nor verifies a signature. A matrix arriving
over an unauthenticated channel is a matrix an attacker wrote, and every check
above reads the shape and says nothing about where the bytes came from.
Integrity belongs to the transport, the same way
[resolving a subject](/acl/pitfalls#the-subject-is-whatever-you-hand-it)
belongs to the session layer.
