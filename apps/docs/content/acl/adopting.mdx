**The concept.** Baize's orders service owns the rules about refunds. The
storefront has to grey out the refund button, and it has no copy of those rules
and no business writing one. So orders publishes its matrix as JSON and the
storefront adopts the document it is handed.

**What you will have.** An evaluator over a document this process did not write,
which answers for the keys the document carries and refuses every key it does
not.

**Why you would want it.** Write the rules a second time in the storefront and
they are right until orders changes one. Orders keeps refusing correctly, so no
alarm fires, and the refund button stays hidden against a server that would have
allowed the call.

**How the library gets you there.** `parseMatrix` builds an evaluator from JSON
and validates the document on the way in. It runs closed, so a key the document
does not carry answers `unknown-action` and the page stays up. A `schema` in the
document checks the paths the rules name, which is the guarantee a local
`Question` type gives you and a foreign document otherwise cannot.

A backend with its own ACL publishes its matrix as JSON; a frontend or a peer
service adopts it. `parseMatrix` is the entry point for a document this process
did not write.

## Closed mode is the whole difference

`parseMatrix(json, options?)` is `hydratePolicy(json, { closed: true, ...options })`.
One flag, and it changes what an unknown key means. Which of the two a document
gets is a question of provenance: `hydratePolicy` for your own document coming
back, `parseMatrix` for somebody else's arriving.

Ask a key the document does not carry, on the open path, and `hydratePolicy`
throws: `UnknownObjectKeyError` for an object kind it has never heard of,
`UnknownPermissionError` for an action it has not got. Ask the same key on the
closed path and `parseMatrix` answers
`{ allowed: false, reason: 'unknown-action' }` for both.

The open path treats that key as a bug and the closed path treats it as data,
and each is right about its own case. A key a local typed policy does not carry
is a programmer error: the compiler knows the whole key universe, and the throw
points at the line. A key a foreign document does not carry means the document
has moved on. The producer removed a permission, or this consumer was written
against an older revision, and a throw there takes down a page over a permission
nobody has.

Neither path grants. `unknown-action` is `allowed: false`, so the closed path
refuses the call it could not decide, and the producing service decides for
itself when the call reaches it.

## Adopting a document still validates it

Closed mode softens the _query_ and leaves the document under every check.
Everything a local matrix is held to, a foreign one is held to, at adoption
time:

| Refused at construction    | When                                                   |
| -------------------------- | ------------------------------------------------------ |
| `InvalidMatrixError`       | not an envelope, no `permissions` array, bad `version` |
| `InvalidPermissionError`   | a malformed `object`, `action`, `rules` or `fields`    |
| `InvalidRuleError`         | a rule whose `when` is absent or not an array          |
| `InvalidConditionError`    | an unusable shape, namespace, path depth, or operator  |
| `KeyMismatchError`         | `key` is not exactly `` `${object}.${action}` ``       |
| `DuplicatePermissionError` | two permissions share a key                            |

`InvalidRuleError` is the one worth understanding. `when` is required and must be
an array. A document that lost its conditions in transit (`null`, absent, a
string) fails construction, and it never becomes a permission that grants
everything. The unconditional grant is spelled as an empty `when`, which is the
form that survives a JSON round trip.

Adoption is a boundary, so handle the throw. `parseMatrix` on a payload from the
network can fail for reasons this process cannot fix. Catch `AclConfigError`,
keep the last document that constructed, and alarm. A fresh document that does
not build still leaves you a policy to serve.

## Check a foreign document against a schema

A foreign consumer has no `Question` type to check paths against. The producer's
`schema` is what carries that guarantee across the wire:


The document above declares `status` as a string and then tests it with
`contains`, which tests an array, so `hydratePolicy` refuses it with
`FieldTypeMismatchError`. A condition naming a field the schema does not declare
at all is `UnknownFieldError`, raised the same way. Without a schema,
`object.askedBt` raises nothing. That misspelling is a path that never reads, so
the permission decides `unevaluable` forever and a UI refetches forever.

`schema.objects` declares one entry per object kind, and that document declares
`question`. A producer publishing four kinds declares four, in the same schema,
and `hydratePolicy` checks the rules of each against its own entry. A permission
on an object kind absent from `schema.objects` is unchecked, so a partial schema
checks part of the document.

## Know which document acl is running

A consumer holding a document for weeks needs to say which revision decided.
`version` travels on the envelope and survives the round trip:

```ts file=libs/acl/README.md region=matrix-round-trip

```

`version` is a string or a number, compared with `!==`. `hydratePolicy(matrix, {
version })` overrides the document's own: the document states what a producer
shipped, the option states what this site is actually running. The option wins,
and the frozen `access.matrix` carries the winner, so the version that decided is
the version that crosses a server-side rendering (SSR) boundary.

A document stating no version leaves `access.version` undefined, where a `!==`
decides nothing. [Refetch when the version
moves](/acl/advanced#refetch-when-the-version-moves) is the contract; the
library supplies the comparison and nothing else.

## What adopting a document does not give you

The library does not sign a document or verify one. A matrix arriving over an
unauthenticated channel is a matrix an attacker wrote, and every construction
check above reads the shape and says nothing about where the bytes came from.
Integrity belongs to the transport, the same way [resolving a
subject](/acl/pitfalls#the-subject-is-whatever-you-hand-it) belongs to the
session layer.
