# Generating and validating

To mint a pickup code and check one a customer reads back, call `generate` and
`validate` on the instance `createToken` returns.

## Configure a token instance

Getting started built one instance on the defaults. Pass options to
`createToken` to build a different instance, and a gift card code wants more
characters than a pickup code:

```ts twoslash file=libs/token/README.md region=instances

```

`giftCard` draws 15 random characters, 75 bits, and appends a check character.
Four chunks of four take three hyphens, so its `value` is 19 characters long.

| Option       | Default  | Meaning                                             |
| ------------ | -------- | --------------------------------------------------- |
| `length`     | `8`      | total characters, the check character included      |
| `chunkSize`  | `4`      | characters between separators; must divide `length` |
| `separator`  | `'-'`    | between chunks, and between a prefix and the code   |
| `dictionary` | 32 chars | the alphabet a code draws from                      |

`createToken` checks every option once, at construction, and nothing at use. An
instance you hold cannot mint a code its own `validate` rejects.

### When token refuses a shape

`createToken` throws `InvalidShapeError` when `length`, `chunkSize` and
`separator` cannot describe a code. The error carries a `reason` and the three
options as resolved, defaults included. `refusal` below returns that error, or
`undefined` when the options are accepted:

```ts twoslash file=libs/token/README.md region=shape-errors

```

A `chunkSize` of 4 does not divide a `length` of 10, so the last chunk would be
shorter than the rest, and `reason` is `'chunk-size-indivisible'`. Set
`chunkSize` equal to `length` for an unchunked code. A `separator` of `'a'` is
refused because `a` is in the dictionary and `validate` could not strip it. Its
error's `length` is the default 8, which you did not pass: the error carries all
three options because the value to change is not always the one `reason` names.

## Mint a code with token's `generate`

`generate` returns the code in two forms, `value` and `body`, its check
character as `check`, and the prefix you passed:

```ts twoslash file=libs/token/README.md region=generate

```

`generate` draws `length - 1` characters from `crypto.getRandomValues` with
`byte % n`, where `n` is the number of characters in the dictionary, which the
instance reports as `token.n`. `createToken` requires `n` to divide 256, so every
character is equally likely and `generate` never discards a byte to draw again.
The check character is appended, then the whole code is chunked. `body` is the
random part alone, before the check character and before chunking.

`generate` never retries and never checks for collisions.

Mint a pickup code below. The shape control is the `length` and `chunkSize`
pair, and the alphabet control is the default 32 characters against the 16 of
hexadecimal, `0123456789abcdef`. Every option either control offers is a
configuration `createToken` accepts. The caption reports the code's random bits
and the number of issued codes at which two matching codes become even odds.

## Check a code with token's `validate`

`validate` returns `valid: true` and the `body`, or `valid: false` and a
`reason`:

```ts twoslash file=libs/token/README.md region=validate

```

<Probe package="token" probe="validate" />

| `reason`           | Meaning                                                          |
| ------------------ | ---------------------------------------------------------------- |
| `outside-alphabet` | a character not in the dictionary, after separators are stripped |
| `wrong-length`     | the code is not `length` characters long                         |
| `check-failed`     | the last character does not check out against the ones before it |

`validate` checks in that order and reports the first failure. It returns a
reason and never throws, and it has no side effects, so it can run on every
request ahead of the lookup.

## Look up an order from a token code

Narrow on `valid` to reach `body`, and look the order up by it:

```ts twoslash file=libs/token/README.md region=lookup

```

`body` is the code without its check character, case-folded, so `A4KP9MXA`
finds the same row as `a4kp-9mxa`. A freshly minted code passes `validate` and
finds no order, because `valid: true` means the code is well formed and says
nothing about whether it was issued.

## Token separators are presentation

`generate` chunks `value` and leaves `body` unchunked. `validate` strips the
separator and folds case first, so a code typed without the separator, grouped
differently, or read off a card in capitals still validates:

```ts twoslash file=libs/token/README.md region=separators

```

A shorter code with a space between two chunks of three reads aloud as two
words. `validate` strips the separator its own instance was built with, so
`counterCode` strips the space:

```ts twoslash file=libs/token/README.md region=spoken

```

The separator must share no character with the dictionary, or stripping it
would remove part of the code. `createToken` refuses one that does with
`reason: 'separator-in-dictionary'`.

## The token prefix sits outside the check character

`generate({ prefix: 'ORD' })` writes `ORD` and the separator ahead of the code,
and the check character covers the code alone:

```ts twoslash file=libs/token/README.md region=prefix

```

`validate` reads a leading `ORD-` as three more characters of the code, and
`ORD` contains `o`, which the dictionary excludes as confusable. Folding the
prefix into the check would require every prefix character to be in the
dictionary. Comparing the prefix is a literal string match, which is what
`value.startsWith('ORD-')` does. `generate` draws the whole body at random, so
no option brings a prefix under the check character.

## What token's check character catches

`@evanion/luhn` computes the check character with the Luhn algorithm, the
check-digit scheme on a credit card number, generalised to any even-sized
dictionary. It catches two kinds of mistake:

- Every single-character substitution, at every position, including the check
  character itself.
- Every swap of two adjacent characters, except one pair: the first and last
  entries of the dictionary, `0` and `z` by default.

```ts twoslash file=libs/token/README.md region=check-catches

```

`a4kp-9mza` substitutes `z` for `x`, and `a4pk-9mxa` swaps `k` and `p`. Both
fail. `b0zg-7kqb` and `bz0g-7kqb` differ by a swap of `0` and `z`, and both
pass.

The blind spot comes from Luhn's doubling step and holds for every
even-sized dictionary: the first and last entries swap undetected, the way `0`
and `9` do on a card number.

Luhn catches nothing else. A code invented from scratch passes one time in 32.
