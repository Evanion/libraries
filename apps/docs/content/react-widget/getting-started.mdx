# Getting started

By the end of this page `Widgets` renders a Baize listing from one item, and you
have the HTML React wrote for it.

## Before you install react-widget

- React 18 or 19, the only peer dependency.
- Node 20 or newer.
- An ESM project, since the package ships no CommonJS build.
- TypeScript 5.0 or newer for the compile-time check, because the published
  types use a `const` type parameter. The components render without TypeScript.

## Install react-widget

Pick the line for your package manager.

```bash
npm install @evanion/react-widget
```

```bash
yarn add @evanion/react-widget
```

```bash
pnpm add @evanion/react-widget
```

The item model comes from `@evanion/widget`, which the package pins exactly and
re-exports, so this one install is enough.

## Render one react-widget region

`createWidgets` takes `components`, the component map from a widget type to the
component that draws it, and returns `Widgets`. `Widgets` takes `items` and
renders each item's component with its `props`. `renderToStaticMarkup`, from
`react-dom/server`, returns the HTML React wrote:

```tsx twoslash file=libs/react-widget/README.md region=region-markup

```

`Widgets` wrapped the region in a `<section>`, its default wrapper, and put the
widget in a `<div>` carrying the item's `id` and `type` as `data-widget-id` and
`data-widget-type`. `ListingCard` rendered only the `<h3>`. If your own page
prints the same shape, react-widget is working in your project.

`as const` keeps `type` the literal `'listing'`. Without it TypeScript widens
the type to `string` and `Widgets` refuses the array, because `string` is not a
key of the component map.

Call `createWidgets` once, at module scope. Each call returns a new `Widgets`
component, so a call inside a component remounts the region on every render.

## Now that a region renders, check the items you write

[Writing and checking items](/react-widget/examples) types an item array held in
a variable, nests items under a widget, and checks a CMS payload before
