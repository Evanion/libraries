# API reference

`@evanion/react-widget` exports one factory, two default chrome components and
the types they use. It also re-exports the item model from `@evanion/widget`,
so one install covers both; the entries from [`validateItems`](#validateitems)
on are those re-exports.

## `createWidgets(config)`

`createWidgets` takes a component map and optional chrome, and returns the
`Widgets` component that renders items against them.

```tsx signature
function createWidgets<
  const C extends WidgetRegistry<AnyWidgetComponent>,
  M = WidgetMeta,
>(
  config: WidgetsConfig<C, M>,
): {
  Widgets: MemoExoticComponent<
    (props: WidgetsProps<C, M>) => JSX.Element | null
  >;
  defineItems: (items: WidgetItem<C, M>[]) => WidgetItem<C, M>[];
  validateItems: (
    items: unknown,
    required?: Record<string, string[]>,
  ) => WidgetProblem[];
};
```

| Returned        | What it does                                                                                |
| --------------- | ------------------------------------------------------------------------------------------- |
| `Widgets`       | renders an item array against the map; its props are [`WidgetsProps`](#widgetsprops)        |
| `defineItems`   | returns the array it is handed, typed `WidgetItem<C, M>[]`, for an array held in a variable |
| `validateItems` | [`validateItems`](#validateitems) with the map's keys as the known types                    |

`C` is inferred from `config.components` and `M` from `config.chrome.item`.
Pass neither by hand. TypeScript infers no type argument once one is named, so
naming `M` means writing `C` out as well. Call
`createWidgets` once, at module scope, because each call returns a new `Widgets`
and a call inside a component remounts the region on every render.


## `WidgetsConfig`

`WidgetsConfig<C, M>` is the argument to `createWidgets`.

```ts signature
interface WidgetsConfig<
  C extends WidgetRegistry<AnyWidgetComponent>,
  M = WidgetMeta,
> {
  components: C;
  chrome?: WidgetsChrome<M>;
}
```

`components` is the component map, and its shape drives inference for the
whole set. `chrome` is the factory's [`WidgetsChrome`](#widgetschrome).

## `WidgetsProps`

`WidgetsProps<C, M>` is the props of the `Widgets` component `createWidgets`
returns.

| Prop         | Type                      | Meaning                                                   |
| ------------ | ------------------------- | --------------------------------------------------------- |
| `items`      | `WidgetItem<C, M>[]`      | the items to render                                       |
| `components` | `Partial<C>`              | per-instance components, merged over the factory's map    |
| `chrome`     | `WidgetsChrome<M>`        | per-instance chrome, resolved field by field              |
| `ctx`        | `Record<string, unknown>` | page-level data, passed to every widget as its `ctx` prop |

`Widgets` is wrapped in `memo()`. An `items` prop that is not an array renders
`null` and warns in development. The renderer passes `ctx` after the item's
props, so its value reaches the widget over anything an item carries under that
name, `undefined` included.

## `WidgetsChrome`

`WidgetsChrome<M>` is the markup a widget set draws around its region and its
widgets, and the Suspense behaviour between them.

```ts signature
interface WidgetsChrome<M = WidgetMeta> {
  wrapper?: WidgetsWrapperComponent;
  item?: WidgetItemComponent<M>;
  suspense?: WidgetSuspenseMode;
  suspenseFallback?: ReactNode;
}
```

| Field              | Default                             | What it is                                               |
| ------------------ | ----------------------------------- | -------------------------------------------------------- |
| `wrapper`          | [`DefaultWrapper`](#defaultwrapper) | rendered around the whole region                         |
| `item`             | [`DefaultItem`](#defaultitem)       | rendered around each widget; its annotation types `meta` |
| `suspense`         | `'per-item'`                        | whether each widget gets its own `<Suspense>`            |
| `suspenseFallback` | nothing                             | rendered while a widget suspends                         |

## `WidgetSuspenseMode`

`WidgetSuspenseMode` is `'per-item' | 'none'`, the values `chrome.suspense`
takes.

```ts signature
type WidgetSuspenseMode = 'per-item' | 'none';
```

`'per-item'` gives each widget its own boundary, so one slow widget does not
hold up its siblings. `'none'` gives the region no boundary, for widgets that
never suspend. React's streaming renderer then writes every item into the shell,
the first HTML it sends, and leaves none to a script that moves it into place
later.
[A synchronous region](/react-widget/advanced#a-synchronous-region-chromesuspense-none)
carries the measurement. No mode puts one boundary around the whole region,
because React sends a large unfinished boundary after the shell, every item at
once. To get one boundary anyway, wrap `<Widgets>` in `<Suspense>` and set
`'none'`.

## `WidgetItemComponent`

`WidgetItemComponent<M>` is the type of `chrome.item`, the component rendered
around each widget.

```ts signature
type WidgetItemComponent<M = WidgetMeta> = ComponentType<{
  children?: ReactNode;
  'data-widget-id': string;
  'data-widget-type': string;
  meta?: M;
}>;
```

Annotating `chrome.item` with it is what types the whole set's `meta`:
`createWidgets` infers `M` from the annotation.


## `WidgetsWrapperComponent`

`WidgetsWrapperComponent` is the type of `chrome.wrapper`, the component
rendered around the whole region.

```ts signature
type WidgetsWrapperComponent = ComponentType<{
  children?: ReactNode;
  items?: readonly RenderableWidgetItem[];
}>;
```

`items` and `children` are aligned by position. An item the renderer skipped is
dropped from both, so index `i` of one is index `i` of the other, and a wrapper
can group, size or window by item. A child element's own props are the item's
`id`, `type` and `meta`, and the item's `props` sit on the widget element nested
inside it. `items` hands the wrapper each whole item as data, top-level items
only.

If your wrapper spreads its props onto a DOM element, remove `items` first, the
way `DefaultWrapper` does, or React warns about an unknown attribute.

## `DefaultWrapper`

`DefaultWrapper` is the default `chrome.wrapper`: a `<section>` carrying every
prop it is handed except `items`.

```tsx signature
function DefaultWrapper(
  props: HTMLProps<HTMLDivElement> & {
    items?: readonly RenderableWidgetItem[];
  },
): JSX.Element;
```

A `<section>` with an accessible name maps to the `region` landmark role, so an
`aria-label` makes the region reachable by landmark navigation.


## `DefaultItem`

`DefaultItem` is the default `chrome.item`: a `<div>` carrying `data-widget-id`,
`data-widget-type` and every other prop it is handed except `meta`.

```tsx signature
function DefaultItem(
  props: HTMLProps<HTMLDivElement> & { meta?: Record<string, unknown> },
): JSX.Element;
```

CMS click-to-edit overlays, analytics and end-to-end selectors key off the two
`data-widget-*` attributes. `meta` is dropped because React warns about an
unknown attribute on every key of it that reaches the DOM. Neither default
carries a Suspense boundary or an error boundary; the Suspense boundary lives in
the renderer.

## `WidgetItem`

`WidgetItem<C, M>` is the checked item, a union with one member per key of the
component map.

```ts signature
type WidgetItem<
  C extends WidgetRegistry<AnyWidgetComponent>,
  M = WidgetMeta,
> = {
  [K in keyof C & string]: {
    id: string;
    type: K;
    props: WidgetDataProps<C[K]>;
    meta?: M;
    children?: WidgetChildren<C, K, M>;
  };
}[keyof C & string];
```

`type` narrows `props` to that component's props. `M` is one vocabulary per set,
because one chrome reads every item's `meta`. `WidgetItem` widens to
[`AnyWidgetItem`](#anywidgetitem). `satisfies WidgetItem<typeof components>[]`
checks an array the way `defineItems` does.

```tsx twoslash file=libs/react-widget/README.md region=typed-items

```

## `WidgetDataProps`

`WidgetDataProps<C>` is the `props` an item carries for component `C`: its
props less `children` and `ctx`, which the renderer supplies.

```ts signature
type WidgetDataProps<C extends AnyWidgetComponent> = [
  keyof Omit<ComponentProps<C>, 'children' | 'ctx'>,
] extends [never]
  ? Record<string, never>
  : Omit<ComponentProps<C>, 'children' | 'ctx'>;
```

A component with no props left resolves to `Record<string, never>`, which admits
`props: {}` and rejects any key. Typed `{}`, the same `props` admits every key,
because TypeScript assigns any object to `{}` with no excess-property check.

## `WidgetChildren`

`WidgetChildren<C, K, M>` is the type of an item's `children`:
`WidgetItem<C, M>[]` when component `C[K]` declares `children`, and `never`
when it does not.

```ts signature
type WidgetChildren<
  C extends WidgetRegistry<AnyWidgetComponent>,
  K extends keyof C,
  M = WidgetMeta,
> = 'children' extends keyof ComponentProps<C[K]> ? WidgetItem<C, M>[] : never;
```

The `never` makes nesting under a widget that renders no `children` a compile
error. Without it, the renderer drops that subtree and logs nothing.

```tsx twoslash file=libs/react-widget/README.md region=nesting

```

## `RenderableWidgetItem`

`RenderableWidgetItem` is the item with its types erased, which the renderer and
`chrome.wrapper`'s `items` use.

```ts signature
interface RenderableWidgetItem {
  id: string;
  type: string;
  props: Record<string, unknown>;
  meta?: Record<string, unknown>;
  children?: RenderableWidgetItem[];
}
```

The renderer widens the checked union to this once, between the public props
and the render loop. Spreading the union onto a component directly makes
TypeScript fail with TS2590, "union type that is too complex to represent".

## `AnyWidgetComponent`

`AnyWidgetComponent` is `ComponentType<any>`, the constraint a component map's
values meet.

```ts signature
type AnyWidgetComponent = ComponentType<any>;
```

`ComponentType<unknown>` rejects a component with concrete props, because
component props are contravariant. Inference is unaffected:
`ComponentProps<C[K]>` resolves against the component that was passed.

## `validateItems`

`validateItems` walks a payload and returns every problem it finds, re-exported
unchanged from `@evanion/widget`.

```ts twoslash file=libs/react-widget/README.md region=validate-payload

```

The standalone export takes a list of type names or a registry, so a webhook
or a CI script checks a payload without importing a React component. The bound
form that `createWidgets` returns takes no names. Both take an optional
`required` map from a widget type to the props that must be present and
non-blank. Neither checks a prop's type against a component; `WidgetItem` does
that at compile time.
[The core's entry](/widget/api#validateitems) carries the signature, and
[What it reports](/widget/problems) every message.

## `defineWidgets`

`defineWidgets` returns the component map it is handed, typed as the literal
object, re-exported from `@evanion/widget`.

```ts twoslash file=libs/react-widget/README.md region=define-widgets

```

One map declared on its own types `WidgetItem`, feeds `createWidgets` and
feeds the standalone `validateItems`, so the `raffle` type fails the compile and
the runtime check alike. Annotating that map as `WidgetRegistry` widens its keys
to `string`, and `defineWidgets` keeps them literal. A map declared with no
annotation keeps them literal too, so the call is optional in this package.
[The core's entry](/widget/api#definewidgets) carries the signature.

## `ERROR_MESSAGES`

`ERROR_MESSAGES` is the text `Widgets` warns with in development, re-exported
from `@evanion/widget`.

`MALFORMED_ITEMS` reports an `items` prop that is not an array, and `Widgets`
renders nothing. `MALFORMED_CHILDREN` reports nested items that are not an
array, and `Widgets` renders the widget without them. The rest report an item
`Widgets` skipped. A message about one item names its `id`, and `Widgets` logs
each distinct message once per process, so a second bad item still gets its own
warning.
[The core's entry](/widget/api#error_messages) lists every key.

## `VALIDATION_MESSAGES`

`VALIDATION_MESSAGES` is the text `validateItems` reports, re-exported from
`@evanion/widget`, so a caller can group or translate problems without matching
on prose. [The core's entry](/widget/api#validation_messages) lists every key.

## `AnyWidgetItem`

`AnyWidgetItem` is the loose item, from `@evanion/widget`, for data built before
a component map exists: a CMS payload, a fixture, a network response. It checks
nothing against a component; `WidgetItem` widens to it.
[The core's entry](/widget/api#anywidgetitem) carries the interface.

## `WidgetRegistry`

`WidgetRegistry<T>` is `Record<string, T>`, from `@evanion/widget`. This package
instantiates it as `WidgetRegistry<AnyWidgetComponent>`, its component map type.
[The core's entry](/widget/api#widgetregistry) carries the rest.

## `WidgetMeta`

`WidgetMeta` is `Record<string, unknown>`, from `@evanion/widget`: the `meta`
type of a set whose `chrome.item` declares none, and the default for `M` on this
page. [The core's entry](/widget/api#widgetmeta) carries the rest.

## `WidgetProblem`

`WidgetProblem` is one line of the list `validateItems` returns, from
`@evanion/widget`: an `index`, the item's `id` and `type`, and a `message`.
[The core's entry](/widget/api#widgetproblem) says what each field holds.

## `KnownWidgetTypes`

`KnownWidgetTypes` is `WidgetRegistry | readonly string[]`, from
`@evanion/widget`: the known types `validateItems` takes, as a registry or a
plain list of names. [The core's entry](/widget/api#knownwidgettypes) carries
the rest.

## Migrating react-widget from 0.2.x

The item shape, the props and the data are unchanged. Three type names moved to
`@evanion/widget` and are re-exported here under the names the whole family
uses.

| Was                  | Now                                  |
| -------------------- | ------------------------------------ |
| `WidgetComponentMap` | `WidgetRegistry<AnyWidgetComponent>` |
| `WidgetItemProblem`  | `WidgetProblem`                      |
| `WidgetProps`        | `AnyWidgetItem`                      |

`chrome.wrapper` now receives an `items` prop beside its children. It is
optional, so an existing wrapper keeps compiling. If your wrapper spreads its
props onto a DOM element, remove `items` first.

## Migrating react-widget from 0.1.x

0.2.0 removed everything that cannot exist under React's `react-server` export
condition.

| Removed                                                                                                         | Replacement                                                                  |
| --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `'use client'`                                                                                                  | none needed; the package is importable from a Server Component               |
| `WidgetsProvider`, `useWidgets`, `WidgetsConfig.context`                                                        | call `createWidgets` once at module scope                                    |
| the injected `Output` prop and `<Output/>`                                                                      | read `children`                                                              |
| `WidgetOutputProps`                                                                                             | none needed                                                                  |
| the default `WidgetErrorBoundary`                                                                               | your own boundary in a custom `chrome.item`, in your own `'use client'` file |
| `DEFAULT_STYLES.LOADING`                                                                                        | `chrome.suspenseFallback`                                                    |
| `DEFAULT_STYLES.ERROR`, `ERROR_MESSAGES.WIDGET_ERROR`, `ERROR_MESSAGES.WIDGET_FAILED`, `ERROR_MESSAGES.LOADING` | removed with the boundary that used them                                     |

`renderWidget` and `NestedWidgetsContext` are no longer exported. The nesting
mechanism is internal, so a change to it is not a breaking release.
