# Playground

## A Baize page as one react-widget region

The counter's view of Baize below is one `Widgets` region: a figures row and two
boards, composed from the seven items printed under it. Every block is a
component written once, and the items decide which blocks the page has, what
sits inside what and how wide each one is.

Move an item with the controls in the gutter and the page is composed again.
Moving `counter` above `week` carries two boards and three figures as one block,
which a nested item list expresses and a flat `items.map` cannot. Moving
`tables` past `reprints` swaps the wide side, because `meta.span` belongs to the
item and travels with it.

## Edit a react-widget region in the browser

The editors below run the published `@evanion/react-widget` build. Each snippet
builds a component map with `createWidgets`, writes an item array, and ends in
`render(<Widgets items={items} />)`.

<PlaygroundExamples />

react-live evaluates each snippet in `noInline` mode against a fixed scope, with
no module resolution. An `import` line, or a name outside the scope, shows as a
runtime error in the preview pane.

| In scope                                          | What it is                                                    |
| ------------------------------------------------- | ------------------------------------------------------------- |
| `createWidgets`                                   | the package's own export                                      |
| `React`                                           | React, for `React.ReactNode` and the rest of its API          |
| `useState`, `useEffect`, `useMemo`, `useCallback` | React's hooks, for a widget with client state                 |
| `render`                                          | takes the element the preview shows; every snippet ends in it |

## What the react-widget playground cannot show

Everything runs in the browser, so no widget here is a Server Component. An
async widget and the streaming behaviour of
[`chrome.suspense`](/react-widget/advanced) cannot be demonstrated, and
`chrome.suspenseFallback` shows only for a widget that suspends on the client.

Type errors do not show. The snippets are strings that nothing type-checks, so
an unknown `type`, a mistyped prop and `children` under a widget that renders
none all run without complaint. What the editor shows is the rendered output,
the chrome composing around it, and the console warning when an item names a
type the map does not have.

## Things to change in a react-widget snippet

- A `type` to one the component map does not hold. The item disappears and the
  browser console carries one warning naming its `id`.
- A `props` key. Nothing checks it at runtime, and the widget receives
  `undefined`, which is the gap the type checker closes outside this editor.
- The `chrome.wrapper`, to see how the region container composes.
- An item's position in the array. `id` is the React key, so a reorder moves the
  existing element and keeps its state.
