## A Baize page as one react-widget region

The demo below is one `Widgets` region: the page Baize's staff read for the
week. It holds two top-level items of type `columns`, a row that lays its nested
items side by side. The item with id `week` nests three `metric` items, each one
figure. The item with id `counter`, the shop counter's row, nests a `tables`
item and a `reprints` item, each a titled panel around a data table. The
`tables` item carries `meta.span: 2`, so the item chrome gives it two columns.
All seven items are printed under the page.

Move an item with the arrows beside the line that opens it in that listing, and
`Widgets` renders the page again. Moving `counter` above `week` swaps the two
rows, and each row takes its nested items with it. Moving `tables` past
`reprints` puts the two-column panel on the other side, because `meta.span`
belongs to the item and travels with it.

The published `Widgets` renders this demo from the items printed under it, and
nothing is simulated.

## Edit a react-widget region in the browser

The editors below run the published `@evanion/react-widget` build. Each snippet
builds a component map with `createWidgets`, writes an item array, and ends in
`render(<Widgets items={items} />)`.

<PlaygroundExamples />

The editor runs each snippet against a fixed scope, with no module resolution.
An `import` line, or a name outside the scope, shows as a runtime error in the
preview pane.

| In scope                                          | What it is                                                    |
| ------------------------------------------------- | ------------------------------------------------------------- |
| `createWidgets`                                   | the package's own export                                      |
| `React`                                           | React, for `React.ReactNode` and the rest of its API          |
| `useState`, `useEffect`, `useMemo`, `useCallback` | React's hooks, for a widget with client state                 |
| `render`                                          | takes the element the preview shows; every snippet ends in it |

## What the react-widget playground cannot show

Everything runs in the browser, so no widget here is a Server Component. An
async widget and the streaming behaviour of
[`chrome.suspense`](/react-widget/advanced) cannot be demonstrated, and
`chrome.suspenseFallback` shows only for a widget that suspends on the client.

Type errors do not show. The snippets are strings that nothing type-checks, so
an unknown `type`, a mistyped prop and `children` under a widget that renders
none all run without complaint. The console stays quiet too: this site is a
production build, and `Widgets` warns only in development. The preview shows
only the HTML `Widgets` rendered, inside the chrome the snippet passed.

## Things to change in a react-widget snippet

- A `type` to one the component map does not hold. The item disappears and the
  rest of the region renders.
- A `props` key. Nothing checks it at runtime, and the widget receives
  `undefined`, which is the gap the type checker closes outside this editor.
- The `chrome.wrapper`. The region's container changes and every widget stays
  inside it.
- An item's position in the array. The region renders the items in the new
  order.
