## What the numbers cover

The scope is the eleven packages `nx.json`'s `release.projects` matches, which
is everything under `libs/`. The build resolves that pattern through the Nx
project graph, so a twelfth library joins these counts the day it is released
and nobody edits this page.

The demo apps are off the counts, and that is a real omission. `apps/shop-api`
and `apps/storefront` run the policy engine through a NestJS service and an
Astro renderer, and one of them holds an end-to-end file that exercises a whole
request. A reader told that `@evanion/acl` carries a thousand tests has not
been told that an application enforcing a policy through it also passes.

## The documentation's examples are executed

<DocExamples />

A fenced block in a package README is collected by that package's own vitest
run, so the example a reader copies is an example that ran. A `// -> value`
line inside one becomes an assertion before the block executes. A `twoslash`
fence in this site's content is compiled against the package's built `dist/`
under Twoslash's strict defaults, and a fence declaring an error code fails
when the compiler stops producing it. A `file=… region=…` block, such as the
one below and the thirty-six further down, is filled from the named region of
the file the tests run.

```ts twoslash file=libs/acl/README.md region=quick-start

```

Run `npx nx test @evanion/acl` to watch the README's own blocks execute.

## The security register, and every case in it

`libs/acl/SECURITY.md` names thirty-six classes of attack and puts each in one
of three tiers. The tier decides what a passing test under it may claim: tier 1
says the library prevents the class, tier 2 says the library supplies the
primitive and the consumer has to use it, and tier 3 says the class is
structurally out of scope. A tier 3 entry carries no passing defence, because a
passing test there would imply one.

## What this page cannot prove

**A test suite covers the cases somebody thought of.** Each of the
thirty-six register entries is a class somebody named. The thirty-seventh is in
no register, in no suite, and nothing on this page would look different if it
existed. SEC-019 draws generated writes from a seeded generator, which is the
narrowest exception and still generates within a shape somebody chose, against
a property somebody stated.

**The guards check shape, and never correctness.** The export-coverage check
refuses a published export with no example, and it has no opinion about whether
the example is any good or whether the export should exist. The twoslash check
proves a fence compiles, which is a different claim from the fence being the
right way to use the API.

<Guards />

Both allowance files default an unlisted entry to zero, so the backlog above
cannot grow. It has not been paid down either, and a guard quoted without its
own backlog is the marketing a sceptic came expecting.

**The register describes one library, at one layer.** Eight entries are tier 3,
and [the security contract](/acl/security) is what they mean: in a browser the
control disappears and the request it would have sent does not. A reader taking
this page as evidence that an application using `@evanion/acl` is secure has
drawn a conclusion the register's own tier 3 refutes.

**Nothing here is an audit.** No third party has reviewed this code. Projects
of comparable subject link a sponsored external audit or publish an audit
report in the repository, and this project has neither.

**The numbers describe one commit.** The provenance line at the top names it.
If the deploy stops running the suite, that commit stops moving with the site,
and a reader can see the mismatch from this page.
