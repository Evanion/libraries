# What coverage measures

Vitest's `v8` coverage provider counts the code a test run executed, from what
Node's V8 engine records. It counts nothing about assertions, so a suite that
imports every module and asserts nothing still scores high.

## Four coverage metrics per library

Every `@evanion/*` library's `vite.config.ts` turns coverage on for each test
run, and `@evanion/acl`'s block reads:

```ts file=libs/acl/vite.config.ts region=coverage

```

The `json-summary` reporter writes four percentages to `coverage-summary.json`
in the `reportsDirectory` above. The table gives each library all four, with the
count covered over the count the report found:

- Statements: the statements the run executed.
- Branches: the paths through each `if`, `else`, ternary, `switch` case and
  short-circuit operator that the run took.
- Functions: the functions the run called at least once.
- Lines: the lines of code the run executed.

Read statements beside branches: a statement percentage well above the branch
percentage means lines ran while one path through their conditions never did.

<CoverageTable />

The table leaves out a workspace average and every file a run did not load:

- An average would mislead. Several libraries sit at 100% on all four metrics,
  and `@evanion/acl`, which holds more test cases than any other library, sits
  lower. An average of their percentages gives a library of a few dozen
  statements the same weight as `@evanion/acl`.
- The report omits a file no test imported, and the Files in the report column
  counts the files the run loaded. So 98% there means 98% of what the run
  loaded, and the library as a whole can sit lower.

## What is not built from these numbers

This site leaves four uses of the `@evanion/*` coverage figures out:

- No coverage badge appears on this site or in any README. A badge shows the
  percentage with no qualifier and no case beside it. `@evanion/acl`'s
  percentage covers about a thousand executable lines of pure functions over
  frozen JSON, with no network code and no code that parses bytes off the wire.
  Beside a badge from a project that has both, the higher acl number would
  suggest the stronger suite.
- No trend line is drawn, because a stored series needs either a committed file
  that goes stale or a database this static site cannot read.
- No coverage threshold fails a build. Once a build fails under a minimum, the
  next test someone writes executes a line to clear it and asserts nothing. The
  build gates the register: `tools/repo-checks/src/security-register.test.ts`
  fails when a [register](/testing/security-register) entry and its test come
  apart.
- No package page carries a percentage. A reader on `/luhn`, the page of the
  check-digit library `@evanion/luhn`, who sees 100% has learned that every
  statement of a small library ran, and nothing about what its tests assert.
