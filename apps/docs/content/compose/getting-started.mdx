## Before you install compose

- React 18 or 19, the only dependency the package has.
- Node 20 or newer.
- An ESM project. A CommonJS project needs Node 20.19, 22.12 or newer, whose
  `require()` loads ES modules. An older `require()` fails with
  `ERR_REQUIRE_ESM`.
- TypeScript 5.0 or newer for the compile error on each entry, because the
  published types use a `const` type parameter. The component runs without
  TypeScript.

## Install compose

Pick the line for your package manager.

```bash
npm install @evanion/compose
```

```bash
yarn add @evanion/compose
```

```bash
pnpm add @evanion/compose
```

## Compose the shop's providers

`ComposeProvider` takes two props: `providers`, the array, and `children`, what
the array wraps. Baize's root holds three providers and renders them around the
page it is given. Import `ComposeProvider` and `provider` from
`@evanion/compose`. `renderToStaticMarkup`, from `react-dom/server`, turns `Shop`
into the HTML string `markup`:

```tsx twoslash file=libs/compose/README.md region=first-shop

```

`CartProvider` and `CurrencyProvider` go in as bare components, because neither
declares a prop beyond `children`. `ThemeProvider` needs a `theme`, so
`provider(ThemeProvider, { theme: 'dark' })` pairs it with its props. No entry
passes `children`: `ComposeProvider` fills each one with the next entry down,
and the last entry gets `Shop`'s own children.

`markup` is the HTML React wrote for `Shop`. The cart's `div` is outermost and
the page is innermost, which is the array read from the top. In your app, render
`Shop` where the nested providers sit today, around your routes. A context
provider renders no element of its own, so check the order in the Components tab
of React DevTools: each provider sits inside the one before it in the array.
