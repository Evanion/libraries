# API reference

Everything `@evanion/compose` exports, one heading per symbol.

## `ComposeProvider`

```signature
function ComposeProvider<const T extends ProviderArray>(
  props: ComposeProviderProps<T>,
): React.ReactElement;
```

| Prop        | Type                    | Notes                                        |
| ----------- | ----------------------- | -------------------------------------------- |
| `providers` | `ValidatedProviders<T>` | Providers to compose; the first is outermost |
| `children`  | `React.ReactNode`       | Wrapped by every provider                    |

A generic function rather than a `React.FC`. The `const T` parameter is what
infers the array as a literal tuple, and a `React.FC` annotation would widen it
and take the per-entry checking with it.

`ComposeProvider` renders a fragment containing the nested tree. An entry that
is a bare component is rendered with no props; a tuple entry is rendered with
its second element spread as props:

```tsx twoslash file=libs/compose/examples/shop.tsx region=stack

```

`ComposeProvider` throws `TypeError` when `providers` is not an array, and when
a `components` prop is supplied without `providers`. In development it also
warns once on an empty array.

## `provider(component, props)`

```signature
function provider<T extends AnyComponent, P extends PropsWithoutChildren<T>>(
  component: T,
  props: P & Record<Exclude<keyof P, keyof PropsWithoutChildren<T>>, never>,
): readonly [T, PropsWithoutChildren<T>];
```

`provider` returns the `[component, props]` tuple, and nothing else happens at
runtime. `T` is inferred from `component` in the same expression, so `props` is
checked and completed against that component. It is one of three ways to write
an entry, beside a bare component and a plain tuple:

```tsx twoslash file=libs/compose/examples/entries.tsx region=entries

```

The `Record<Exclude<…>, never>` intersection is what rejects an excess key.
Plain assignability would not: TypeScript's excess-property check fires on a
fresh object literal and is skipped for a props object that arrives through a
variable.

## `AnyComponent`

```signature
type AnyComponent = ComponentType<any>;
```

For use in a generic constraint. `ComponentType<unknown>` would reject a
component with concrete props, because component props are contravariant: a
`ComponentType<{ theme: string }>` is not assignable to a
`ComponentType<unknown>`. TypeScript has no "some component, props unknown"
type for this position. Inference is unaffected: every check in
`@evanion/compose` resolves against the component actually passed.

## `PropsWithoutChildren<T>`

```signature
type PropsWithoutChildren<T extends AnyComponent> = Omit<
  ComponentProps<T>,
  'children'
>;
```

What an entry has to supply. `children` is excluded because `ComposeProvider`
provides it: the next provider down, or the caller's own children at the
innermost level.

## `Provider`

```signature
type Provider = AnyComponent | readonly [AnyComponent, unknown];
```

One entry of the array: a component, or a component paired with its props.

## `ProviderArray`

```signature
type ProviderArray = readonly Provider[];
```

`readonly`, so an array written `as const` is assignable. A value annotated
with this type has lost its length and the type at each position, so
`ComposeProvider` checks none of its entries.
[Wrapping compose in your own component](/compose/type-checking#wrapping-compose-in-your-own-component)
shows the wrapper that keeps the check.

## `ValidateProvider<T>`

Checks one entry. A valid entry maps to itself. A failing one maps to
`ComposeError<"message">`, a type naming what is wrong, except for a missing or
mistyped prop value, which maps to the shape the entry should have had.
[Reading a compose error](/compose/type-checking#reading-a-compose-error) lists
the messages.

## `ValidateProviders<T>`

`ValidateProvider` applied across a tuple, positions preserved, so the error
points at the offending element.

## `ValidatedProviders<T>`

```signature
type ValidatedProviders<T extends ProviderArray> = number extends T['length']
  ? ProviderArray
  : T & ValidateProviders<T>;
```

The type of the `providers` prop. `number extends T['length']` is the standard
tuple-versus-array test, and gating on it does two things:

- A widened `ProviderArray` passes through unchecked. Compared against the shape
  each entry should have had, it could never match.
- A non-tuple array is never compared member by member. That comparison makes
  TypeScript walk `every`, `map` and `reduce` and report the variance of a
  predicate before it mentions the real mismatch.

`T` stays in the intersection because a bare `ValidateProviders<T>` is a
non-homomorphic mapped type and therefore not an inference site: TypeScript
would fall back to the constraint and check nothing.

## `ComposeProviderProps<T>`

```signature
interface ComposeProviderProps<T extends ProviderArray = ProviderArray> {
  providers: ValidatedProviders<T>;
  children: React.ReactNode;
}
```

The props of `ComposeProvider`, exported for a wrapper that names them. The
wrapper keeps the per-entry checks only when it declares its own
`<const T extends ProviderArray>` and passes `T` here. Under the default `T`,
`providers` is a plain `ProviderArray`.
[Wrapping compose in your own component](/compose/type-checking#wrapping-compose-in-your-own-component)
shows one.

## Migrating from 1.x

| 1.0.8                                           | 2.0                                                                      |
| ----------------------------------------------- | ------------------------------------------------------------------------ |
| `<ComposeProvider components={[...]}>`          | `<ComposeProvider providers={[...]}>`                                    |
| dual CommonJS and ESM builds                    | ESM only; `require('@evanion/compose')` needs Node 20.19, 22.12 or newer |
| the `Component` type                            | `Provider` or `ProviderArray`                                            |
| `Provider`, an alias of `Component`             | `AnyComponent \| readonly [AnyComponent, unknown]`                       |
| `ComposeProvider` typed as a `React.FC`         | a generic function that no longer assigns to `React.FC`                  |
| a missing `providers` fails reading `undefined` | throws a `TypeError` naming `providers`                                  |

The `components` prop is gone from the type surface. A JavaScript caller that
still passes it gets a named error:

