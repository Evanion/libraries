# Getting started

By the end of this page `Widgets.astro` renders a Baize listing page from two
items a CMS saved, and you have read the HTML Astro wrote for it.

## Before you install astro-widget

- Astro `^7.3.4`, the package's only peer dependency.
- Node 20 or newer and an ESM project, since `@evanion/astro-widget` has no
  CommonJS build.

## Install astro-widget

```bash
npm install @evanion/astro-widget
```

```bash
yarn add @evanion/astro-widget
```

```bash
pnpm add @evanion/astro-widget
```

`@evanion/widget` installs with it. `defineWidgets`, `validateItems` and the
item types come from that package, and you import them from
`@evanion/astro-widget`. `Widgets.astro` is published as `.astro` source, and
Astro compiles it from `node_modules` with no configuration.

## Write an astro-widget widget

A widget is an ordinary `.astro` component. Save this one as
`src/widgets/ListingHeader.astro`. It renders the `title` and `players` props a
`listing-header` item carries:

```astro file=libs/astro-widget/examples/src/widgets/ListingHeader.astro region=listing-header

```

`src/widgets/PriceBox.astro` renders the one `price` prop a `price-box` item
carries:

```astro file=libs/astro-widget/examples/src/widgets/PriceBox.astro region=price-box

```

## Register the widgets in an astro-widget registry

The registry maps each item's `type` to the widget that renders it.
`defineWidgets` returns the object it is handed, with the keys kept as literal
types, so an editor completes the type names. Save the registry as
`src/registry.ts`:

```ts file=libs/astro-widget/examples/src/registry.ts region=registry

```

## Save the items astro-widget renders

The CMS writes the listing page as a list of items, and each item's `props` are
the props its widget takes. Save the list as `src/data/brass-birmingham.ts`. In
your site the CMS writes the same list as JSON, and the page imports that file:

```ts file=libs/astro-widget/examples/src/data/brass-birmingham.ts region=items

```

## Render the items with astro-widget

`Widgets.astro` takes the items and the registry, and renders each item through
its widget, in order. Save the page as `src/pages/brass-birmingham.astro`:

```astro file=libs/astro-widget/examples/src/pages/brass-birmingham.astro region=page

```

## See the HTML astro-widget rendered

`AstroContainer`, Astro's container API, renders `brass-birmingham.astro`
outside a request and returns the markup the page renders:

```ts file=libs/astro-widget/README.md region=first-render

```

The header and the price render inside `<main>` in the order the items list
them, and `Widgets.astro` added no element of its own. Run `astro dev` and open
`/brass-birmingham` to see the header and the price in a browser.

## Now that astro-widget renders the page, check the items first

`Widgets.astro` skips an item whose `type` the registry does not hold, so a CMS
save with a stale type publishes a page with a gap in it.
[Validation](/astro-widget/validation) runs `validateItems` over the items and
fails the build on that save.
