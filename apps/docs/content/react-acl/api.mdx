`@evanion/react-acl` exports one provider, four hooks, a factory that binds them
to a policy, and three interfaces. Every type named below is re-exported from
`@evanion/acl` under the same name and documented in
[the core's reference](/acl/api): `Decision`, `FieldDecision`, `Access`,
`Subject`, `Matrix`, `Instant` and the rest.

A hook called outside a `PolicyProvider` throws, and the message names the
provider and the package.

## `PolicyProvider`

`PolicyProvider` holds one evaluator, one subject and one clock for the tree
under it, and renders its children and nothing else.

```tsx signature
function PolicyProvider<Keys extends string = string>(
  props: PolicyProviderProps<Keys>,
): ReactElement;
```

The context value is memoised on the identity of `access`, `subject` and
`context`, so all three need stable references. `context.now` defaults to
`new Date()` when it is left off, and that memo recomputes whenever any of the
three changes identity, so the clock moves under the tree. Pass the value the
server rendered with.


## `PolicyProviderProps`

```tsx signature
interface PolicyProviderProps<Keys extends string = string> {
  access: Access<Subject, AnyObjects, Keys>;
  subject: Subject;
  context?: { now?: Instant };
  children?: ReactNode;
}
```

`access` is any `Access`, whether the core's `hydratePolicy` returned it or
`policy<Subject, Objects>().build()` did. The types a typed policy
carries stop here: the hooks below take `key: string`, so a key this provider's
document never declared reaches them, and the engine throws
`UnknownObjectKeyError` at render unless the matrix was hydrated with
`closed: true`. [`createPolicyContext`](#createpolicycontext) is what keeps
those types.

Only `now` is read off `context`. `PolicyProvider` takes the subject as its own
prop, and one `useMemo` keyed on `access`, `subject` and `context` holds both.
A re-render that changes who is signed in rebuilds the clock with them, which is
why an omitted `context` re-reads the wall clock at every such change.

## `useCan`

`useCan` returns one decision for one action on one row.

```tsx signature
function useCan(
  key: string,
  action: string,
  object?: Record<string, unknown>,
): Decision;
```

`object` is optional for the create case, where there is no instance yet. A rule
that reads the row and is asked without one answers
[`unevaluable`](/acl/refusals#when-the-answer-is-unevaluable).

Memoised on `access`, `subject`, `key`, `action`, `object` and `now`. The row's
identity is part of that key, so a component handed a rebuilt row object
evaluates again and the stale answer never reaches it.

```tsx twoslash file=libs/react-acl/examples/decision.tsx region=decision

```

## `useCanMany`

`useCanMany` returns one decision per row, in the order the rows were given.

```tsx signature
function useCanMany(
  key: string,
  action: string,
  objects: readonly Record<string, unknown>[],
): Decision[];
```

The returned array is parallel to the input, so a row's answer is at the row's
index. `useCanMany` is the hook for a list. React forbids a hook inside a loop,
so a row component calling `useCan` for itself breaks the first time the list is
filtered or reordered.

```tsx twoslash file=libs/react-acl/examples/many.tsx region=many

```

## `useCanFields`

`useCanFields` returns the field-level decision for one action on one axis.

```tsx signature
function useCanFields(
  key: string,
  action: string,
  object: Record<string, unknown>,
  axis: 'read' | 'write',
  proposed?: Record<string, unknown>,
): FieldDecision;
```

`axis` is `'read'` for which fields may be shown and `'write'` for which may be
set. `proposed` is the write the caller intends, and on the write axis the map
covers its keys too, including keys the row has never held.

`action` carries the action-level decision the field maps hang off, and the
engine fills `fields` whatever that decision said. Read `action.allowed` before
you read a field, or a shopper who may not edit the listing at all reaches an
input the map called `'allowed'`.

`fields` maps every field name to `'allowed'`, `'denied'` or `'unevaluable'`.
Compare against `'allowed'`; comparing against `'denied'` treats the
unevaluable fields as writable, which is
[the mistake this API most makes easy](/acl/pitfalls#never-hand-filter-the-field-map).

```tsx twoslash file=libs/react-acl/examples/fields.tsx region=fields

```

## `useCapabilities`

`useCapabilities` returns every action-level decision for the current subject,
keyed by `` `${object}.${action}` ``.

```tsx signature
function useCapabilities(): Record<string, Decision>;
```

`useCapabilities` passes no object, so a rule that reads one cannot be decided
here. It is the hook for a menu or a navigation bar, where the question is which
actions the shopper may reach at all. A question about one particular row goes
to `useCan`.
[What can they do at all?](/acl/capabilities) sets out the no-object contract.

## `createPolicyContext`

`createPolicyContext` binds one policy's subject and object types to a provider
and a set of hooks.

```tsx signature
function createPolicyContext<
  Sub = Subject,
  R = AnyObjects,
  Keys extends string = string,
>(access: Access<Sub, R, Keys>): PolicyContext<Sub, R, Keys>;
```

[`policy`](/acl/authoring) names a subject type once and binds a row type per
object kind, and `build()` returns an `Access` carrying both. Pass that here and
the hooks that come back check their key against the kinds the policy declared
and their row against the type bound to the kind. Both come off the argument, so
the call site writes neither.

A React context fixes its type when it is created, and `useContext` hands a hook
that fixed type whatever the provider above it was given, which is why
`createPolicyContext` is a function returning hooks.

One policy holds every object kind an app has. Chain a `.for()` per kind and one
`createPolicyContext` call covers the listing and the stock report both. You do
not make a context per resource.

Each call does make its own context, so two separate policy documents nest and
each set of hooks reads its own provider. The returned provider also feeds the
shared context, so a component calling `useCan` from the package root underneath
it reads the same decision.

## `PolicyContext`

`PolicyContext` is what `createPolicyContext` returns: the same provider and
four hooks, at the types the policy carries.

```tsx signature
interface PolicyContext<Sub, R, Keys extends string = string> {
  PolicyProvider(props: BoundPolicyProviderProps<Sub, R, Keys>): ReactElement;
  useCan<K extends keyof R & string>(
    key: K,
    action: ActionOf<Keys, K>,
    object?: Partial<R[K]>,
  ): Decision;
  useCanMany<K extends keyof R & string>(
    key: K,
    action: ActionOf<Keys, K>,
    objects: readonly Partial<R[K]>[],
  ): Decision[];
  useCanFields<K extends keyof R & string>(
    key: K,
    action: ActionOf<Keys, K>,
    object: Partial<R[K]>,
    axis: 'read' | 'write',
    proposed?: Partial<R[K]>,
  ): FieldDecision;
  useCapabilities(): Record<Keys, Decision>;
}
```

`Partial<R[K]>` for the row, because a list row carrying two of five fields is
the [`unevaluable`](/acl/refusals#when-the-answer-is-unevaluable) case, and the
compiler has no business calling it a type error. A row type declared
`extends Record<string, unknown>` accepts
every key and gives the check nothing to hold, so declare the row's fields and
nothing more.

`useCapabilities` answers by permission key, `listing.edit`, where `R` holds the
object kinds, `listing`. A policy whose blocks
[declare their actions](/acl/authoring#the-vocabulary-of-a-kind) narrows
those keys to the ones it declares, so `listing.edti` is a compile error. A
policy that leaves one block's actions open stays keyed by `string`.

## `BoundPolicyProviderProps`

```tsx signature
interface BoundPolicyProviderProps<Sub, R, Keys extends string = string> {
  access?: Access<Sub, R, Keys>;
  subject: Sub;
  context?: { now?: Instant };
  children?: ReactNode;
}
```

`access` is optional here and required on `PolicyProvider`, because
`createPolicyContext` was already handed a document. Pass it to decide against a
different one of the same shape: a per-tenant matrix, or the copy the browser
rebuilt with `hydratePolicy`, which crossed JSON and carries no types of its
own.

`subject` is the subject type the policy was authored against, so a value
missing a field that type declares is a compile error at the mount.
