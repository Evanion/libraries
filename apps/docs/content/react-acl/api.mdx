# API reference

<WorkshopNotice slug="react-acl" />

`@evanion/react-acl` exports one provider, four hooks, a factory that binds them
to a policy, and three interfaces. It also re-exports seventeen of
`@evanion/acl`'s types under their own names, from [`Access`](#access) down, so
a component file imports `Decision` from either package. The core's values,
`hydratePolicy` and `policy` among them, are imported from `@evanion/acl`.

## `PolicyProvider`

`PolicyProvider` holds one evaluator, one subject and one instant for the tree
under it, and renders its children and nothing else. A hook called outside a
`PolicyProvider` throws, and the message names the provider and the package.

```tsx signature
function PolicyProvider<Keys extends string = string>(
  props: PolicyProviderProps<Keys>,
): ReactElement;
```

- The context value is memoised on the identity of `access`, `subject` and
  `context`, so all three need stable references.
- `context.now` defaults to `new Date()` when it is left off.
- The memo recomputes whenever any of the three changes identity, so the clock
  moves under the tree. Pass the value the server rendered with.

```tsx twoslash file=libs/react-acl/examples/mount.tsx region=mount

```

## `PolicyProviderProps`

```tsx signature
interface PolicyProviderProps<Keys extends string = string> {
  access: Access<Subject, AnyObjects, Keys>;
  subject: Subject;
  context?: { now?: Instant };
  children?: ReactNode;
}
```

| Prop       | What it is                                                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `access`   | any `Access`, whether the core's `hydratePolicy` returned it or `policy<Subject, Objects>().build()` did                               |
| `subject`  | the subject every hook under the provider decides against, held in the same `useMemo`                                                  |
| `context`  | only `now` is read off it, and an omitted `context` re-reads the wall clock whenever `access`, `subject` or `context` changes identity |
| `children` | the tree the provider renders                                                                                                          |

`PolicyProvider` erases a typed policy's key and row types. The hooks below take
`key: string`, so a key this provider's document never declared reaches them at
render. The evaluator then throws `UnknownObjectKeyError` for an object kind the
document never declared, and `UnknownPermissionError` for an action that kind
never declared. A matrix hydrated with `closed: true` answers `unknown-action`
for both instead of throwing. [`createPolicyContext`](#createpolicycontext) keeps
those types.

## `useCan`

`useCan` returns one decision for one action on one row.

```tsx signature
function useCan(
  key: string,
  action: string,
  object?: Record<string, unknown>,
): Decision;
```

- `object` is optional for the create case, where there is no instance yet. A
  rule that reads the row and is asked without one answers
  [`unevaluable`](/acl/refusals#when-the-answer-is-unevaluable).
- `useCan` memoises on `access`, `subject`, `key`, `action`, `object` and `now`,
  so a component handed a rebuilt row evaluates again and no stale answer
  reaches it.

```tsx twoslash file=libs/react-acl/examples/decision.tsx region=decision

```

## `useCanMany`

`useCanMany` returns one decision per row, in the order the rows were given.

```tsx signature
function useCanMany(
  key: string,
  action: string,
  objects: readonly Record<string, unknown>[],
): Decision[];
```

The returned array is parallel to the input, so a row's answer sits at the row's
index. React forbids a hook inside a loop, so the component holding the list
cannot call `useCan` once per row.

```tsx twoslash file=libs/react-acl/examples/many.tsx region=many

```

## `useCanFields`

`useCanFields` returns the field-level decision for one action on one axis.

```tsx signature
function useCanFields(
  key: string,
  action: string,
  object: Record<string, unknown>,
  axis: 'read' | 'write',
  proposed?: Record<string, unknown>,
): FieldDecision;
```

- `axis` is `'read'` for which fields may be shown, and `'write'` for which may
  be set.
- `proposed` is the write the caller intends. On the write axis the map covers
  its keys too, including keys the row has never held.

The returned [`FieldDecision`](#fielddecision) carries `action`, the
action-level decision, and `fields`, which the engine fills whatever `action`
said. Read `action.allowed` before you read a field, or a shopper who may not
edit the listing at all reaches an input the map called `'allowed'`. Compare a
field against `'allowed'`; comparing against `'denied'` treats the unevaluable
fields as writable, which is
[the mistake this API most makes easy](/acl/pitfalls#never-hand-filter-the-field-map).

```tsx twoslash file=libs/react-acl/examples/fields.tsx region=fields

```

The map enforces nothing in the browser. The server applies the same map to the
posted form with [`pickAllowedFields`](/acl/writing).

## `useCapabilities`

`useCapabilities` returns every action-level decision for the current subject,
keyed by `` `${object}.${action}` ``.

```tsx signature
function useCapabilities(): Record<string, Decision>;
```

`useCapabilities` passes no object, so a rule that reads one cannot be decided
here. A menu or a navigation bar asks which actions the shopper may reach at
all, and a question about one particular row goes to `useCan`.
[Listing everything a user may do](/acl/listing-permissions) sets out the
no-object contract.

```tsx twoslash file=libs/react-acl/examples/menu.tsx region=menu

```

## `createPolicyContext`

`createPolicyContext` binds one policy's subject and object types to a provider
and a set of hooks.

```tsx signature
function createPolicyContext<
  Sub = Subject,
  R = AnyObjects,
  Keys extends string = string,
>(access: Access<Sub, R, Keys>): PolicyContext<Sub, R, Keys>;
```

[`policy`](/acl/authoring) names a subject type once and binds a row type per
object kind, and `build()` returns an `Access` carrying both. The hooks that
come back check their key against the kinds the policy declared, and their row
against the type bound to the kind, both read off the argument.

| What you have                            | What `createPolicyContext` gives                                                               |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------- |
| one policy holding every object kind     | one call covering the listing and the stock report both, since you chain a `.for()` per kind   |
| two separate policy documents            | one context per call, so the two nest and each set of hooks reads its own provider             |
| a component under the returned provider  | the same decision from a `useCan` imported at the package root, which that provider also feeds |
| a key or a row the policy never declared | a compile error, since the hooks check both against the `Access` handed in                     |

```tsx twoslash file=libs/react-acl/examples/typed.tsx region=typed

```

## `PolicyContext`

`PolicyContext` is what `createPolicyContext` returns: the same provider and
four hooks, at the types the policy carries.

```tsx signature
interface PolicyContext<Sub, R, Keys extends string = string> {
  PolicyProvider(props: BoundPolicyProviderProps<Sub, R, Keys>): ReactElement;
  useCan<K extends keyof R & string>(
    key: K,
    action: ActionOf<Keys, K>,
    object?: Partial<R[K]>,
  ): Decision;
  useCanMany<K extends keyof R & string>(
    key: K,
    action: ActionOf<Keys, K>,
    objects: readonly Partial<R[K]>[],
  ): Decision[];
  useCanFields<K extends keyof R & string>(
    key: K,
    action: ActionOf<Keys, K>,
    object: Partial<R[K]>,
    axis: 'read' | 'write',
    proposed?: Partial<R[K]>,
  ): FieldDecision;
  useCapabilities(): Record<Keys, Decision>;
}
```

| Type detail                                                                            | What it means                                                                                                                                       |
| -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Partial<R[K]>` on every row parameter                                                 | a list row carrying two of five fields is the [`unevaluable`](/acl/refusals#when-the-answer-is-unevaluable) case, so the compiler lets it through   |
| a row type declared `extends Record<string, unknown>`                                  | accepts every key and gives the check nothing to hold, so declare the row's fields and nothing more                                                 |
| the keys `useCapabilities` answers by                                                  | `` `${object}.${action}` ``, `listing.edit`, where `R` holds the object kinds                                                                       |
| a policy whose blocks [declare their actions](/acl/authoring#the-vocabulary-of-a-kind) | narrows those keys to the ones it declares, so `listing.edti` is a compile error; a policy leaving one block's actions open stays keyed by `string` |

## `BoundPolicyProviderProps`

```tsx signature
interface BoundPolicyProviderProps<Sub, R, Keys extends string = string> {
  access?: Access<Sub, R, Keys>;
  subject: Sub;
  context?: { now?: Instant };
  children?: ReactNode;
}
```

`access` is optional here and required on `PolicyProvider`, because
`createPolicyContext` was already handed a document. Pass one to decide against
a different document of the same shape: a per-tenant matrix, or the copy the
browser rebuilt with `hydratePolicy`, which carries no types of its own.

`subject` takes the type the policy was authored against, so a value missing a
field that type declares is a compile error at the mount.
