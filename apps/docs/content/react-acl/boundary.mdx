# Which side decides

To enforce a permission, call `access.can` from `@evanion/acl` on the server, in
the loader and again in the action. `useCan` runs in the shopper's browser and
decides only which controls render.

## What a react-acl app calls on the server

A loader or a server component calls `access.can` and imports nothing from
`@evanion/react-acl`. The server component below asks `'read'` before it renders
anything, and the action behind the Edit button asks the same question with
`'edit'`:

```tsx twoslash file=libs/react-acl/examples/server.tsx region=server

```

`ListingPage` takes `access` as a prop so the example runs under a test. An app
builds the evaluator once, at module scope in a server-only module, and calls
`access.authorize(shopper)` once per request, which drops the subject from every
call after it.

`useCan('listing', 'edit', listing)` and
`access.can(shopper, 'listing', 'edit', listing)` evaluate the same rules over
the same matrix and return the same `Decision`. `can` is a function over frozen
JSON and does not know where it runs, so neither call's type says which side
enforces. The runtime separates them. The server's call ran where the shopper
cannot reach the code. The browser's call ran over a matrix the shopper can read,
against a subject the shopper's own page supplied.

## Where each layer of a react-acl app decides

| Where                                | Runtime | Decides?                                |
| ------------------------------------ | ------- | --------------------------------------- |
| Middleware                           | trusted | yes, for what it lets through           |
| Loader or server component           | trusted | yes, for what it returns or renders     |
| `PolicyProvider` and its tree        | browser | never; it toggles what the shopper sees |
| Action, Server Action, route handler | trusted | yes, independently, for what it writes  |

A caller reaches the last row directly. `curl` posts to the action without
rendering anything, so the handler resolves the subject from the session, reads
the listing from the database, and decides again. Every layer runs its own
evaluation and trusts no earlier one, between two of your own services as much
as between the browser and the server.

Each of those evaluations reads a matrix already in memory. Nothing in the
trusted rows waits on a network call to decide, so a slow or unreachable policy
service cannot turn a deny into an allow.

## Why react-acl cannot run in a server component

`@evanion/react-acl` carries `'use client'` at the top of its entry point and
calls `createContext`. Next.js resolves React under the `react-server` condition
for a React Server Component (RSC), and that build exports no `createContext`
and no stateful hook.

An RSC that imports `useCan` gets a client reference, and calling it during the
server render throws. An RSC may render a client component, such as the
`ShopAccess` wrapper from Getting started, and every prop it passes is
serialized on the way to the browser.
For its own decisions an RSC calls `access.can` from `@evanion/acl` directly.

## What crosses the render in a react-acl app

`Access` is a set of closures over a frozen document, and `JSON.stringify` drops
every method on it silently. No loader return value and no server component prop
can carry one. The matrix crosses in its place, and the browser calls
`hydratePolicy` on it to build its own evaluator, which is the `access` prop
[Getting started](/react-acl/getting-started) mounts.

| What crosses | The form it crosses in                          | What the browser does with it         |
| ------------ | ----------------------------------------------- | ------------------------------------- |
| `Access`     | nothing; closures do not serialize              | rebuilds its own with `hydratePolicy` |
| the matrix   | a JSON envelope carrying `version` and `schema` | hydrates it into an evaluator         |
| the subject  | a plain object, and no credential               | evaluates against it                  |
| `now`        | an ISO string                                   | keys every hook memo on it            |

The subject crosses because the browser needs it to evaluate. Nothing reads it
back: on the next request the server resolves its own subject from the session.

`now` crosses as a string. Resolve it on the server, so the server render and
the client's first render agree on the instant and no time window in the policy
is read against a clock the shopper's machine sets.

## How fresh the browser's copy of a react-acl matrix is

The matrix in the browser is as fresh as the render that delivered it. Revoke a
permission and that copy keeps granting until something replaces it, and nothing
in the browser notices. `access.version`, the revision stamped on the matrix, is
the value to compare. Your app writes the check that fails closed and refetches.

The server never reads the browser's copy. Every loader, action and handler
evaluates its own, so a stale copy can show a shopper an Edit button and the
action behind it still answers 403.
