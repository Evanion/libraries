# @evanion/react-acl

An Edit button that asks `@evanion/acl` whether the signed-in user may edit a
listing needs your rules, that user and the current time. Passed as props, all
three travel through three components that never read them.

## How react-acl holds what a permission check needs

`PolicyProvider` takes your rules, the signed-in user and the current time once,
as its `access`, `subject` and `context` props, and holds them in a React
context for the tree under it. `useCan` reads all three out of that context and
asks the rules one question.


`EditControl` passes `'listing'`, the kind of record it asks about, the action
`'edit'` and the listing itself. It renders the button only when
`decision.allowed` is true. The signed-in user and the current time come from
the provider above it.

One provider also gives the whole screen one current time. A rule can hold only
inside a time window, such as a discount that ends at 18:00, and two components
each handed their own `now` can read times either side of it. The rule then
answers two ways on one screen.

## The react-acl vocabulary

Every react-acl page uses the terms below. They come from `@evanion/acl`, the
package that evaluates the rules, and react-acl uses them unchanged.

- The **matrix** is your rules as one JSON document. Your server builds it with
  `@evanion/acl` and sends it to the browser with the page.
- An **evaluator** answers questions from one matrix. `hydratePolicy` builds one
  from the JSON, and these pages always call it `access`. `access.can` asks it
  one question.
- A **subject** is who is acting: the signed-in user, as a plain object your
  server resolved. In Baize the subject is the shopper.
- An **object kind** names a kind of record the rules cover, such as
  `'listing'`. A **row** is one record of that kind, such as one listing.
- A **decision** is what an evaluator returns for one question. `allowed` is the
  answer, and `reason` says why. Code gates on `allowed` alone.
- The **instant** is the time every time window in the rules is read against.
  `context.now` carries it into the provider.

## What react-acl can do

| The screen asks                                           | The export            |
| --------------------------------------------------------- | --------------------- |
| May this shopper take this action on this row?            | `useCan`              |
| May they take it on each row of this list?                | `useCanMany`          |
| Which inputs of this form may they see, or set?           | `useCanFields`        |
| What may they reach at all, for a menu?                   | `useCapabilities`     |
| Can the compiler check my object kinds, actions and rows? | `createPolicyContext` |

Each hook returns what the `@evanion/acl` method it is named after returns, for
the subject and the instant the provider holds: `useCan` returns what `can`
returns.

## When react-acl is the wrong tool

- A server component, a loader or a Server Action. Each of those calls
  `access.can` from `@evanion/acl` directly, because react-acl runs only in
  client components.
- One component asking one question.
  `access.can(shopper, 'listing', 'edit', listing)` returns the same answer
  without a provider.
