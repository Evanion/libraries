# @evanion/react-acl

An Edit button that asks `can` four components down needs your policy, the
signed-in user and the current time. Passed as props, all three travel through
three components that never read them.

## How react-acl holds what a permission check needs

`PolicyProvider` takes the three once, as its `access`, `subject` and `context`
props, and holds them in a React context for the tree under it. `useCan`,
`useCanMany`, `useCanFields` and `useCapabilities` read all three out of that
context and call the `@evanion/acl` method each one is named after.

`EditControl` passes the object kind `'listing'`, the action `'edit'` and the
row, and renders the button only when `decision.allowed` is true. The shopper
and the instant come from the provider above it.

One provider also means one instant. A component handed `now` as a prop can
read a different time from its sibling, and a rule with a time window then
answers two ways on one screen.

## The react-acl vocabulary

Six words carry this section. The matrix, the evaluator, the subject and the
decision belong to `@evanion/acl`, the package that evaluates the rules, and
react-acl uses them unchanged.

- The **matrix** is your rules as one JSON document. Your server builds it from
  your policy and sends it to the browser with the page.
- An **evaluator** answers questions from one matrix. `hydratePolicy` in
  `@evanion/acl` builds one from the JSON, and these pages always call it
  `access`.
- A **subject** is who is acting: the signed-in user, as a plain object your
  server resolved.
- A **decision** is what an evaluator returns for one question. `allowed` is the
  answer, and `reason` says why and is output only.
- The **provider** is `PolicyProvider`, the component that holds an evaluator, a
  subject and an instant for every component under it.
- The **instant** is the time every time window in the rules is read against.
  `context.now` carries it into the provider.

## What react-acl can do

| The screen asks                                           | The export            |
| --------------------------------------------------------- | --------------------- |
| May this shopper take this action on this row?            | `useCan`              |
| May they take it on each row of this list?                | `useCanMany`          |
| Which inputs of this form may they see, or set?           | `useCanFields`        |
| What may they reach at all, for a menu?                   | `useCapabilities`     |
| Can the compiler check my object kinds, actions and rows? | `createPolicyContext` |

Each hook returns what the `@evanion/acl` method of the same name returns, for
the subject and the instant the provider holds.

## When react-acl is the wrong tool

- A server component, a loader or a Server Action. Those call `access.can` from
  `@evanion/acl` directly. react-acl carries `'use client'` at the top of its
  entry point and calls `createContext`, so it cannot run in a React Server
  Component.
- One component asking one question. A provider for a single call site is a
  context you keep mounted, and `access.can(subject, key, action, row)` is the
  same answer in one line.
- Anywhere the answer has to hold. The hooks read a copy of the matrix as fresh
  as the render that delivered it, and a browser holding a stale copy keeps
  granting what the server has revoked.
