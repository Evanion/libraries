# @evanion/nestjs-correlation-id

An order in Baize, the board game shop these pages use, crosses `storefront`,
`orders` and `stock`, and nothing ties one service's log lines for it to
another's. `@evanion/nestjs-correlation-id` gives the request one id every
NestJS service can log.

## How nestjs-correlation-id carries one id across services

A correlation id is a string that names one request in every service the
request reaches. `CorrelationService` is the provider that holds the current id,
in Node's [`AsyncLocalStorage`](https://nodejs.org/api/async_context.html). A
correlation context is the scope `CorrelationService.run(id, callback)` opens:
the callback, plus everything it calls or awaits. Inside it, the service's
`getCorrelationId()` returns `id`.

In an application `CorrelationIdMiddleware` opens the context for each request,
so a handler only reads the id. Below, two contexts are opened by hand and one
handler runs in both at the same time: each run awaits, then reads the id its
own context was opened with:


Outside both contexts `getCorrelationId()` returns `undefined`, because no
context is open there.

`CorrelationIdMiddleware` reads the id from the `X-Correlation-Id` header and
reuses it when it passes a format check. When the header is missing or fails the
check, the middleware generates a new id. It sets the same header on the
response.

`withCorrelation()` configures `HttpModule` from `@nestjs/axios` so that every
outgoing `HttpService` call carries the id, and the next service's middleware
reuses it:

```mermaid caption="One X-Correlation-Id header carried from storefront through orders to stock."
flowchart LR
  S["storefront"] -->|"X-Correlation-Id"| M["orders:<br>CorrelationIdMiddleware<br>reuses it, or generates one"]:::accent
  M --> H["the handler<br>getCorrelationId()"]
  H --> X["HttpService<br>withCorrelation()"]
  X -->|"X-Correlation-Id"| N["stock:<br>reuses the same id"]
```

## What nestjs-correlation-id provides

| Export                             | What it does                                                             |
| ---------------------------------- | ------------------------------------------------------------------------ |
| `CorrelationModule`                | provides `CorrelationService` and the configuration to every module      |
| `CorrelationIdMiddleware`          | opens a correlation context per request and sets the id on the response  |
| `CorrelationService`               | reads and generates the id, and opens a context for work with no request |
| `withCorrelation()`                | `HttpModule.registerAsync` options that send the id on every call        |
| `DEFAULT_CORRELATION_ID_VALIDATOR` | the format check an incoming id passes before the middleware reuses it   |

A queue consumer or a cron job has no request, so it opens its own context with
`run()`.

## What nestjs-correlation-id leaves to you

- It writes no log line. Your logger injects `CorrelationService`, calls
  `getCorrelationId()` and adds the value to its own output.
- It reads one header, `X-Correlation-Id` unless you configure another. There
  is no list of fallback header names.
- It forwards the id on `HttpService` calls whose module used
  `withCorrelation()`. A `fetch` call or a queue message carries the id only
  when your code puts it there.
- It records no spans and no timings. A tracer such as OpenTelemetry does that,
  and can run beside it.
