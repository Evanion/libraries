# @evanion/nestjs-correlation-id

One order in Baize crosses three services, `storefront`, `orders` and `stock`,
and each one writes its own log lines. `@evanion/nestjs-correlation-id` gives
the request one id that every NestJS service on the path can log.

## How nestjs-correlation-id carries one id across services

A correlation id is a string that names one request in every service the
request reaches. A correlation context is the stretch of work that can read it:
`CorrelationService.run(id, callback)` opens one, and everything the callback
calls or awaits gets `id` back from `getCorrelationId()`. Below, a
`CorrelationService` built by hand runs two handlers at the same time, each
awaits, and each reads the id its own context was opened with:

Outside both contexts `getCorrelationId()` returns `undefined`, because no
request is in flight there.

`CorrelationIdMiddleware` calls `run()` once per request. It reads the id from
the `X-Correlation-Id` header, reuses it when it passes validation, and mints a
new one when the header is missing or rejected. `withCorrelation()` writes the
id onto each outgoing `HttpService` call, and the next service's middleware
reuses it.

`CorrelationService` keeps the id in Node's
[`AsyncLocalStorage`](https://nodejs.org/api/async_context.html), so it stays a
singleton. A request-scoped provider would make every provider that injects it
request-scoped too, `HttpService` included: rebuilt per request, and never given
`onModuleInit`.

## What nestjs-correlation-id exports

| Export                             | What it does                                                              |
| ---------------------------------- | ------------------------------------------------------------------------- |
| `CorrelationModule`                | provides `CorrelationService` and the configuration to every module       |
| `CorrelationIdMiddleware`          | opens a correlation context per request and echoes the id on the response |
| `CorrelationService`               | reads and replaces the id, mints one, and opens a context for a job       |
| `withCorrelation()`                | `HttpModule.registerAsync` options that send the id on every call         |
| `DEFAULT_CORRELATION_ID_VALIDATOR` | the check an incoming id passes before the middleware reuses it           |

The middleware reads and writes raw `node:http` headers, so it runs under
`@nestjs/platform-express` and `@nestjs/platform-fastify` alike.

## What nestjs-correlation-id leaves to you

- It writes no log line. Your logger calls `getCorrelationId()` and adds the
  value to its own output.
- It reads one header. There is no list of fallback header names.
- It forwards the id on `HttpService` calls whose module used
  `withCorrelation()`. A `fetch` call or a queue message carries the id only
  when your code puts it there.
- It records no spans and no timings. A tracer such as OpenTelemetry does that,
  and can run beside it.
