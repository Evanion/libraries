# Getting started

By the end of this page every request to your NestJS application carries a
correlation id, and a handler reads it from `CorrelationService`.

## Before you install nestjs-correlation-id

- A NestJS 12 application, meaning `@nestjs/common` `^12.0.0`, on the Express
  or the Fastify adapter.
- Node 20 or newer for an ES module project. The package ships only ES modules,
  so a CommonJS project needs Node 20.19, 22.12 or newer, which load it through
  `require()` the same way they load NestJS 12. On an older Node, upgrade Node
  or switch the project to ES modules.
- `@nestjs/axios` `^12.0.1` and `axios`, only if you forward the id on outgoing
  calls. `@nestjs/axios` is an optional peer dependency, and this page does not
  need it.

## Install nestjs-correlation-id

```bash
npm install @evanion/nestjs-correlation-id
```

```bash
yarn add @evanion/nestjs-correlation-id
```

```bash
pnpm add @evanion/nestjs-correlation-id
```

The package's one runtime dependency is `tslib`.

## Register CorrelationModule and the middleware

`CorrelationModule.forRoot()` provides `CorrelationService` to every module, and
`CorrelationIdMiddleware` opens a correlation context around each request.
Register both in your root module:

```ts twoslash file=libs/nestjs-correlation-id/examples/app.module.ts region=register

```

`forRoot()` with no argument is the whole minimum configuration. The middleware
reads `X-Correlation-Id`, generates a missing id with `randomUUID`, and reuses an
incoming id only when it passes `DEFAULT_CORRELATION_ID_VALIDATOR`.

- `forRoot()` registers a global module, so call it once, in the root module.
- `forRoutes('*')` covers every route. On a route the middleware skips,
  `getCorrelationId()` returns `undefined`.
- Apply your own middleware that reads the id after `CorrelationIdMiddleware`
  in `configure()`, because the context opens there.

## Read the id nestjs-correlation-id holds for a request

Inject `CorrelationService` and call `getCorrelationId()`. `OrdersController`
in Baize's `orders` service returns the id with the order and writes both to its
log line:

```ts file=libs/nestjs-correlation-id/examples/orders.controller.ts region=read-the-id

```

`getCorrelationId()` is synchronous, and nothing passes the id to `find()`: the
controller reads it from the context the middleware opened.

## Check that nestjs-correlation-id reuses the caller's id

Add `controllers: [OrdersController]` to the `@Module()` of `AppModule` and start
the application. The request below assumes it listens on port 3000, the port
`nest new` sets up. Send a request with an id:

```bash
curl -i -H 'X-Correlation-Id: storefront-4f1c9a' http://localhost:3000/orders/order-2026-0042
```

The response carries the header `X-Correlation-Id: storefront-4f1c9a` and the
body `{"order":"order-2026-0042","correlationId":"storefront-4f1c9a"}`. Leave
the header off and both carry a fresh universally unique identifier (UUID).

The code below checks the same result without a server, as a unit test would.
It calls the middleware the way Nest does, once for a request that carries
`storefront-4f1c9a` and once for a request with no header. Node lowercases
incoming header names, so the request object carries `x-correlation-id`. The
configuration has no `validate`, so the middleware falls back to
`DEFAULT_CORRELATION_ID_VALIDATOR`. The generator returns `orders-0f3a2b` so that
its result is predictable:

```ts twoslash file=libs/nestjs-correlation-id/README.md region=middleware-by-hand

```

The callback for the first request read `storefront-4f1c9a`, because the id
passed `DEFAULT_CORRELATION_ID_VALIDATOR` and the middleware reused it. The
callback for the second read the generated id. After both requests,
`getCorrelationId()` returns `undefined`.

## Now that every request carries an id, forward it

[Forward the id to the next service](/nestjs-correlation-id/forwarding) passes
`withCorrelation()` to `HttpModule`, so Baize's `stock` service receives the id
the `orders` service was called with.
