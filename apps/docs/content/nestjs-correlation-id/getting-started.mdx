# Getting started

By the end of this page every request to your NestJS application carries a
correlation id, and a handler reads it from `CorrelationService`.

## Before you install nestjs-correlation-id

- NestJS 12, meaning `@nestjs/common` `^12.0.0`, on the Express or the Fastify
  adapter.
- Node 20 or newer.
- An ES module project, or a CommonJS one on Node 20.19, 22.12 or newer. The
  package ships only ES modules, and those Node versions load it through
  `require()` the same way they load NestJS 12.
- `@nestjs/axios` `^12.0.1`, only if you forward the id on outgoing calls. It
  is an optional peer dependency, and this page does not need it.

## Install nestjs-correlation-id

```bash
npm install @evanion/nestjs-correlation-id
```

```bash
yarn add @evanion/nestjs-correlation-id
```

```bash
pnpm add @evanion/nestjs-correlation-id
```

The package's one runtime dependency is `tslib`.

## Register CorrelationModule and the middleware

`CorrelationModule.forRoot()` provides `CorrelationService` to every module, and
`CorrelationIdMiddleware` opens a correlation context around each request.
Register both in your root module:

```ts twoslash file=libs/nestjs-correlation-id/examples/app.module.ts region=register

```

`forRoot()` with no argument is the whole minimum configuration. The middleware
reads `X-Correlation-Id`, generates a missing id with `randomUUID`, and reuses an
incoming id only when it passes `DEFAULT_CORRELATION_ID_VALIDATOR`.

- `forRoot()` registers a global module, so call it once, in the root module.
- `forRoutes('*')` covers every route. On a route the middleware skips,
  `getCorrelationId()` returns `undefined`.
- Middleware of your own that reads the id goes after `CorrelationIdMiddleware`
  in `configure()`, because the context opens there.

## Read the correlation id in a handler with nestjs-correlation-id

Inject `CorrelationService` and call `getCorrelationId()`. The service is a
singleton, so injecting it keeps your controller a singleton too.
`OrdersController` in Baize's `orders` service returns the id with the order
and writes both to its log line:

```ts file=libs/nestjs-correlation-id/examples/orders.controller.ts region=read-the-id

```

`getCorrelationId()` is synchronous, and nothing passes the id to `find()`: the
controller reads it from the context the middleware opened.

## See the correlation id a request carries with nestjs-correlation-id

Add `OrdersController` to the `controllers` of `AppModule`, start the
application, and send a request with an id:

```bash
curl -i -H 'X-Correlation-Id: storefront-4f1c9a' http://localhost:3000/orders/order-2026-0042
```

The response carries `X-Correlation-Id: storefront-4f1c9a`, and the body carries
the same id from `OrdersController`. Leave the header off and both carry a fresh
universally unique identifier (UUID).

The fence below runs the same middleware without a server, the way Nest calls
it. The first request carries `storefront-4f1c9a` and the second carries no
header. The generator here returns `orders-0f3a2b` so that its result is
predictable:

```ts twoslash file=libs/nestjs-correlation-id/README.md region=middleware-by-hand

```

The first handler read `storefront-4f1c9a`, because the id passed
`DEFAULT_CORRELATION_ID_VALIDATOR` and the middleware reused it. The second read
the generated id. After both requests, `getCorrelationId()` returns
`undefined`.

## Now that every request carries an id, forward it

[Forward the id to the next service](/nestjs-correlation-id/forwarding) passes
`withCorrelation()` to `HttpModule`, so Baize's `stock` service receives the id
the `orders` service was called with.
