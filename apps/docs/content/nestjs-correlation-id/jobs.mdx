# Carry the id through a job

A queue consumer or a cron job has no incoming request and no middleware, so it
opens its own correlation context with `CorrelationService.run()`.

## Open a correlation context in a queue consumer

`RestockJob` handles a restock message in Baize's `orders` service. The service
that queued the message set its `correlationId` from `getCorrelationId()` while
it handled a request, so the message carries that request's id when there was
one. `RestockJob` injects `CorrelationService`, the configuration `forRoot()`
resolved under `CORRELATION_CONFIG_TOKEN`, and `StockClient`, the `orders`
service's client for `stock`:

```ts file=libs/nestjs-correlation-id/examples/restock.job.ts region=restock-job

```

- `run(id, callback)` runs `callback` inside a correlation context and returns
  what `callback` returns, so the promise from `stock.level()` comes straight
  back out of `handle()`.
- Everything the callback calls or awaits reads `id`. `StockModule` registers
  `StockClient`'s `HttpService` with `withCorrelation()`, so its call to `stock`
  carries the id.
- `generate()` returns a new id from the configured generator, `randomUUID`
  unless `forRoot()` was given another.

## Why RestockJob validates the carried id

An id read off a queue message reaches the same log lines and outgoing headers
as one read off a request, so it passes the same check. `validate` on the
injected configuration is the function `CorrelationIdMiddleware` applies to an
incoming header, `DEFAULT_CORRELATION_ID_VALIDATOR` unless `forRoot()` was given
another. A carried id that fails the check is dropped, and the job generates its
own.

`CorrelationConfig` types `validate` as optional, which is why `RestockJob`
calls it with `?.`. `forRoot()` always sets it, so the call always runs.

## Replace the id inside a correlation context

`setCorrelationId(id)` replaces the id for the rest of the context it is called
in. A consumer that opens its context before it has read the message, for
instance with `run(generate(), …)` around every handler, calls it once it has
read the id the message carried. Outside any context it throws.

The generated id came from the generator passed to `forRoot()`. Inside
`run('orders-0f3a2b', …)`, `setCorrelationId` changed what `getCorrelationId()`
returns. Outside, the call threw, and the message names the two ways to open a
context.

Inside a request, `setCorrelationId` leaves the response header alone. The
header keeps the id the middleware wrote when the request arrived.
