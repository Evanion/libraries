# API reference

`@evanion/nestjs-correlation-id` exports one module, one middleware, one
service, one function that configures `HttpModule`, one configuration interface
and four constants.

## `CorrelationModule`

`CorrelationModule` provides `CorrelationService` and the resolved
configuration to the whole application.

```ts signature
class CorrelationModule {
  static forRoot(config?: Partial<CorrelationConfig>): DynamicModule;
}
```

`forRoot()` fills in every unset field of `config` and returns the module,
registered `global: true`. It provides and exports `CorrelationService`, and the
configuration under [`CORRELATION_CONFIG_TOKEN`](#correlation_config_token).
Call it once, in the root module: a second call registers a second
configuration under the same token, and the last import wins.


## `CorrelationIdMiddleware`

`CorrelationIdMiddleware` opens a correlation context around every request it
is applied to.

```ts signature
class CorrelationIdMiddleware implements NestMiddleware {
  use(
    req: IncomingMessage,
    res: ServerResponse,
    next: (error?: unknown) => void,
  ): void;
}
```

Per request it does five things, in order:

1. Reads the configured header, case-insensitively. A repeated header arrives
   as an array or as one comma-joined string, and both become one string.
2. Reuses that value when `validate` accepts it, and calls the generator
   otherwise.
3. Writes the id onto `req.headers` when the request carried no header, so a
   proxy or an access logger reading the raw header sees the same id. A header
   that arrived stays as it came in, including one `validate` rejected.
4. Sets the response header, unless something already set it.
5. Calls `next` inside `CorrelationService.run(id, next)`.

`req` and `res` are typed against `node:http`, so the class runs under the
Express and the Fastify adapters. Middleware that reads the id has to be applied
after this one.

## `CorrelationService`

`CorrelationService` reads, replaces and mints the correlation id, and opens a
correlation context.

```ts signature
@Injectable()
class CorrelationService {
  run<T>(correlationId: string, callback: () => T): T;
  getCorrelationId(): string | undefined;
  setCorrelationId(correlationId: string): void;
  generate(): string;
}
```

| Method                 | What it does                                                          |
| ---------------------- | --------------------------------------------------------------------- |
| `run(id, callback)`    | runs `callback` in a correlation context and returns what it returns  |
| `getCorrelationId()`   | the surrounding context's id, or `undefined` outside one; synchronous |
| `setCorrelationId(id)` | replaces the surrounding context's id; throws outside one             |
| `generate()`           | a fresh id from the configured generator                              |

The service is a singleton over `AsyncLocalStorage`, and injecting it leaves the
scope of the provider holding it unchanged. `setCorrelationId` leaves the
response header with the id the middleware wrote on arrival.


## `withCorrelation(config?)`

`withCorrelation()` returns options for `HttpModule.registerAsync` that send the
current correlation id on every outgoing request.

```ts signature
function withCorrelation(config?: HttpModuleOptions): HttpModuleAsyncOptions;
```

`config` reaches the axios instance unchanged. The id is attached by an axios
request interceptor, registered as an extra provider under
[`CORRELATION_AXIOS_INTERCEPTOR`](#correlation_axios_interceptor), which reads
the context as each request goes out. No header is attached outside a context.

It requires `CorrelationModule.forRoot()` somewhere in the application; without
it Nest fails at boot with
`Nest can't resolve dependencies of the HTTP_MODULE_OPTIONS (?)`. The package
imports `@nestjs/axios` for its types only, so an application that never calls
`withCorrelation` does not need it installed.


## `CorrelationConfig`

`CorrelationConfig` is the configuration `forRoot()` resolves and provides under
`CORRELATION_CONFIG_TOKEN`.

```ts signature
interface CorrelationConfig {
  header: string;
  generator: () => string;
  validate?: (value: string) => boolean;
}
```

| Field       | What it is                                                                                   |
| ----------- | -------------------------------------------------------------------------------------------- |
| `header`    | the header read from the request and written to the response, in the casing sent on the wire |
| `generator` | mints an id when the request carried none that `validate` accepts                            |
| `validate`  | decides whether an incoming id is reused; defaults to `DEFAULT_CORRELATION_ID_VALIDATOR`     |

`forRoot()` takes a `Partial<CorrelationConfig>` and fills in every field,
`validate` included, so a provider injecting the token never sees a partial
object.

## `CORRELATION_ID_HEADER`

`CORRELATION_ID_HEADER` is the header `forRoot()` uses when `config.header` is
not set.

```ts signature
const CORRELATION_ID_HEADER = 'X-Correlation-Id';
```

No correlation header is registered with IANA. `X-Correlation-Id` and
`X-Request-Id` are the two in common use.

## `CORRELATION_CONFIG_TOKEN`

`CORRELATION_CONFIG_TOKEN` is the injection token of the resolved
`CorrelationConfig`.

```ts signature
const CORRELATION_CONFIG_TOKEN =
  '@evanion/nestjs-correlation-id:CORRELATION_CONFIG';
```

The token is namespaced because `forRoot()` registers it in a `global: true`
module, where a bare `'CORRELATION_CONFIG'` would collide with any other package
that chose the same string. It is a string because a `Symbol()` is unique per
copy of the module: two copies of the package would mint two tokens, and Nest
would fail to resolve one of them. Inject it with `@Inject`:


## `CORRELATION_AXIOS_INTERCEPTOR`

`CORRELATION_AXIOS_INTERCEPTOR` is the token of the provider `withCorrelation()`
registers to attach its interceptor to the axios instance.

```ts signature
const CORRELATION_AXIOS_INTERCEPTOR =
  '@evanion/nestjs-correlation-id:AXIOS_INTERCEPTOR';
```

Nothing injects it. The provider exists so that Nest runs the factory that
registers the interceptor.

## `DEFAULT_CORRELATION_ID_VALIDATOR`

`DEFAULT_CORRELATION_ID_VALIDATOR` accepts an incoming id of 1 to 128 word
characters, dots, colons and hyphens, and rejects everything else.

```ts signature
const DEFAULT_CORRELATION_ID_VALIDATOR: (value: string) => boolean;
```

An accepted id reaches the response header and the application's logs, both
line-oriented, so rejecting CR and LF keeps a header value from splitting a
response or forging a log line. The 128-character cap bounds what one request
appends to every log line it touches; a UUID is 36.
