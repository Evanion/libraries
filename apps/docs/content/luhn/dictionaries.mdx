# Dictionaries

`createLuhn({ dictionary })` builds an instance over an alphabet you choose. It
checks the dictionary once, when the instance is built, and `caseInsensitive`
decides whether input is folded to lowercase.

## The default luhn dictionary

`Luhn` is built over `DEFAULT_DICTIONARY`, the 36 lowercase alphanumerics, and
folds input to lowercase:

```ts twoslash file=libs/luhn/README.md region=default-dictionary

```

`n` is the dictionary's size, and the Luhn sum from the Overview is computed
modulo `n`. The default holds no uppercase letters, which is what makes
lowercasing input sound over it: `O` becomes `o`, and `o` has one index.

## Build a luhn instance over your own dictionary

Baize's pickup codes draw on 32 characters: the default 36 with `i`, `l`, `o`
and `w` dropped, because they are confused when read or heard. The default
dictionary still holds all four, which is why an order code can end in `l`.
`createLuhn` builds an instance over the 32:

```ts twoslash file=libs/luhn/README.md region=pickup-dictionary

```

`pickup.generate` and `pickup.validate` are the same calls `Luhn` carries,
bound to the new alphabet, and `filtered` counts the characters of the input
the dictionary does not hold. `caseInsensitive` is `false` because `createLuhn`
cannot tell whether your alphabet holds case pairs, so it folds only when you
ask.

The order of the string decides which index each character holds, and so every
check character the instance produces. `'0123…xyz'` and `'zyx…3210'` are
different alphabets, and a code built under one is not guaranteed to validate
under the other. Keep the string as a constant, and never sort or deduplicate it
at runtime.

## What createLuhn checks in a luhn dictionary

`createLuhn` throws `InvalidDictionaryError` when the dictionary fails one of
five constraints. The error's `reason` names which:

| `reason`       | What the dictionary must be                                           |
| -------------- | --------------------------------------------------------------------- |
| `not-a-string` | a string                                                              |
| `too-short`    | at least 2 code points long                                           |
| `odd-length`   | an even number of code points long                                    |
| `duplicate`    | free of repeated code points                                          |
| `case-pairs`   | free of case variants of one letter, when `caseInsensitive` is `true` |

`offending` names what failed, so a settings screen can point at it: the
repeated characters for `duplicate`, the case pairs joined as `'Aa'` for
`case-pairs`, and nothing for the other three:

```ts twoslash file=libs/luhn/README.md region=constraints

```

The size has to be even because of the Luhn sum. Counting leftwards from the
check character, every second character contributes
`floor(2x / n) + (2x mod n)` for its index `x`, and for an odd `n` two indices
can contribute the same amount. Over three characters, index 1 doubles to 2 and
contributes 0 + 2, and index 2 doubles to 4 and contributes 1 + 1. Both
contribute 2, so a 1 typed for a 2 at a doubled position is not caught.

Every constraint is checked when `createLuhn` builds the instance, and none at
the call. So `generate` and `validate` never fail on the dictionary, and an
instance you hold cannot produce a code its own `validate` rejects.

`createLuhn` counts code points, not UTF-16 units, so a dictionary of playing

`'🂡🂱🃁🃑'.length` is 8 because each symbol is a surrogate pair. `split('')`

## Case sensitivity in a luhn dictionary

`caseInsensitive` folds input to lowercase before looking it up. It defaults to
`true` when you pass no dictionary and `false` when you pass one:

```ts twoslash file=libs/luhn/README.md region=case-sensitivity

```

The pickup instance refuses `A4KP-9MXA` because `A`, `K`, `P`, `M` and `X` are
not in its dictionary. `validate` drops them, counts them in `filtered`, and
checks what is left. Turning folding on makes it accept the code a customer
typed in capitals. `ALTERNATING_CASE_DICTIONARY` is 62 characters, `0` to `9`
then `Aa Bb … Zz`, and it reads case: `Order` and `order` get different check
characters.

Lowercasing input over a dictionary holding both `A` and `a` would send both to
the index of `a` and leave the index of `A` unreachable, so `createLuhn` refuses
it:

```ts twoslash file=libs/luhn/README.md region=case-pairs

```

## Choosing a luhn dictionary's size

A random string passes `validate` one time in `n`, so a larger dictionary
catches more of what is not a code at all. A size that divides 256 is the other
consideration. It makes `byte % n` pick each character equally often when a
generator such as `@evanion/token` draws random codes over the dictionary, and
each instance's `uniformOverBytes` property reports whether it does. 32 is the
largest size under 36 that divides 256, which is why the pickup alphabet has 32
characters.
