# Generating and validating

`Luhn.generate` computes the check character for a code, and `Luhn.validate`
checks a code that carries one. Both return the phrase they read, and only
`generate` can throw.

## Generate a check character with luhn

`Luhn.generate` takes the code without its check character and returns three
fields:

```ts twoslash file=libs/luhn/README.md region=generate

```

<Probe package="luhn" probe="generate" />

| Field      | What it holds                                                                  |
| ---------- | ------------------------------------------------------------------------------ |
| `phrase`   | the input with every character outside the dictionary dropped, and case folded |
| `checksum` | the check character, one character of the dictionary                           |
| `filtered` | how many characters of the input were dropped                                  |

The phrase, from the Overview, is what the check character was computed over.
`order-2026-0042` and `ORDER 2026/0042` produce the same phrase, so they get
the same `l`.

`generate` does not append `checksum`. Where it goes and what separates it is
yours, and `validate` hands the order number back through `phrase`:

```ts twoslash file=libs/luhn/README.md region=sign-and-read

```

`orderNumberIn` slices `phrase` rather than the string it was given. `phrase` is
the filtered form, so `ORDER 2026 0042 L` and `order-2026-0042-l` both give back
`order20260042`, which is the value to look the order up by.

## Why luhn's generate throws EmptyInputError

`Luhn.generate` throws `EmptyInputError` when no character of its input is in
the dictionary. A check character over nothing carries no information, and
returning one would give `''` and `'--'` the same answer. Catch it where the
input comes from a person:

```ts twoslash file=libs/luhn/README.md region=empty-input

```

`EmptyInputError` is the only error `generate` or `validate` raises. The
dictionary was checked when the instance was built, so nothing else can fail at
the call.

## Validate a code with luhn

`Luhn.validate` treats the last dictionary character of its input as the check
character and never throws:

```ts twoslash file=libs/luhn/README.md region=validate

```

`isValid` is `false` for fewer than two surviving characters, because an order
number and a check character is the minimum. `phrase` here includes the check
character, which is why `orderNumberIn` above slices one off. `generate`'s
`phrase` does not, because the check character did not exist yet.
