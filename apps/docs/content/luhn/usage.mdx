# Generating and validating

`Luhn.generate` computes the check character for a code, and `Luhn.validate`
checks a code that carries one. Both return the phrase they read, and only
`generate` can throw.

## Generate a check character with luhn

`Luhn.generate` takes the code without its check character and returns three
fields:

```ts twoslash file=libs/luhn/README.md region=generate

```

<Probe package="luhn" probe="generate" />

| Field      | What it holds                                                                  |
| ---------- | ------------------------------------------------------------------------------ |
| `phrase`   | the input with every character outside the dictionary dropped, and case folded |
| `checksum` | the check character, one character of the dictionary                           |
| `filtered` | how many characters of the input were dropped                                  |

The phrase, from the Overview, is what the check character was computed over.
`order-2026-0042` and `ORDER 2026/0042` produce the same phrase, so they get
the same `l`.

`generate` does not append `checksum`, so where it goes and what separates it is
yours to decide. `validate` hands the order number back through `phrase`:

```ts twoslash file=libs/luhn/README.md region=sign-and-read

```

`orderNumberIn` slices `phrase` rather than the string it was given, so
`ORDER 2026 0042 L` and `order-2026-0042-l` both give back `order20260042`. The
phrase has lost the hyphens and the case, so store the phrase `generate`
returned when the order was created, and look the order up by it.

## Why luhn's generate throws EmptyInputError

`Luhn.generate` throws `EmptyInputError` when no character of its input is in
the dictionary. Every such input leaves an empty phrase, so a blank form field
and `'--'` would get the same check character, and that character would check
nothing. Catch the error where the input comes from a person:

```ts twoslash file=libs/luhn/README.md region=empty-input

```

`EmptyInputError` is the only error a luhn call raises, and only `generate`
raises it. The dictionary was checked when the instance was built, so nothing
else can fail at the call.

## Validate a code with luhn

`Luhn.validate` treats the last dictionary character of its input as the check
character and never throws:

```ts twoslash file=libs/luhn/README.md region=validate

```

`isValid` is `false` when `phrase` holds fewer than two characters, because an
order number and a check character is the minimum. `validate`'s `phrase`
includes the check character, so the order number is `phrase.slice(0, -1)`.
`generate`'s `phrase` does not, because the check character did not exist yet.

The code below was issued as `order-2026-0042-l`. Type it back in and the
verdict follows `isValid`, so case and hyphens make no difference to it. The
"Change a character" and "Swap two" buttons each break the code, and
`validate` refuses it.

## Refuse stray characters with luhn's filtered count

`filtered` counts the characters `validate` dropped. Baize's receipt prints
`order-2026-0042-l` for a person to read and carries `order20260042l`, with no
separators, in its barcode. A till that reads the barcode can refuse anything
else without reimplementing the filter:

```ts twoslash file=libs/luhn/README.md region=strict-input

```

Counting is by code point, not by UTF-16 unit, so an emoji typed into the field
is one dropped character, not two.
