# @evanion/luhn

A customer reads an order code back over the phone and one digit comes out
wrong. `@evanion/luhn` puts a check character on the code, so `Luhn.validate`
refuses the mistyped one before your database is asked.

## How luhn catches a mistyped code

Baize, the board game shop these examples are set in, prints
`order-2026-0042-l` on a receipt. The `l` at the end is the check character,
computed from every character before it. `Luhn.validate` computes it again from
the code it is given and compares:

The second code has one digit changed. The third has two adjacent digits
swapped. Neither produces `l` again, so both come back `isValid: false`, and the
code never reaches the lookup that would have answered "no such order".

`Luhn.generate` is the call that computed the `l`. It drops every character
outside the dictionary, runs Luhn's fold over the dictionary position of each
character that remains, and turns the total into one more dictionary character.
`Luhn.validate` runs the same fold over the whole code, check character
included, and accepts it when the total is a multiple of the dictionary's size.

## The luhn vocabulary

Every later luhn page uses four words.

- The **dictionary** is the alphabet a code is read against, as one string. Its
  order decides every check character, so the same letters in a different order
  are a different dictionary.
- The **check character** is one character of the dictionary, appended to a
  code. `generate` returns it as `checksum`.
- The **phrase** is the input with every character outside the dictionary
  dropped. It is what the check character is computed over, and both calls
  return it.
- An **instance** is a dictionary with `generate` and `validate` bound to it.
  `Luhn` is the default instance, over `0` to `9` and `a` to `z`.

## What luhn can do

| You want to                                 | What luhn gives you                                               |
| ------------------------------------------- | ----------------------------------------------------------------- |
| put a check character on a code             | `Luhn.generate(code).checksum`                                    |
| refuse a mistyped code                      | `Luhn.validate(code).isValid`                                     |
| accept `ORDER 2026 0042 L` as the same code | characters outside the dictionary dropped, and case folded        |
| check codes drawn from your own alphabet    | `createLuhn({ dictionary })`, which validates the alphabet once   |
| compute a credit card's check digit         | `createLuhn({ dictionary: '0123456789' })`, which is plain mod-10 |
| know whether random bytes pick evenly       | `uniformOverBytes`, true when the dictionary's size divides 256   |

## What a luhn check character catches, and what it does not

- It catches every single-character substitution, at every position, including
  the check character itself.
- It catches every swap of two adjacent characters except one: the first and
  last entries of the dictionary, `0` and `z` in the default.
- It does not prove a code exists. A random string passes one time in 36 under
  the default dictionary, and whether order `2026-0042` was ever placed is a
  question for your database.
- It is not authentication. The algorithm and the dictionary are public, so
  anyone can compute the check character for any string.
- It does not generate codes. `@evanion/token` draws random pickup codes like
  `ORD-a4kp-9mxa` and uses this package for their check character.
