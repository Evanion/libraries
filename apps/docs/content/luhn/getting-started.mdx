# Getting started

By the end of this page your code signs Baize's order number with a check
character, and `Luhn.validate` refuses the same code with one digit mistyped.

## Before you install luhn

- Node 20 or newer, or any browser.
- An ESM project. A CommonJS project needs Node 20.19, 22.12 or newer, whose
  `require()` loads ES modules. An older `require()` fails with
  `ERR_REQUIRE_ESM`.
- No peer dependencies and no runtime dependencies.

## Install luhn

Pick the line for your package manager.

```bash
npm install @evanion/luhn
```

```bash
yarn add @evanion/luhn
```

```bash
pnpm add @evanion/luhn
```

## The one thing luhn is configured by

The dictionary, and the default answers it. `Luhn` is the instance built over
`'0123456789abcdefghijklmnopqrstuvwxyz'`, and it folds input to lowercase before
looking a character up. Take the default and there is nothing to call:
`import { Luhn } from '@evanion/luhn'` is the whole setup.

## Sign an order code and check it

`Luhn.generate` returns the check character for an order number, and
`Luhn.validate` answers whether a code carrying one holds together:

```ts twoslash file=libs/luhn/README.md region=round-trip

```

`checksum` is `l`, and `order-2026-0042-l` is the code the shop prints on the
receipt. `order-2026-0043-l` is the same code with one digit read back wrong,
and `validate` answers `isValid: false` for it, so your counter refuses the code
before the database is asked about it.

The hyphens are not part of what was checked. `generate` drops every character
outside the dictionary before computing, so `ORDER20260042L` validates against
the same `l`.
