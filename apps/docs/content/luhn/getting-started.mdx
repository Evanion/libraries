# Getting started

By the end of this page the shop prints an order code with a check character on
it, and the counter refuses a mistyped one without asking the database.

## Prerequisites

- Node 20 or newer, or any browser.
- ESM. The package ships no `require` condition, so a CommonJS `require()` of it
  raises `ERR_REQUIRE_ESM`.
- No peer dependencies and no runtime dependencies.

## Install

```bash
npm install @evanion/luhn
```

```bash
yarn add @evanion/luhn
```

```bash
pnpm add @evanion/luhn
```

## The one thing to configure

The alphabet, and the default answers it. `Luhn` is built over
`'0123456789abcdefghijklmnopqrstuvwxyz'`, in that order, and folds input to
lowercase before looking a character up. The order is what decides every check
character the package produces, so two dictionaries holding the same characters
in a different order are different alphabets.

Take the default and there is nothing to call:
`import { Luhn } from '@evanion/luhn'` is the whole of the setup. Reach for
`createLuhn` and a dictionary of your own when the codes you already print draw on
a narrower set of characters, which [Dictionaries](/luhn/dictionaries) covers.

## Sign an order code and check it

`Luhn.generate` returns the check character for a body, and `Luhn.validate`
answers whether a code carrying one holds together. The import is the fence's
first line:

```ts twoslash file=libs/luhn/README.md region=round-trip

```

`order-2026-0042-l` is the code the shop prints on a receipt. Read the order
number back one digit wrong and `validate` answers `isValid: false`, so the
counter rejects the code before the database is asked about it.

The hyphens are not part of what was checked. `generate` drops every character
outside the dictionary first, so `ORDER20260042L` and `or-der-2026-0042-l` both
validate against the same check character.
