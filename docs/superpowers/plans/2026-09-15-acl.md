# `@evanion/acl` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build two packages — `@evanion/acl` (a framework-free declarative access-control matrix evaluated locally in any JS runtime) and `@evanion/react-acl` (the React binding: provider, hooks, re-exports).

**Architecture:** A frozen, serializable matrix of permissions (`object.action` keys with `dependsOn` cascade, declarative conditions over a namespaced `subject.*` / `object.*` / `now` context) and a pure `can(subject, key, action, object?, now?)` evaluator returning a `Decision` with an output-only `reason`. The core is built by `tsc` with `@evanion/source` packaging; the React binding is a separate `vite`+`jsdom` package that depends on the core and re-exports its types. Both mirror the existing `feature`/`widget`→`react-widget` conventions exactly.

**Tech Stack:** TypeScript (nodenext), Nx, Vitest, `@evanion/doc-examples` (README doctests), React 18/19 (binding only). No runtime dependencies in the core.

## Conventions to follow (read before starting)

These are established by the existing `feature`/`widget`/`react-widget` packages and the repo-checks. Deviating fails CI:

- **Imports** use `.js` extensions in relative specifiers (nodenext). Every `import`/`export` in `.ts` source files must end in `.js`.
- **Core package build** (`libs/acl`): built by `tsc` via `tsconfig.lib.json` (like `widget`/`feature`), NOT bundled. `tsconfig.lib.json` sets `emitDeclarationOnly: false`, `rootDir: "src"`, `outDir: "dist"`, `types: ["node"]`. The `vite.config.ts` has **no `build` section** and runs tests in `environment: 'node'`.
- **React package build** (`libs/react-acl`): built by `vite` with `vite-plugin-dts` (like `react-widget`), `environment: 'jsdom'`, `'use client'` directive on the client entry.
- **Doctests**: README code blocks marked `ts @import.meta.vitest` run via `@evanion/doc-examples` — `...docExamples()`, `test.includeSource: docExampleSources()`, `includeSource` set. Doctest blocks must import from the package specifier (`@evanion/acl`), not relative paths. `// -> value` claims become assertions.
- **Errors**: construction validates and throws `AclConfigError` subclasses; evaluation is **total** (never throws).
- **Tests**: Vitest, globals `true`. Type tests via `*.test-d.ts` + `typecheck` config in the vite config.
- **Authority**: `docs/superpowers/specs/2026-09-14-acl-design.md` is the specification. Where this plan and the spec disagree, the spec wins and the plan is corrected.
- **Acceptance bar for a semantic test**: a test that covers one rule of the engine must fail when that rule alone is mutated in the implementation. A test that still passes under its own mutation asserts an outcome, not a rule.
- **Repo integration** (required or CI fails):
  - `scripts/verify-packaging.mjs` `LIBS` array: add both packages.
  - `commitlint.config.js` `scope-enum`: add `acl` and `react-acl`.
  - `apps/docs/app/navigation.ts`: add both packages with unique `hue`s.
  - `LICENSE` file per package (copy content from `libs/widget/LICENSE`).
- The plan's commits use scope `acl` / `react-acl`; these must be added to commitlint first (Task 0).

```ts
/** The kind of object an action applies to. A string key in the matrix. */
export type ObjectKey = string;

/** The name of an action a subject can take on an object. */
export type Action = string;

/**
 * An instant, for a `now` condition. A string is parsed as ISO 8601, a number
 * as epoch milliseconds.
 */
export type Instant = string | number | Date;

/** The result of a field-level decision: allowed, denied, or not decidable. */
export type FieldState = 'allowed' | 'denied' | 'unevaluable';

/** Why a field decision landed where it did. Output only. */
export type FieldReason =
  | 'allow'
  | 'not-listed'
  | 'denied'
  | 'targets-failed'
  | 'transition-failed'
  | 'missing-field'
  | 'proposed-required';

/** A condition over the namespaced context. */
export type Condition =
  | { field: 'now'; op: 'before' | 'after'; value: Instant }
  | {
      field: string;
      op: 'eq' | 'ne' | 'in' | 'not-in' | 'contains';
      path?: string;
      value?: unknown;
    };

/** The namespaced evaluation context. */
export interface EvaluationContext {
  subject: Record<string, unknown>;
  object?: Record<string, unknown>;
  /**
   * The clock instant the `now` conditions read. Any `Instant` form, so a
   * hydrated context needs no conversion at the call site. Each entry point
   * settles it to epoch milliseconds once; one that does not parse fails the
   * conditions reading it.
   */
  now?: Instant;
}

/** A field rule: either a value allow-list or a state machine, never both. */
export type FieldConfig =
  | { targets: readonly unknown[] }
  | { transitions: Record<string, readonly unknown[]> };

/**
 * The field rules attached to an action's permission: one name-token list under
 * `fields`, plus one entry per configured field name.
 *
 * `*` and `!name` are authoring syntax and live only in the token list. The
 * decision maps `decideFields` returns carry real field names only.
 */
export interface FieldRules {
  /** An allow-list, or a '*' baseline with '!name' exclusions. */
  fields?: readonly string[];
  [field: string]: readonly string[] | FieldConfig | undefined;
}

/** One activation rule for a permission: an AND-ed set of conditions. */
export interface Rule {
  id?: string;
  when?: readonly Condition[];
}

/** One permission: allows and/or denies, plus optional field rules. */
export interface Permission {
  key: string;
  object: ObjectKey;
  action: Action;
  /** Allow rules, OR-ed. */
  rules?: readonly Rule[];
  /** Deny rules, OR-ed. A matched deny wins over an allow. */
  denyRules?: readonly Rule[];
  /** Permissions that must resolve on for this one to resolve on. */
  dependsOn?: readonly string[];
  /** Field-level rules, write and/or read axis. */
  fields?: FieldRules;
}

/** The canonical matrix: a flat list of permissions. */
export type Matrix = readonly Permission[];

export type Reason =
  | 'allow'
  | 'no-rule-matched'
  | 'denied'
  | 'dependency-off'
  | 'unknown-action'
  | 'unevaluable';

/** The root cause of a cascade: the first ancestor off for a non-dependency reason. */
export interface Cause {
  key: string;
  reason: Reason;
  rule?: string;
  /** The paths to fetch when `reason` is `unevaluable`. */
  missing?: readonly string[];
}

/** One action-level decision. */
export interface Decision {
  key: string;
  allowed: boolean;
  reason: Reason;
  rule?: string;
  blockedBy?: string;
  cause?: Cause;
  missing?: readonly string[];
}

/** A decision over every field of an action. */
export interface FieldDecision {
  /** True only when the action is allowed and every field is allowed. */
  allowed: boolean;
  /** The action-level decision the field maps hang off, cascade resolved. */
  action: Decision;
  fields: Record<string, FieldState>;
  reasons: Record<string, FieldReason>;
}

/** The field half of a `FieldDecision`, which `decideFields` returns. */
export type FieldOutcome = Omit<FieldDecision, 'action'>;
```

```ts
import type { ObjectKey } from './types.js';

/** Base class for every error this library throws. All raised at construction. */
export class AclConfigError extends Error {
  constructor(message: string) {
    super(message);
    this.name = 'AclConfigError';
  }
}

/** A dependency cycle. Rejected because resolution order is undefined. */
export class FeatureCycleError extends AclConfigError {
  readonly path: readonly string[];
  constructor(path: readonly string[]) {
    super(`permission dependency cycle: ${path.join(' -> ')}`);
    this.name = 'FeatureCycleError';
    this.path = path;
  }
}

/** A `dependsOn` naming a permission that is not configured. */
export class UnknownDependencyError extends AclConfigError {
  readonly key: string;
  readonly dependency: string;
  constructor(key: string, dependency: string) {
    super(
      `permission "${key}" depends on "${dependency}", which is not configured`,
    );
    this.name = 'UnknownDependencyError';
    this.key = key;
    this.dependency = dependency;
  }
}

/** Two permissions with the same key. */
export class DuplicatePermissionError extends AclConfigError {
  readonly key: string;
  constructor(key: string) {
    super(`duplicate permission key "${key}"`);
    this.name = 'DuplicatePermissionError';
    this.key = key;
  }
}

/** A `!` entry in `fields()` has no `*` baseline. */
export class DenyWithoutBaselineError extends AclConfigError {
  constructor(field: string) {
    super(
      `field "!${field}" has no baseline: a deny entry requires a '*' baseline (or an explicit allow-list) to say what is allowed`,
    );
    this.name = 'DenyWithoutBaselineError';
  }
}

/** A `!` entry mixed into an explicit allow-list. */
export class BangInAllowListError extends AclConfigError {
  constructor(field: string) {
    super(
      `field "!${field}" is denied inside an explicit allow-list, which already denies anything not listed`,
    );
    this.name = 'BangInAllowListError';
  }
}

/** Both `targets` and `transitions` on one field. */
export class TargetsTransitionsConflictError extends AclConfigError {
  constructor(field: string) {
    super(
      `field "${field}" configures both targets and transitions, which are mutually exclusive`,
    );
    this.name = 'TargetsTransitionsConflictError';
  }
}

/** An unknown object kind at runtime on a typed (local) matrix. */
export class UnknownObjectKeyError extends AclConfigError {
  readonly key: ObjectKey;
  constructor(key: ObjectKey) {
    super(`object kind "${key}" is not configured in this matrix`);
    this.name = 'UnknownObjectKeyError';
    this.key = key;
  }
}

/** An unknown permission key at runtime on a typed (local) matrix. */
export class UnknownPermissionError extends AclConfigError {
  readonly key: string;
  constructor(key: string) {
    super(`permission "${key}" is not configured in this matrix`);
    this.name = 'UnknownPermissionError';
    this.key = key;
  }
}

/**
 * A `key` that is not `${object}.${action}`. Lookup is by the key string, so a
 * permission whose key disagrees with its object and action is unreachable: a
 * silent hole in the matrix rather than a visible failure.
 */
export class KeyMismatchError extends AclConfigError {
  readonly key: string;
  readonly object: ObjectKey;
  readonly action: string;
  constructor(key: string, object: ObjectKey, action: string) {
    super(
      `permission key "${key}" is not "${object}.${action}": a key must be exactly \`\${object}.\${action}\``,
    );
    this.name = 'KeyMismatchError';
    this.key = key;
    this.object = object;
    this.action = action;
  }
}

/**
 * A matrix node that does not round-trip through JSON — a function, a `Date`, a
 * `Map`, a captured object reference. The matrix ships to the client as JSON,
 * so a node that survives construction but not serialization gives the two
 * runtimes different matrices.
 */
export class NotSerializableError extends AclConfigError {
  readonly key: string;
  readonly path: string;
  constructor(key: string, path: string, kind: string) {
    super(
      `permission "${key}" holds a ${kind} at ${path}, which does not round-trip through JSON`,
    );
    this.name = 'NotSerializableError';
    this.key = key;
    this.path = path;
  }
}
```

```ts
import type { Condition, EvaluationContext, Instant } from './types.js';

function toEpoch(value: Instant): number {
  if (value instanceof Date) return value.getTime();
  if (typeof value === 'number') return value;
  return new Date(value).getTime();
}

/**
 * Reads a namespaced path ("subject.id", "object.authorId") or the bare "now"
 * from a context, with a hasOwnProperty guard so prototype-chain fields never
 * resolve. Returns undefined when the scope or field is absent.
 */
function readPath(ctx: EvaluationContext, path: string): unknown {
  if (path === 'now') return ctx.now;
  const dot = path.indexOf('.');
  if (dot === -1) return undefined;
  const scope = path.slice(0, dot);
  const field = path.slice(dot + 1);
  const bag =
    scope === 'subject'
      ? ctx.subject
      : scope === 'object'
        ? ctx.object
        : undefined;
  if (!bag) return undefined;
  return Object.prototype.hasOwnProperty.call(bag, field)
    ? bag[field]
    : undefined;
}

function equal(a: unknown, b: unknown): boolean {
  // Literal vs literal: strict.
  return a === b;
}

/** Whether a condition holds for a context. Never throws. */
export function evaluateCondition(
  condition: Condition,
  ctx: EvaluationContext,
): boolean {
  if (condition.op === 'before' || condition.op === 'after') {
    const now = ctx.now;
    if (Number.isNaN(now)) return false;
    const boundary = toEpoch(condition.value);
    if (Number.isNaN(boundary)) return false;
    return condition.op === 'before' ? now < boundary : now > boundary;
  }

  const actual = readPath(ctx, condition.field);
  // An absent field never holds, including for negative operators: `ne` on an
  // absent field is unevaluable, not "true because it is not equal".
  if (actual === undefined) return false;

  switch (condition.op) {
    case 'eq':
      // A path operand (field vs field) compares the two resolved values.
      if (condition.path !== undefined) {
        const other = readPath(ctx, condition.path);
        return other !== undefined && equal(actual, other);
      }
      return equal(actual, condition.value);
    case 'ne':
      if (condition.path !== undefined) {
        const other = readPath(ctx, condition.path);
        return other !== undefined && !equal(actual, other);
      }
      return !equal(actual, condition.value);
    case 'in':
      return Array.isArray(condition.value) && condition.value.includes(actual);
    case 'not-in':
      return (
        Array.isArray(condition.value) && !condition.value.includes(actual)
      );
    case 'contains':
      return Array.isArray(actual) && actual.includes(condition.value);
    default:
      return false;
  }
}
```

```ts
import {
  DuplicatePermissionError,
  FeatureCycleError,
  UnknownDependencyError,
} from './errors.js';
import type { Permission } from './types.js';

export interface PermissionGraph {
  /** Every key, ordered so a permission always follows its dependencies. */
  readonly order: readonly string[];
  /** Transitive dependants of `key`, in dependency order. */
  dependants(key: string): readonly string[];
  /**
   * Transitive dependencies of `key`, in dependency order, excluding `key`.
   *
   * `can` folds this list to build the resolved map a cascade reads, so a
   * single-permission call resolves the same chain `capabilities` does.
   */
  ancestors(key: string): readonly string[];
}

/** Validates the dependency graph and returns a resolution order. */
export function buildGraph(
  permissions: readonly Permission[],
): PermissionGraph {
  const parents = new Map<string, readonly string[]>();

  for (const permission of permissions) {
    if (parents.has(permission.key)) {
      throw new DuplicatePermissionError(permission.key);
    }
    parents.set(permission.key, permission.dependsOn ?? []);
  }

  for (const [key, dependsOn] of parents) {
    for (const parent of dependsOn) {
      if (!parents.has(parent)) {
        throw new UnknownDependencyError(key, parent);
      }
    }
  }

  const order: string[] = [];
  const finished = new Set<string>();
  const onPath = new Set<string>();
  const path: string[] = [];

  const visit = (key: string): void => {
    if (finished.has(key)) return;
    if (onPath.has(key)) {
      const start = path.indexOf(key);
      throw new FeatureCycleError([...path.slice(start), key]);
    }
    onPath.add(key);
    path.push(key);
    for (const parent of parents.get(key) ?? []) visit(parent);
    path.pop();
    onPath.delete(key);
    finished.add(key);
    order.push(key);
  };

  for (const key of parents.keys()) visit(key);

  const position = new Map<string, number>(order.map((k, i) => [k, i]));
  const children = new Map<string, string[]>(order.map((key) => [key, []]));
  for (const [key, dependsOn] of parents) {
    for (const parent of dependsOn) children.get(parent)?.push(key);
  }

  const dependants = (key: string): readonly string[] => {
    const seen = new Set<string>();
    const queue = [...(children.get(key) ?? [])];
    while (queue.length) {
      const next = queue.shift() as string;
      if (seen.has(next)) continue;
      seen.add(next);
      queue.push(...(children.get(next) ?? []));
    }
    return [...seen].sort(
      (a, b) => (position.get(a) ?? 0) - (position.get(b) ?? 0),
    );
  };

  const ancestors = (key: string): readonly string[] => {
    const seen = new Set<string>();
    const queue = [...(parents.get(key) ?? [])];
    while (queue.length) {
      const next = queue.shift() as string;
      if (seen.has(next)) continue;
      seen.add(next);
      queue.push(...(parents.get(next) ?? []));
    }
    return [...seen].sort(
      (a, b) => (position.get(a) ?? 0) - (position.get(b) ?? 0),
    );
  };

  return { order, dependants, ancestors };
}
```

The canonical matrix holds an action's field rules as one `fields` object: a
`fields` array of name tokens (`['body', 'title']`, or `['*', '!status']`), plus
one entry per configured field name mapped to a `FieldConfig`. `*` and `!name`
are authoring syntax and live only in that token list.

The rules this task enforces, all raised at construction:

- `key` is exactly `` `${object}.${action}` `` → `KeyMismatchError`. Lookup is by
  the key string, so a permission whose key disagrees with its object and action
  is unreachable.
- a `.` in `object` or `action` → `InvalidPermissionError`. The key is the two
  parts joined on a dot, so a part carrying the delimiter makes two permissions
  share one key. `:` stays legal: an object kind namespaced by origin is spelled
  `orders:invoice`.
- a `!` entry with no `*` baseline → `DenyWithoutBaselineError`.
- a `!` entry alongside a named allow entry → `BangInAllowListError`; an explicit
  allow-list already denies everything not listed.
- `targets` and `transitions` on one field → `TargetsTransitionsConflictError`.
- an op outside `eq` / `ne` / `in` / `not-in` / `contains`, and a `now` condition
  whose op is not `before` / `after`.
- a condition `field` or `path` outside `subject.<field>` / `object.<field>` /
  `now`, including one nesting below its scope. Field-name validity itself is the
  typed path's compile-time guarantee (Task 10), and a foreign matrix has no
  types to check against.
- an operator paired with a comparand it cannot use. See the spec's validation
  list for the pairing per op.
- a node the structured clone algorithm refuses — a function, a symbol, a
  structure nested deeper than it walks → `InvalidMatrixError`, reported against
  the permission holding it.

`NotSerializableError` is not implemented. It named a `Date` as unserializable,
and `Instant` accepts a `Date`, so the two rules contradict; the JSON round-trip
check is open, and the clone guard above covers the half of it that decides
whether construction throws.

Duplicate keys, unknown dependencies and cycles belong to `buildGraph` (Task 4).

```ts
import {
  BangInAllowListError,
  DenyWithoutBaselineError,
  KeyMismatchError,
  NotSerializableError,
  TargetsTransitionsConflictError,
} from './errors.js';
import type { Condition, FieldConfig, Matrix, Permission } from './types.js';

const OPS = new Set(['eq', 'ne', 'in', 'not-in', 'contains']);

function assertNamespace(path: string, label: string): void {
  if (path === 'now') return;
  const scope = path.slice(0, path.indexOf('.'));
  if (scope !== 'subject' && scope !== 'object') {
    throw new Error(
      `invalid condition ${label} "${path}": must be subject.*, object.* or now`,
    );
  }
}

function assertCondition(condition: Condition): void {
  if (condition.field === 'now') {
    if (condition.op !== 'before' && condition.op !== 'after') {
      throw new Error('invalid condition: now supports before and after only');
    }
    return;
  }
  assertNamespace(condition.field, 'field');
  if (!OPS.has(condition.op)) {
    throw new Error(`invalid condition op "${condition.op}"`);
  }
  if (condition.path !== undefined) assertNamespace(condition.path, 'path');
}

/**
 * The kind of a value that does not survive JSON.stringify -> JSON.parse
 * unchanged, or undefined when the value round-trips.
 */
function notSerializable(value: unknown): string | undefined {
  if (value === null) return undefined;
  const type = typeof value;
  if (type === 'string' || type === 'number' || type === 'boolean') {
    return undefined;
  }
  if (type !== 'object') return type;
  if (Array.isArray(value)) {
    for (const entry of value) {
      const kind = notSerializable(entry);
      if (kind) return kind;
    }
    return undefined;
  }
  const prototype = Object.getPrototypeOf(value) as object | null;
  if (prototype !== Object.prototype && prototype !== null) {
    return (value as object).constructor?.name ?? 'class instance';
  }
  for (const entry of Object.values(value as Record<string, unknown>)) {
    const kind = notSerializable(entry);
    if (kind) return kind;
  }
  return undefined;
}

function assertSerializable(permission: Permission): void {
  const rules = [...(permission.rules ?? []), ...(permission.denyRules ?? [])];
  for (const [index, rule] of rules.entries()) {
    for (const [at, condition] of (rule.when ?? []).entries()) {
      const kind = notSerializable(condition.value);
      if (kind) {
        throw new NotSerializableError(
          permission.key,
          `rules[${index}].when[${at}].value`,
          kind,
        );
      }
    }
  }
  const kind = notSerializable(permission.fields ?? {});
  if (kind) throw new NotSerializableError(permission.key, 'fields', kind);
}

function assertFieldConfig(field: string, config: FieldConfig): void {
  if ('targets' in config && 'transitions' in config) {
    throw new TargetsTransitionsConflictError(field);
  }
}

function assertFieldRules(permission: Permission): void {
  const rules = permission.fields ?? {};
  const names = rules['fields'] as readonly string[] | undefined;

  if (names) {
    const baseline = names.includes('*');
    const listed = names.filter((n) => n !== '*' && !n.startsWith('!'));
    for (const name of names) {
      if (!name.startsWith('!')) continue;
      const field = name.slice(1);
      if (!baseline) throw new DenyWithoutBaselineError(field);
      if (listed.length > 0) throw new BangInAllowListError(field);
    }
  }

  for (const [field, config] of Object.entries(rules)) {
    if (field === 'fields' || !config) continue;
    assertFieldConfig(field, config as FieldConfig);
  }
}

/**
 * Validates a canonical matrix's keys, conditions, field rules and
 * serializability. The dependency graph is `buildGraph`'s. Throws an
 * AclConfigError subclass.
 */
export function validateMatrix(matrix: Matrix): void {
  for (const permission of matrix) {
    if (permission.key !== `${permission.object}.${permission.action}`) {
      throw new KeyMismatchError(
        permission.key,
        permission.object,
        permission.action,
      );
    }
    for (const rule of [
      ...(permission.rules ?? []),
      ...(permission.denyRules ?? []),
    ]) {
      for (const condition of rule.when ?? []) assertCondition(condition);
    }
    assertFieldRules(permission);
    assertSerializable(permission);
  }
}
```

### Task 6: Core evaluate (precedence, deny, cascade, unevaluable)

**Files:**

- Create: `libs/acl/src/evaluate.ts`
- Test: `libs/acl/src/evaluate.test.ts`

`decide(permission, ctx, resolved)` is pure in its three arguments. `resolved`
carries the decisions of the permission's transitive dependencies; Task 8 folds
it. The precedence order is the whole engine and is defined once, here. A
definite outcome beats an undecidable one; among definite outcomes, deny beats
allow:

1. a deny rule MATCHES → `denied`
2. a dependency resolved off → `dependency-off`, with `blockedBy` and `cause`
3. the allow side definitely FAILS → `no-rule-matched`
4. the deny side is UNDECIDABLE → `unevaluable`, naming the deny rule, with
   `missing` unioned across both sides
5. an allow rule MATCHES → `allow`
6. the allow side is UNDECIDABLE → `unevaluable`
7. otherwise → `no-rule-matched`

A rule MATCHES when every condition holds, FAILS when any condition definitely
fails, and is UNDECIDABLE otherwise. A side MATCHES if any rule matches, is
UNDECIDABLE if no rule matches and at least one is undecidable, and FAILS
otherwise.

Two rules decide what "could not be decided" means, and both are load-bearing:

- **A condition is object-dependent when either operand reads `object.*`**, its
  `field` or its `path`. A condition comparing an object path against a literal
  comparand (`{ field: 'object.status', op: 'eq', value: 'published' }`) is
  object-dependent exactly like one comparing two paths. Detecting only the
  `path` operand makes a literal-comparand rule evaluate against an absent
  object and report a definite `no-rule-matched` where the answer is unknown.
- **A rule is undecidable only when every condition that does not read the
  object holds** and at least one condition does read it while no instance is
  present. A rule with a false object-independent condition is a definite
  non-match whatever the object would have been, so it reports `no-match`, not
  undecidable. This is what makes the spec's mixed-branch case come out
  `allow`: `or(eq('object.authorId', 'subject.id'), always)` with no instance
  allows on the `always` branch.

A deny rule denies only on a definite match; an undecidable deny does not deny.

```ts
import { evaluateCondition } from './conditions.js';
import type {
  Cause,
  Condition,
  Decision,
  EvaluationContext,
  Permission,
  Rule,
} from './types.js';

function ruleId(rule: Rule, index: number): string {
  return rule.id ?? `#${index}`;
}

/** The object paths a condition reads: its field, its path operand, or both. */
function objectPaths(condition: Condition): readonly string[] {
  const paths: string[] = [];
  if (condition.field.startsWith('object.')) paths.push(condition.field);
  if (condition.path?.startsWith('object.')) paths.push(condition.path);
  return paths;
}

type RuleOutcome =
  | { state: 'match'; rule: string }
  | { state: 'no-match'; rule: string }
  | { state: 'undecidable'; rule: string; missing: readonly string[] };

/**
 * Whether one rule matches, definitely does not, or cannot be decided.
 *
 * The conditions in a rule are AND-ed. A condition that reads the object with
 * no instance present is set aside rather than evaluated against `undefined`.
 * The rule is undecidable only if every remaining condition holds: one false
 * object-independent condition makes the rule a definite non-match whatever the
 * object would have been.
 */
function ruleOutcome(
  rule: Rule,
  index: number,
  ctx: EvaluationContext,
): RuleOutcome {
  const id = ruleId(rule, index);
  const missing: string[] = [];
  for (const condition of rule.when ?? []) {
    const paths = objectPaths(condition);
    if (paths.length > 0 && ctx.object === undefined) {
      missing.push(...paths);
      continue;
    }
    if (!evaluateCondition(condition, ctx)) {
      return { state: 'no-match', rule: id };
    }
  }
  if (missing.length > 0) {
    return { state: 'undecidable', rule: id, missing: [...new Set(missing)] };
  }
  return { state: 'match', rule: id };
}

/** The allow side: steps 3, 5, 6 and 7 of the precedence order. */
function rulesAllow(permission: Permission, ctx: EvaluationContext): Decision {
  const undecided: string[] = [];
  for (const [index, rule] of (permission.rules ?? []).entries()) {
    const outcome = ruleOutcome(rule, index, ctx);
    if (outcome.state === 'match') {
      return {
        key: permission.key,
        allowed: true,
        reason: 'allow',
        rule: outcome.rule,
      };
    }
    if (outcome.state === 'undecidable') undecided.push(...outcome.missing);
  }
  if (undecided.length > 0) {
    return {
      key: permission.key,
      allowed: false,
      reason: 'unevaluable',
      missing: [...new Set(undecided)],
    };
  }
  return { key: permission.key, allowed: false, reason: 'no-rule-matched' };
}

function blockingParent(
  permission: Permission,
  resolved: ReadonlyMap<string, { readonly allowed: boolean }>,
): string | undefined {
  for (const parent of permission.dependsOn ?? []) {
    const decision = resolved.get(parent);
    if (!decision || !decision.allowed) return parent;
  }
  return undefined;
}

function rootCause(
  parent: string,
  resolved: ReadonlyMap<string, Decision>,
): Cause {
  let at = parent;
  const seen = new Set<string>([at]);
  for (;;) {
    const decision = resolved.get(at);
    if (!decision) return { key: at, reason: 'no-rule-matched' };
    if (
      decision.reason !== 'dependency-off' ||
      decision.blockedBy === undefined
    ) {
      const cause: Cause = { key: at, reason: decision.reason };
      if (decision.rule) cause.rule = decision.rule;
      return cause;
    }
    at = decision.blockedBy;
    if (seen.has(at)) return { key: at, reason: decision.reason };
    seen.add(at);
  }
}

/**
 * Decides one permission. Pure in `(permission, ctx, resolved)`.
 *
 * Precedence, defined once:
 * 1. a deny rule matches -> denied
 * 2. a dependency resolved off -> dependency-off
 * 3. the allow side definitely fails -> no-rule-matched
 * 4. the deny side is undecidable -> unevaluable
 * 5. an allow rule matches -> allow
 * 6. the allow side is undecidable -> unevaluable
 * 7. otherwise -> no-rule-matched
 *
 * `resolved` holds the decisions of this permission's transitive dependencies.
 * A caller that passes an empty map makes every permission with `dependsOn`
 * report `dependency-off`, whatever its rules say.
 */
export function decide(
  permission: Permission,
  ctx: EvaluationContext,
  resolved: ReadonlyMap<string, Decision>,
): Decision {
  for (const [index, deny] of (permission.denyRules ?? []).entries()) {
    const outcome = ruleOutcome(deny, index, ctx);
    if (outcome.state === 'match') {
      return {
        key: permission.key,
        allowed: false,
        reason: 'denied',
        rule: outcome.rule,
      };
    }
  }

  const blocked = blockingParent(permission, resolved);
  if (blocked !== undefined) {
    return {
      key: permission.key,
      allowed: false,
      reason: 'dependency-off',
      blockedBy: blocked,
      cause: rootCause(blocked, resolved),
    };
  }

  return rulesAllow(permission, ctx);
}
```

**Files:**

Read and write are separate axes. Read is a projection hint, so `targets` and
`transitions` apply to write only and the read axis reads the name token list
alone. Each field decision is tri-state, and the top-level `allowed` is true
only when every field is `allowed`.

`*` and `!name` are resolved at the top of `decideFields` into a baseline flag,
an allowed set and a denied set. **Neither token may reach the `fields` or
`reasons` maps**: those carry real field names only, and a caller keying a form
on `'*'` or `'!status'` gets a field that does not exist. The field universe is
the object's own keys, plus the keys of `proposed` on the write axis, plus the
configured field names, plus the real names the token list mentions — never the
tokens themselves, from whichever of those sources they arrive. A proposed key
nobody decided is a key nobody denied, so the write axis decides them all.

Reasons are distinct because the caller fixes them differently:
`proposed-required` means a `targets` or `transitions` rule was evaluated with
no proposed value, fixed by passing a proposed state; `missing-field` means the
object lacks the field a rule reads, fixed by passing a complete object. A bang
entry reports `denied`; a name absent from an explicit allow-list reports
`not-listed`.

```ts
import type {
  EvaluationContext,
  FieldConfig,
  FieldDecision,
  FieldReason,
  FieldRules,
  FieldState,
  Permission,
} from './types.js';

interface Outcome {
  state: FieldState;
  reason: FieldReason;
}

/** The token list resolved to real names: `*` and `!name` stop here. */
interface Names {
  baseline: boolean;
  allowed: ReadonlySet<string>;
  denied: ReadonlySet<string>;
}

function hasOwn(bag: object, key: string): boolean {
  return Object.prototype.hasOwnProperty.call(bag, key);
}

function resolveNames(
  tokens: readonly string[] | undefined,
): Names | undefined {
  if (!tokens) return undefined;
  const allowed = new Set<string>();
  const denied = new Set<string>();
  let baseline = false;
  for (const token of tokens) {
    if (token === '*') baseline = true;
    else if (token.startsWith('!')) denied.add(token.slice(1));
    else allowed.add(token);
  }
  return { baseline, allowed, denied };
}

function byName(field: string, names: Names): Outcome {
  if (names.denied.has(field)) return { state: 'denied', reason: 'denied' };
  if (names.baseline || names.allowed.has(field)) {
    return { state: 'allowed', reason: 'allow' };
  }
  return { state: 'denied', reason: 'not-listed' };
}

function byConfig(
  field: string,
  config: FieldConfig,
  ctx: EvaluationContext,
  proposed: Record<string, unknown> | undefined,
): Outcome {
  const hasProposed = proposed !== undefined && hasOwn(proposed, field);
  const next = proposed?.[field];

  if ('targets' in config) {
    if (!hasProposed) {
      return { state: 'unevaluable', reason: 'proposed-required' };
    }
    return config.targets.includes(next)
      ? { state: 'allowed', reason: 'allow' }
      : { state: 'denied', reason: 'targets-failed' };
  }

  const object = ctx.object;
  if (!object || !hasOwn(object, field)) {
    return { state: 'unevaluable', reason: 'missing-field' };
  }
  if (!hasProposed) {
    return { state: 'unevaluable', reason: 'proposed-required' };
  }
  const edges = config.transitions[String(object[field])];
  return Array.isArray(edges) && edges.includes(next)
    ? { state: 'allowed', reason: 'allow' }
    : { state: 'denied', reason: 'transition-failed' };
}

/**
 * The field-level decision for one permission on one axis.
 *
 * Read is projection only: targets and transitions are write concepts, so a
 * read field is decided by the name list alone. Missing data yields
 * `unevaluable`, never a silent allow or deny.
 */
export function decideFields(
  permission: Permission,
  ctx: EvaluationContext,
  axis: 'read' | 'write',
  proposed?: Record<string, unknown>,
): FieldDecision {
  const rules: FieldRules = permission.fields ?? {};
  const names = resolveNames(rules['fields'] as readonly string[] | undefined);

  const configured = Object.keys(rules).filter((key) => key !== 'fields');
  const universe = new Set<string>([
    ...(ctx.object ? Object.keys(ctx.object) : []),
    ...configured,
    ...(names ? [...names.allowed, ...names.denied] : []),
  ]);

  const fields: FieldDecision['fields'] = {};
  const reasons: FieldDecision['reasons'] = {};

  for (const field of universe) {
    const config = rules[field] as FieldConfig | undefined;
    const named = names ? byName(field, names) : undefined;

    if (named && named.state === 'denied') {
      fields[field] = named.state;
      reasons[field] = named.reason;
      continue;
    }

    if (axis === 'write' && config) {
      const outcome = byConfig(field, config, ctx, proposed);
      fields[field] = outcome.state;
      reasons[field] = outcome.reason;
      continue;
    }

    const outcome = named ?? { state: 'allowed', reason: 'allow' };
    fields[field] = outcome.state as FieldState;
    reasons[field] = outcome.reason as FieldReason;
  }

  return {
    allowed: Object.values(fields).every((state) => state === 'allowed'),
    fields,
    reasons,
  };
}
```

Every entry point takes `(subject, key, action, object?, now?)`, in that order.
`key` names the object kind; `object` is the instance.

`can`, `canMany` and `authorize` each resolve the permission's transitive
dependencies before deciding it, and hand `decide` the resulting map. A call
that hands `decide` an empty map makes every permission with `dependsOn` report
`dependency-off` regardless of its rules, so `can` and `capabilities` would give
opposite answers for the same input. `graph.ancestors(key)` is the fold order.

A dependency is decided against the same context as the permission that depends
on it when the two name the same object kind, and against an object-free context
otherwise. Reading one kind's instance through another kind's `object.*` paths
is the field collision the namespaced context exists to prevent.

Field rules are leaf-level and never cascade: `decideFields` decides a field
against that permission's own rules and nothing else. The **action** gate is
what `canFields` adds on top. It resolves the same cascade `can` resolves and
returns it as `FieldDecision.action`, and `allowed` is the action's `allowed`
AND every field's. Without it `canFields` reports a field-level allow for an
action the engine refuses.

```ts
function deepFreeze<T>(value: T): T {
  if (value === null || typeof value !== 'object') return value;
  for (const nested of Object.values(value)) deepFreeze(nested);
  return Object.freeze(value);
}

export function createPolicy(
  matrix: Matrix,
  options: AccessOptions = {},
): Access {
  validateMatrix(matrix);
  const frozen = deepFreeze(structuredClone(matrix)) as Matrix;
  const graph = buildGraph(frozen);
  const index = new Map(frozen.map((p) => [p.key, p] as const));
  const kinds = new Set(frozen.map((p) => p.object));
  const closed = options.closed ?? false;
  const version = options.version;

  const permissionFor = (
    key: string,
    action: string,
  ): Permission | undefined => {
    const permission = index.get(`${key}.${action}`);
    if (permission) return permission;
    if (closed) return undefined;
    throw new UnknownPermissionError(`${key}.${action}`);
  };

  const assertKind = (key: string): void => {
    if (!closed && !kinds.has(key)) throw new UnknownObjectKeyError(key);
  };

  const ctxWith = (
    subject: Subject,
    object: Record<string, unknown> | undefined,
    now: Instant | undefined,
  ): ResolvedContext => ({
    subject: subject as Record<string, unknown>,
    object,
    now: now === undefined ? Date.now() : settleNow(now),
  });

  /**
   * The decisions of `permission`'s transitive dependencies, folded in
   * dependency order. A dependency of another object kind is decided without
   * the instance: its `object.*` paths name a different shape.
   */
  const resolveFor = (
    permission: Permission,
    ctx: EvaluationContext,
  ): Map<string, Decision> => {
    const resolved = new Map<string, Decision>();
    for (const key of graph.ancestors(permission.key)) {
      const ancestor = index.get(key);
      if (!ancestor) continue;
      const ancestorCtx =
        ancestor.object === permission.object
          ? ctx
          : { ...ctx, object: undefined };
      resolved.set(key, decide(ancestor, ancestorCtx, resolved));
    }
    return resolved;
  };

  const unknown = (key: string, action: string): Decision => ({
    key: `${key}.${action}`,
    allowed: false,
    reason: 'unknown-action',
  });

  const can = (
    subject: Subject,
    key: string,
    action: string,
    object?: Record<string, unknown>,
    now?: Instant,
  ): Decision => {
    assertKind(key);
    const permission = permissionFor(key, action);
    if (!permission) return unknown(key, action);
    const ctx = ctxWith(subject, object, now);
    return decide(permission, ctx, resolveFor(permission, ctx));
  };

  const canMany = (
    subject: Subject,
    key: string,
    action: string,
    objects: readonly Record<string, unknown>[],
    now?: Instant,
  ): Decision[] => {
    assertKind(key);
    const permission = permissionFor(key, action);
    if (!permission) return objects.map(() => unknown(key, action));
    const at = ctxWith(subject, undefined, now).now;
    return objects.map((object) => {
      const ctx = ctxWith(subject, object, at);
      return decide(permission, ctx, resolveFor(permission, ctx));
    });
  };

  const canFields = (
    subject: Subject,
    key: string,
    action: string,
    object: Record<string, unknown>,
    axis: 'read' | 'write',
    proposed?: Record<string, unknown>,
    now?: Instant,
  ): FieldDecision => {
    assertKind(key);
    const permission = permissionFor(key, action);
    if (!permission) {
      return {
        allowed: false,
        action: {
          key: `${key}.${action}`,
          allowed: false,
          reason: 'unknown-action',
        },
        fields: {},
        reasons: {},
      };
    }
    // Field rules are leaf-level: they never cascade through dependsOn. The
    // action gate does, and it is composed here.
    const ctx = ctxWith(subject, object, now);
    const decision = decideCascaded(permission, ctx);
    const outcome = decideFields(permission, ctx, axis, proposed);
    return {
      allowed: decision.allowed && outcome.allowed,
      action: decision,
      fields: outcome.fields,
      reasons: outcome.reasons,
    };
  };

  const capabilities = (
    subject: Subject,
    now?: Instant,
  ): Record<string, Decision> => {
    const ctx = ctxWith(subject, undefined, now);
    const resolved = new Map<string, Decision>();
    for (const key of graph.order) {
      const permission = index.get(key);
      if (!permission) continue;
      resolved.set(key, decide(permission, ctx, resolved));
    }
    return Object.fromEntries(resolved);
  };

  const authorize = (
    subject: Subject,
    options?: { now?: Instant },
  ): Authorized => {
    const now =
      options?.now === undefined ? Date.now() : settleNow(options.now);
    return {
      can: (key, action, object) => can(subject, key, action, object, now),
      canMany: (key, action, objects) =>
        canMany(subject, key, action, objects, now),
      canFields: (key, action, object, axis, proposed) =>
        canFields(subject, key, action, object, axis, proposed, now),
      capabilities: () => capabilities(subject, now),
    };
  };

  const object = (key: string): BoundObject => {
    assertKind(key);
    return {
      can: (subject, action, instance, now) =>
        can(subject, key, action, instance, now),
      canMany: (subject, action, instances, now) =>
        canMany(subject, key, action, instances, now),
      canFields: (subject, action, instance, axis, proposed, now) =>
        canFields(subject, key, action, instance, axis, proposed, now),
    };
  };

  return {
    get matrix() {
      return frozen;
    },
    get version() {
      return version;
    },
    can,
    canMany,
    canFields,
    capabilities,
    authorize,
    object,
  };
}
```

### Task 10: Typed authoring — the chained builder

`policy<Subject>()` names the subject once and returns a builder. Each `.for()`
call names one object kind, binds its object type, and hands a **contextually
typed parameter** to a block. The condition helpers are methods on that
parameter, so they see both `Subject` and the block's object type:

```ts
const access = policy<Subject>()
  .for<'comment', Comment>('comment', (p) =>
    p
      .allow(
        'update',
        p.or(
          p.eq('object.authorId', 'subject.id'),
          p.contains('subject.roles', 'editor'),
        ),
      )
      .fields({
        status: { transitions: { draft: ['published'], published: [] } },
      })
      .allow('publish', p.contains('subject.roles', 'editor'))
      .dependsOn('comment.update')
      .deny('delete', p.eq('object.status', 'published'))
      .allow('create', p.always)
      .allow('read', p.always)
      .fields(['*', '!status']),
  )
  .for<'media', Media>('media', (p) =>
    p.allow('read', p.eq('object.ownerId', 'subject.id')),
  );
```

`policy<Subject>()` is a call returning a builder rather than
`policy<Subject>(config)` taking the config directly, because TypeScript has no
partial type-argument inference: naming `Subject` in `policy<Subject>(config)`
forces every other type parameter to be named too, and letting them infer
discards `Subject`. The extra call is what lets `Subject` be explicit while each
`.for()` infers its own object type. A nested-object form cannot deliver the
checking below for the same reason — a free `eq(...)` call resolves its type
arguments before the enclosing call binds anything, so the helpers degrade to
`(a: string, b: string)` and every path typo compiles clean.

Four type-level pieces carry the checking:

1. **Literal capture.** Every path argument is a generic `A extends string`, so
   the argument's literal type reaches the constraint instead of widening to
   `string`.
2. **Per-resource validation.** `Valid<S, Sub, Obj>` resolves `S` against
   `Paths<Sub, 'subject'> | Paths<Obj, 'object'> | 'now'`. The accumulated
   key→object-type map decides which `Obj` a block validates against, so
   `object.authorId` is valid inside the `comment` block and an error inside the
   `media` block.
3. **A branded error string.** An invalid path resolves to the template literal
   type `` `unknown path '${S}' on this resource` ``, which is the _parameter_
   type, so the compiler names the offending path:
   `Argument of type '"object.authrId"' is not assignable to parameter of type "unknown path 'object.authrId' on this resource"`.
   An opaque assignability mismatch is why developers abandon a typed path.
4. **The path-vs-literal discriminator.** An operand whose string type matches
   `` `subject.${string}` | `object.${string}` | 'now' `` is validated as a path;
   anything else passes through as a literal. That shape is the only
   discriminator, and it is load-bearing: without it a mistyped `'subject.idd'`
   is indistinguishable from a deliberate string literal, and the condition
   silently compares a field against the text `"subject.idd"`.

Checked at compile time: the object kind key against the accumulated union of
`.for()` keys; the `object` argument of `can` / `canMany` / `canFields` /
`object` against that key's declared type; every path operand, per resource.
Not checked: action names, the comparand's value type against the field's type,
and `dependsOn` keys — validated at construction instead.

Three further constraints:

- `Paths<T, P>` is one level deep. A condition over a nested field is written
  against a flattened subject or object.
- `not-in` is not an identifier, so the helper is `notIn` and serializes to the
  `not-in` op. `in` is a valid property name and keeps its op's spelling.
- `and` and `or` nest freely. The builder flattens a condition tree to
  disjunctive normal form: each OR branch becomes one rule, and the conditions
  within a branch become that rule's AND-ed `when`. `always` is an empty AND,
  which flattens to one rule with an empty `when`.

The builder holds drafts and flattens on first query, not on each `.for()`: a
`dependsOn` may name a key a later `.for()` contributes, and validation runs
once over the whole matrix.

Four things the implementation settled beyond the sketch below:

- The document's shape lives in one function, `toMatrix`, which takes the
  permissions plus the document-level `version` and `schema` and returns the
  envelope. `toPermission` joins the key from the object kind and the action and
  nowhere else, which is what satisfies `KeyMismatchError` by construction.
- An empty `rules`, `denyRules` or `dependsOn` is omitted rather than emitted as
  `[]`, and so is an absent `version` or `schema` on the envelope: the document a
  foreign backend produces omits them, and the two `JSON.stringify` outputs must
  match.
- `version` and `schema` are arguments to `policy()` rather than chain methods.
  `.for()` exists to accumulate the key-to-type map, and both are per-document
  facts known before the first block is written. A schema is written by hand: the
  builder holds the object type at the type level only.
- `dependsOn` or `fields` before the first `allow` / `deny` of a block has no
  action to attach to and throws an `AclConfigError` rather than being dropped.

```ts
  FieldRules,
  Instant,
  Matrix,
  Permission,
} from './types.js';

/** The namespaced paths one level deep into `T`, prefixed with `P`. */
export type Paths<T, P extends string> = {
  [K in keyof T & string]: `${P}.${K}`;
}[keyof T & string];

/**
 * `S` when it names a path on this resource, and the error message otherwise.
 *
 * The failure branch is the parameter type, so the compiler's message names the
 * offending path instead of reporting an opaque assignability mismatch.
 */
export type Valid<S extends string, Sub, Obj> = S extends
  Paths<Sub, 'subject'> | Paths<Obj, 'object'> | 'now'
  ? S
  : `unknown path '${S}' on this resource`;

/**
 * An operand shaped like a namespaced path is validated as one; anything else
 * is a literal value and passes through untouched. The shape is the only
 * discriminator there is.
 */
export type Operand<B, Sub, Obj> = B extends
  `subject.${string}` | `object.${string}` | 'now'
  ? Valid<B & string, Sub, Obj>
  : B;

type Node =
  | { kind: 'condition'; condition: Condition }
  | { kind: 'and'; parts: readonly Node[] }
  | { kind: 'or'; parts: readonly Node[] };

/** An opaque condition tree. Built by the helpers, flattened by the builder. */
export interface Cond {
  readonly node: Node;
}

function cond(condition: Condition): Cond {
  return { node: { kind: 'condition', condition } };
}

function operand(value: unknown): Pick<Condition, 'path' | 'value'> {
  return typeof value === 'string' &&
    (value === 'now' ||
      value.startsWith('subject.') ||
      value.startsWith('object.'))
    ? { path: value }
    : { value };
}

/** Disjunctive normal form: one branch per rule, AND-ed conditions inside. */
function toBranches(node: Node): readonly (readonly Condition[])[] {
  if (node.kind === 'condition') return [[node.condition]];
  if (node.kind === 'or') return node.parts.flatMap(toBranches);
  return node.parts.reduce<readonly (readonly Condition[])[]>(
    (prefixes, part) =>
      toBranches(part).flatMap((branch) =>
        prefixes.map((prefix) => [...prefix, ...branch]),
      ),
    [[]],
  );
}

function toRules(
  conditions: readonly Cond[],
): { when: readonly Condition[] }[] {
  const node: Node = { kind: 'and', parts: conditions.map((c) => c.node) };
  return toBranches(node).map((when) => ({ when }));
}

/** The condition helpers, bound to one subject type and one object type. */
export interface Ops<Sub, Obj> {
  eq<A extends string, B>(
    field: Valid<A, Sub, Obj>,
    operand: Operand<B, Sub, Obj>,
  ): Cond;
  ne<A extends string, B>(
    field: Valid<A, Sub, Obj>,
    operand: Operand<B, Sub, Obj>,
  ): Cond;
  in<A extends string>(
    field: Valid<A, Sub, Obj>,
    values: readonly unknown[],
  ): Cond;
  notIn<A extends string>(
    field: Valid<A, Sub, Obj>,
    values: readonly unknown[],
  ): Cond;
  contains<A extends string>(field: Valid<A, Sub, Obj>, value: unknown): Cond;
  before(field: 'now', instant: Instant): Cond;
  after(field: 'now', instant: Instant): Cond;
  and(...conditions: Cond[]): Cond;
  or(...conditions: Cond[]): Cond;
  /** Always true. Serializes to a rule with an empty `when`. */
  readonly always: Cond;
}

/** The block parameter: the ops, plus the chained action declarations. */
export interface Actions<Sub, Obj> extends Ops<Sub, Obj> {
  allow(action: string, ...conditions: Cond[]): Actions<Sub, Obj>;
  deny(action: string, ...conditions: Cond[]): Actions<Sub, Obj>;
  /** Attaches to the action most recently declared in the chain. */
  dependsOn(...keys: string[]): Actions<Sub, Obj>;
  /** Attaches to the action most recently declared in the chain. */
  fields(rules: readonly string[] | FieldRules): Actions<Sub, Obj>;
}

/** The policy builder. `R` accumulates the key -> object-type map. */
export interface Policy<Sub, R> {
  for<K extends string, Obj>(
    key: K,
    build: (p: Actions<Sub, Obj>) => unknown,
  ): Policy<Sub, R & Record<K, Obj>>;
  can<K extends keyof R & string>(
    subject: Sub,
    key: K,
    action: string,
    object?: R[K],
    now?: Instant,
  ): Decision;
  canMany<K extends keyof R & string>(
    subject: Sub,
    key: K,
    action: string,
    objects: readonly R[K][],
    now?: Instant,
  ): Decision[];
  canFields<K extends keyof R & string>(
    subject: Sub,
    key: K,
    action: string,
    object: R[K],
    axis: 'read' | 'write',
    proposed?: Partial<R[K]>,
    now?: Instant,
  ): FieldDecision;
  capabilities(subject: Sub, now?: Instant): Record<string, Decision>;
  authorize(subject: Sub, options?: { now?: Instant }): Authorized;
  object<K extends keyof R & string>(key: K): BoundKind<Sub, R[K]>;
  readonly matrix: Matrix;
  readonly version: number | undefined;
}

export interface BoundKind<Sub, Obj> {
  can(subject: Sub, action: string, object?: Obj, now?: Instant): Decision;
  canMany(
    subject: Sub,
    action: string,
    objects: readonly Obj[],
    now?: Instant,
  ): Decision[];
  canFields(
    subject: Sub,
    action: string,
    object: Obj,
    axis: 'read' | 'write',
    proposed?: Partial<Obj>,
    now?: Instant,
  ): FieldDecision;
}

interface Draft {
  action: string;
  rules: { when: readonly Condition[] }[];
  denyRules: { when: readonly Condition[] }[];
  dependsOn: string[];
  fields?: FieldRules;
}

function blockBuilder(drafts: Draft[]): Actions<unknown, unknown> {
  let current: Draft | undefined;

  const draftFor = (action: string): Draft => {
    const existing = drafts.find((draft) => draft.action === action);
    if (existing) return existing;
    const draft: Draft = { action, rules: [], denyRules: [], dependsOn: [] };
    drafts.push(draft);
    return draft;
  };

  const ops = {
    eq: (field: string, value: unknown) =>
      cond({ field, op: 'eq', ...operand(value) } as Condition),
    ne: (field: string, value: unknown) =>
      cond({ field, op: 'ne', ...operand(value) } as Condition),
    in: (field: string, values: readonly unknown[]) =>
      cond({ field, op: 'in', value: values } as Condition),
    notIn: (field: string, values: readonly unknown[]) =>
      cond({ field, op: 'not-in', value: values } as Condition),
    contains: (field: string, value: unknown) =>
      cond({ field, op: 'contains', value } as Condition),
    before: (field: 'now', instant: Instant) =>
      cond({ field, op: 'before', value: instant } as Condition),
    after: (field: 'now', instant: Instant) =>
      cond({ field, op: 'after', value: instant } as Condition),
    and: (...conditions: Cond[]): Cond => ({
      node: { kind: 'and', parts: conditions.map((c) => c.node) },
    }),
    or: (...conditions: Cond[]): Cond => ({
      node: { kind: 'or', parts: conditions.map((c) => c.node) },
    }),
    always: { node: { kind: 'and', parts: [] } } as Cond,
  };

  const chain = {
    ...ops,
    allow(action: string, ...conditions: Cond[]) {
      current = draftFor(action);
      current.rules.push(...toRules(conditions));
      return chain;
    },
    deny(action: string, ...conditions: Cond[]) {
      current = draftFor(action);
      current.denyRules.push(...toRules(conditions));
      return chain;
    },
    dependsOn(...keys: string[]) {
      if (current) current.dependsOn.push(...keys);
      return chain;
    },
    fields(rules: readonly string[] | FieldRules) {
      if (current) {
        current.fields = Array.isArray(rules)
          ? { fields: rules as readonly string[] }
          : (rules as FieldRules);
      }
      return chain;
    },
  };

  return chain as unknown as Actions<unknown, unknown>;
}

function toPermissions(kinds: readonly [string, Draft[]][]): Permission[] {
  return kinds.flatMap(([key, drafts]) =>
    drafts.map((draft) => {
      const permission: Permission = {
        key: `${key}.${draft.action}`,
        object: key,
        action: draft.action,
      };
      if (draft.dependsOn.length) {
        Object.assign(permission, { dependsOn: draft.dependsOn });
      }
      if (draft.rules.length) Object.assign(permission, { rules: draft.rules });
      if (draft.denyRules.length) {
        Object.assign(permission, { denyRules: draft.denyRules });
      }
      if (draft.fields) Object.assign(permission, { fields: draft.fields });
      return permission;
    }),
  );
}

/**
 * The typed authoring path. Names the subject once, accumulates one object type
 * per `.for()` block, and flattens to the canonical matrix.
 *
 * Flattening is deferred to the first query so a `dependsOn` may name a key a
 * later `.for()` contributes and validation runs once over the whole matrix.
 */
export function policy<Sub>(
  options: { version?: number } = {},
): Policy<Sub, Record<never, never>> {
  const kinds: [string, Draft[]][] = [];
  let built: ReturnType<typeof createPolicy> | undefined;

  const access = () => {
    built ??= createPolicy(toPermissions(kinds), options);
    return built;
  };

  const self = {
    for(key: string, build: (p: Actions<unknown, unknown>) => unknown) {
      const drafts: Draft[] = [];
      kinds.push([key, drafts]);
      build(blockBuilder(drafts));
      built = undefined;
      return self;
    },
    can: (
      subject: Subject,
      key: string,
      action: string,
      object?: object,
      now?: Instant,
    ) =>
      access().can(
        subject,
        key,
        action,
        object as Record<string, unknown>,
        now,
      ),
    canMany: (
      subject: Subject,
      key: string,
      action: string,
      objects: readonly object[],
      now?: Instant,
    ) =>
      access().canMany(
        subject,
        key,
        action,
        objects as readonly Record<string, unknown>[],
        now,
      ),
    canFields: (
      subject: Subject,
      key: string,
      action: string,
      object: object,
      axis: 'read' | 'write',
      proposed?: object,
      now?: Instant,
    ) =>
      access().canFields(
        subject,
        key,
        action,
        object as Record<string, unknown>,
        axis,
        proposed as Record<string, unknown> | undefined,
        now,
      ),
    capabilities: (subject: Subject, now?: Instant) =>
      access().capabilities(subject, now),
    authorize: (subject: Subject, opts?: { now?: Instant }) =>
      access().authorize(subject, opts),
    object: (key: string) => access().object(key),
    get matrix() {
      return access().matrix;
    },
    get version() {
      return access().version;
    },
  };

  return self as unknown as Policy<Sub, Record<never, never>>;
}
```

### Task 11: Precedence, cascade and field-token tests

**Files:**

The five-step order is the whole engine, and a suite that only asserts
allow/deny outcomes passes whether or not the steps are in order. The same is
true of the cascade and of the field token resolution: each has one rule, and
an outcome assertion does not pin it.

**Acceptance bar:** every case below must fail when the rule it covers is
mutated in the implementation — remove the deny stage, swap steps 3 and 4, hand
`decide` an empty resolved map from `can`, detect object-dependence on the
`path` operand only, treat a false object-independent condition as undecidable,
let `'*'` into the field decision map, OR the conditions of a `when`. A case
that still passes under its own mutation asserts an outcome, not a rule.

```tsx
'use client';

/**
 * The React adapter: a provider and hooks over an already-built access matrix.
 *
 * Evaluation lives in `@evanion/acl`. Nothing here decides anything;
 * this layer supplies the context and reads decisions.
 */

import { createContext, useContext, useMemo } from 'react';
import type { ReactNode } from 'react';
import type { Access, Subject } from '@evanion/acl';
import type { Decision, EvaluationContext, FieldDecision } from '@evanion/acl';

export type { Access, Subject } from '@evanion/acl';
export type {
  Condition,
  Decision,
  EvaluationContext,
  FieldDecision,
  FieldReason,
  FieldState,
  Matrix,
  Permission,
  Reason,
} from '@evanion/acl';

interface PolicyContextValue {
  access: Access;
  subject: Subject;
  now: Instant;
}

const PolicyContext = createContext<PolicyContextValue | null>(null);

export interface PolicyProviderProps {
  access: Access;
  subject: Subject;
  /**
   * The evaluation context. Only `now` is read here; the subject is passed
   * separately. Pass a stable reference so memoisation on identity holds.
   */
  context?: Pick<EvaluationContext, 'now'>;
  children?: ReactNode;
}

export function PolicyProvider({
  access,
  subject,
  context,
  children,
}: PolicyProviderProps) {
  const value = useMemo<PolicyContextValue>(
    () => ({ access, subject, now: context?.now ?? new Date() }),
    [access, subject, context],
  );
  return (
    <PolicyContext.Provider value={value}>{children}</PolicyContext.Provider>
  );
}

function usePolicy(): PolicyContextValue {
  const value = useContext(PolicyContext);
  if (!value) {
    throw new Error(
      'useCan must be called inside a <PolicyProvider> (from @evanion/react-acl)',
    );
  }
  return value;
}

/**
 * One decision. `object` is the instance, optional for the create case; an
 * object-dependent rule with no instance yields an `unevaluable` decision.
 */
export function useCan(
  key: string,
  action: string,
  object?: Record<string, unknown>,
): Decision {
  const { access, subject, now } = usePolicy();
  return useMemo(
    () => access.can(subject, key, action, object, now),
    // object identity is part of the memo key; a changed instance must not
    // return a stale decision.
    [access, subject, key, action, object, now],
  );
}

/** A bulk decision array for a list, parallel to the input. */
export function useCanMany(
  key: string,
  action: string,
  objects: readonly Record<string, unknown>[],
): Decision[] {
  const { access, subject, now } = usePolicy();
  return useMemo(
    () => access.canMany(subject, key, action, objects, now),
    [access, subject, key, action, objects, now],
  );
}

/** The field-level decision for one action on one axis. */
export function useCanFields(
  key: string,
  action: string,
  object: Record<string, unknown>,
  axis: 'read' | 'write',
  proposed?: Record<string, unknown>,
): FieldDecision {
  const { access, subject, now } = usePolicy();
  return useMemo(
    () => access.canFields(subject, key, action, object, axis, proposed, now),
    [access, subject, key, action, object, axis, proposed, now],
  );
}

/** Every action-level decision for the current subject (no object). */
export function useCapabilities(): Record<string, Decision> {
  const { access, subject, now } = usePolicy();
  return useMemo(
    () => access.capabilities(subject, now),
    [access, subject, now],
  );
}
```

````markdown
# React Authorization

The React binding for `@evanion/acl`. A provider and hooks over an
already-built access matrix, for both an RSC-style graph and a traditional
Node server/client split. Evaluation lives in the core; nothing here decides
anything.

## Installation

```bash
npm install @evanion/react-acl
```
````

## Quick start

```tsx
import { PolicyProvider, useCan } from '@evanion/react-acl';
import { createPolicy } from '@evanion/acl';

const access = createPolicy([
  {
    key: 'comment.update',
    object: 'comment',
    action: 'update',
    rules: [
      { when: [{ field: 'object.authorId', op: 'eq', path: 'subject.id' }] },
    ],
  },
]);

export function App({ user }: { user: { id: string } }) {
  return (
    <PolicyProvider
      access={access}
      subject={user}
      context={{ now: new Date() }}
    >
      <Comment comment={{ authorId: user.id }} />
    </PolicyProvider>
  );
}

function Comment({ comment }: { comment: { authorId: string } }) {
  const decision = useCan('comment', 'update', comment);
  if (!decision.allowed) return <ReadOnlyComment reason={decision.reason} />;
  return <EditableComment />;
}
```

## Hooks

- `useCan(key, action, object?)` — one decision.
- `useCanMany(key, action, objects)` — a decision array parallel to the input.
- `useCanFields(key, action, object, axis, proposed?)` — the field-level decision.
- `useCapabilities()` — every action-level decision for the subject.
